# 新后台与新版面计划

## 目标

本计划整合 Odaily 新后台审核工作台与公开首页新版面两项后续工作：后台让值班人员能看清稿件阅读、文本审查和事实审查状态，同时保留 Odaily 原生发布操作；首页在现有内容分区中新增 Meme 速递。

本计划供 Odaily 技术团队评估，不假设 Odaily 后台源码、网站源码、接口或数据结构由 OdAIly 仓库控制。

## 系统边界

- **Odaily 官方后台**：未来审核工作台的目标系统，包含稿件展示、Alt 阅读、未读底色、文本审查接受/拒绝、事实审查链接跳转，以及 Odaily 原生推送、上下线等功能。
- **Odaily 公开首页**：Meme 速递模块属于公开网站版面调整，与后台审核工作台分开评估和实施。
- **OdAIly AI 快讯后台**：OdAIly 控制台中的“快讯及数据总览 / 快讯总览”，是只读展示后台。它展示与官方后台快讯逐条对应的字段，并补充产出来源、审阅优先级、文本审查状态、事实审查状态、查重和阅读状态；状态只展示，不提供文本反馈、事实审查或阅读留痕操作，也不提供 Alt 放大、未读底色或官方推送/上下线控件。

本计划描述的是未来 Odaily 后台与公开首页的需求，不代表这些改造已在 Odaily 系统上线。OdAIly 仓库维护的快讯总览仍是只读展示后台，不承接下文的审核交互或公开首页展示。

OdAIly 快讯总览从主 SQLite 的当前稿件镜像和审查记录展示文本审查、事实审查及已有查重结果。插件会在正文成功展开或 Alt 阅读层成功显示后，按编辑与正文版本在本地 SQLite 记录阅读；OdAIly 控制台暂不读取这份状态。官方后台读取 OdAIly 的只读导出接口已纳入本地实现，官方后台回传和双方阅读事件同步仍待后续建设。

## 快讯数据与双后台同步

### 出口品类与工作台分组

OdAIly 使用独立的出口品类字段，值为以下七类：`人工`、`AI常规`、`商务`、`行情`、`Meme速递`、`热点自动快讯`、`定时简报`。它们是快讯的业务归类，不等同于 `origin_key` 等来源/工作流字段。主 SQLite 的 `newsflash_production_metadata.outlet_category` 保存该值；现有推送产线已分别写入分类，商务快讯也通过独立出口值入库。

当前 HTML 演示把 AI常规和商务合并列表、合并统计；这只是演示分组，不约束官方后台最终如何组织页面。向官方后台发送数据时仍分别写入 `AI常规` 或 `商务`，不得把展示分组当作出口品类。

品类归属按产出工作流确定：

| 出口品类 | 包含内容 |
|---|---|
| 人工 | 人工直接新增或发布的快讯 |
| AI常规 | X、媒体、竞品等常规稿；MSX 公告自动抓取；“昨夜精彩事件” |
| 商务 | 已发布的商务快讯 |
| 行情 | Hyperliquid、Gate 行情播报、股票行情及 OKX 美股周快讯 |
| Meme速递 | Meme 市值里程碑与社区热议等两类 Meme 成稿 |
| 热点自动快讯 | X Agent 下“自动追踪热点”产出的正式快讯 |
| 定时简报 | 早晚由 Gate 和 MSX 产出的自动快讯，仅包含这两条产线 |

金十本轮不纳入页面、接口或分类范围。股票行情和 OKX 美股周快讯属于“行情”，不能因定时发布而归入“定时简报”；Gate 行情播报也与 Gate 早晚定时简报分开。

### 唯一标识与字段来源

Odaily 官方快讯 ID 是两边关联记录的唯一标识。同步前必须取得该 ID；不以标题或发布时间相似度生成第二套外部身份。官方后台是快讯标题、正文、官方操作人和浏览量的权威来源；OdAIly 推送审查补充数据，不覆盖官方快讯本身。

OdAIly 向官方后台提供：

- 出口品类：使用上表中的一个独立值。
- 审阅优先级：只传等级，不传推荐理由。
- 文本审查者：传插件中可见的完整反馈内容。
- 事实审查者：只传插件使用的审查短文本和 OdAIly 快讯详情 URL，供官方后台跳转查看。
- 查重：预留可为空的短文本或 URL 字段。当前查重结果覆盖不完整，不能作为统一结论外发；字段定义和真实数据接入待后续确认。

Odaily 官方后台应提供按快讯 ID 读取官方操作人和浏览量的接口，必要时也提供官方标题、正文及变更版本，供 OdAIly 更新镜像。由官方侧提供读取接口可保持这两类数据的来源权威；具体鉴权、增量读取方式和字段格式由双方接口评审确定。

本地只读出口为 `GET /integration/newsflashes?limit=100&offset=0`，通过 `Authorization: Bearer ...` 和服务端 `NEWSFLASH_EXPORT_API_TOKEN` 鉴权。响应按页返回已确认的官方快讯 ID、出口品类、优先级等级、完整文本审查反馈、事实审查插件短文本与 OdAIly 链接，以及当前版本的插件阅读人和时间；不传标题或正文，官方后台继续使用自己的稿件字段。查重暂以 `not_implemented` 占位。接口只向外提供数据，不接受官方后台写入；官方操作人和浏览量回传也未实现。

### 审核留痕事件

“是否审核过”按三类独立事件记录，事件都绑定快讯 ID 和当时的标题/正文版本，并记录操作者、时间、发生渠道及可重试的事件唯一号：

| 审核项 | 计为完成的动作 |
|---|---|
| 正文阅读留痕 | 插件按 Alt 放大层成功显示正文，或点击标题成功展开正文。仅按住 Alt 未显示、只看列表标题、打开普通编辑页或进入 OdAIly 管理台不算；插件会本地记录编辑、时间、正文版本和阅读方式，不改变 AI 给出的优先级等级。官方后台的阅读标记仍待实现。 |
| 文本审查者 | 在插件或官方后台对该条反馈点击“接受”或“拒绝”。只打开反馈内容不算。 |
| 事实审查者 | 点击事实审查链接并跳转到 OdAIly 对应快讯详情。仅点击跳转即可记为已查看。 |

插件文本接受/拒绝已有本地反馈记录，正文阅读也已落入插件本地 SQLite；当前出口接口可读取已按官方 ID 关联的阅读人和阅读时间。将这些事件同步到官方后台、接收官方后台的事件回传、事件唯一号和失败重试仍未实现。标题或正文更新后按新版本判定已读，旧版本记录不替代新版本阅读。

在首页侧栏的 **24小时快讯** 与 **精选活动** 之间新增 **Meme速递**，顺序为：

1. 24小时快讯
2. Meme速递
3. 精选活动

Meme速递沿用 24 小时快讯的模块外观和条目模板：相同的标题栏层级、列表间距、标题字体和链接表现。每条内容在标题前单独显示一行标签和时间，标签与时间同一行、同字号，标签加粗；两行依次为“今日热议Meme + 时间”和“Meme速递 + 时间”。其下显示最多两行标题。首页模块仅展示已形成的 Meme 速递成稿，不在此处新增摘要字段或独立卡片视觉。条目点击进入对应快讯，模块标题的更多入口指向 Meme 速递列表；如 Odaily 尚无对应列表页，目标路由在实施前确认。

当前 MHTML 示意稿展示 2 条占位条目，时间为版式示例，标题不代表真实快讯；条目链接也是页内占位。实际接入时由 Odaily 提供对应成稿数据和列表路由。

该模块是公开首页展示，不改变后台稿件审核、推送或下线规则；具体展示条数、排序和刷新行为沿用首页现有快讯模块配置，实施时需与 Odaily 技术团队确认可复用的数据接口和路由。

## 新后台：审核工作台结构

当前 HTML 演示按内容工作方式分为六个展示分区，用于呈现列表、筛选、翻页与共享待办交互；该示意不规定官方后台最终的信息架构。本计划对接范围是 OdAIly 输出的独立品类和审核数据。

| 顺序 | 分区 | 默认条数 | 内容范围 |
|---|---|---:|---|
| 1 | 人工 | 5 | 人工直接新增或发布的快讯 |
| 2 | AI常规/商务（演示合并分区） | 6 | 演示中合并列表和统计；出口品类仍分别传输 |
| 3 | 行情 | 2 | Hyperliquid、Gate 行情播报、股票行情及 OKX 美股周快讯 |
| 4 | Meme速递 | 2 | 市值里程碑、社区热议等 Meme 成稿 |
| 5 | 热点自动快讯 | 2 | X Agent 热点自动追踪生成的正式快讯 |
| 6 | 定时简报 | 2 | 早晚 Gate 与 MSX 自动快讯 |
|  | **首屏默认合计** | **19** | 不足条数时不从其他分区补位 |

子板块归属：

- AI常规和商务只在当前 HTML 演示中合并列表与统计；出口品类仍分开，商务快讯不并入 AI常规。官方后台可自行决定页面如何组织。
- 股票行情及 OKX 美股周快讯属于“行情”，不因正文冠名 MSX 或 Gate、或按周定时发布而移入其他分区。Gate 行情播报与 Gate 早晚定时简报分开。
- Hyperliquid 只显示一份成稿；同一事件命中多个监测方向时把方向显示为标签，不重复占行。
- 报道 AI 行业的稿件属于 AI常规，可附“AI 行业”标签；“AI常规”指常规自动生成来源。
- MSX 公告自动抓取和“昨夜精彩事件”归 AI常规。热点自动追踪产生的正式快讯归“热点自动快讯”，不在 AI常规重复出现；其他热点材料产生的普通稿件仍按其工作线归类。
- 定时简报仅包括早晚 Gate 与 MSX 自动快讯；金十本轮不纳入页面和接口范围。
- Crypto 信源标题提醒、原始巨鲸活动、X Agent 市场情绪和项目推介属于线索/内部材料，不混入这六个成稿列表；沿用现有对应页面或插件入口。
- 人工修改自动生成稿不改变内容线归属，只记录更新者和版本。

### 紧凑行

不在列表行内直接展开正文。现有后台字段和对应数据必须保留，不能从系统或原生操作逻辑中移除。状态值不在工作台表格中单独展示，也不在标题旁显示“已发布/未发布”标识；后台仍依据状态控制原生操作和审查流程：

| 顺序 | 现有字段 |
|---:|---|
| 1 | ID |
| 2 | 状态（保留数据和原生逻辑，不在工作台表格展示） |
| 3 | 标题 |
| 4 | 分组 |
| 5 | 信息流 |
| 6 | 是否重要 |
| 7 | 死链接 |
| 8 | 操作人 |
| 9 | 更新者 |
| 10 | 浏览量(app/h5/web) |
| 11 | 发布时间 |
| 12 | 推送时间 |
| 13 | 操作 |

在这些字段之上增加审核字段：阅读状态、审阅优先级、文本审查状态、事实审查状态、查重。审阅优先级、两类自动审查状态和查重各占一列；列顺序为审阅优先级、文本审查、事实审查、查重，查重紧邻分组之前；阅读状态并入标题单元格。标题单元格只显示标题和未审核/已审核标记，不显示发布状态。现有 ID 和标题固定在左侧，操作继续固定在右侧；其余可见字段通过表格横向滚动查看。状态数据虽不作为表格字段展示，仍用于原生按钮和流程状态判断。

### 查重

查重列只呈现需要快速识别的结果：无重复时显示“—”；存在重复或疑似重复时显示红色叉号“✕”，悬停可查看重复稿件 ID、标题和相似原因。该列不替代文本审查，也不自动判定稿件应下线或拒绝；值班人员结合来源、发布时间和内容判断是否为重复发布。

标题单行截断；完整正文由专用 Alt 阅读浮层查看，或使用 Odaily 原生“编辑”进入编辑页查看。表格行不展开正文。

### 审阅优先级

这是值班排序的核心新字段，由 AI 给出建议，与现有“是否重要”不同。它回答“编辑应该先审阅哪条 AI 稿件”，而“是否重要”回答“这条新闻本身是否重要”。人工稿不参与 AI 审阅优先级排序；行情稿虽为 AI 撰写，但经过专门筛选，优先让值班人员阅读正文，因此行情区统一显示“—”；定时简报也统一显示“—”。其他需要编辑评估的 AI 稿按等级显示，并能查看一句推荐理由。

优先级只依据快讯标题和正文明确表达的事件重要性，不依据事实/文本审查疑点、阅读状态、写作质量或发布决定赋值。它是编辑阅读顺序建议，不代表准确性、风险结论或发布资格。

| 推荐等级 | 用途 |
|---|---|
| 高 | 直接影响读者交易判断，或具有广泛传播价值的重大进展，例如重要产品上线、加密政策/法案取得实质进展、重要人物的重要讲话或重大安全/基础设施事件 |
| 中 | 有明确行业价值，但实际影响范围、主体重要性或近期决策影响有限 |
| 低 | 常规、局部或影响有限的动态，缺少显著的近期决策影响或广泛传播价值 |

行情监控、Meme 速递、定时简报和人工稿不参加优先级评估，显示“—”。未评估、评估失败、历史未记录与低优先级必须分别表达，不能把低当作兜底状态。

常规稿可在同一次 AI 调用中额外输出优先级和一句理由；发布者必须分别按发布规则与事件重要性标准作答，优先级不得改变直发/挂后台决定。发布者按规则跳过模型时，可在推送完成后单独评估，失败不得改变发布结果。热点自动快讯在现有写稿调用中额外输出优先级，不增加模型调用。

行内展示“等级 + 一句理由”，例如“高 · 重要政策进展”。字段名统一为“审阅优先级”。未来的 Odaily 官方后台可按等级筛选并排序；当前 OdAIly 快讯总览只展示等级和理由，不增加筛选、审核或发布操作。同步到官方后台时只传等级，不传理由。

行情分区中的 Hyperliquid、Gate 和股票行情稿均不显示审阅优先级，但作为 AI 稿件保留未审核底色，提示值班人员查看正文。定时简报审阅优先级显示“—”，行级阅读状态保留，但不计入顶部待审核稿件催办数。

演示分区标题栏展示聚合数量，例如“AI常规/商务 · 全部 148 · 未审核 12”；AI常规和商务的总数与未审核数在该演示分区合并统计，出口接口仍按独立品类输出。分区标题栏提供筛选、当前页/总页、前后页及每页 5/10/20/50 条选择。标题栏保持单行、低高度；分区名与全局数量使用小字号和紧凑行高，减少页面占用，尤其避免“人工 · 全部 28 · 未审核 2”这类低优先级统计压过稿件列表。翻页和扩行只影响当前分区；扩行直接增加页面总高度，不在分区内部再套滚动框。新内容提示数量，不自动插到当前阅读位置。

行情分区可按 Hyperliquid、Gate 异动、股票异动筛选。定时简报使用紧凑行显示计划执行和发布结果；异常才展开说明。定时稿件保留“未审核”标识，但默认不计入顶部待审核稿件提醒。

## 全局待处理栏

页面顶部只有一条共用提示栏，所有人看到相同数量：

> 文本问题待反馈 3　|　事实疑点待查看 2　|　待审核稿件 8

数量覆盖所有分区和分页，不按登录者个人拆分。点击数量可筛选对应条目。定时简报除外：它们仍显示行级阅读状态，但默认不进入“待审核稿件”催办数。

### 待审核稿件

当前版本没有以下任意一项有效阅读动作时，行内显示“未审核”：

- 插件按 Alt 成功显示正文，或点击标题成功展开正文；Odaily 官方后台的阅读留痕留待后续实现。

仅查看列表标题、鼠标经过普通行、打开 OdAIly 管理台均不算阅读。动作成功后更新为“已审核”，记录操作者、时间和阅读方式。一个人完成有效阅读后，所有人看到同一结果。

行内未审核以文字加橙色标记显示，并给整行轻浅底色；已审核显示克制的完成标识。问题待反馈和事实疑点只在各自审查字段中使用强调色，不把已审核稿件染成红底。负责人、处理人和谁值班是不同信息，不以排班自动推断实际阅读人。

审核标识绑定标题和正文版本。标题或正文变更后，当前稿件重新显示“未审核”，旧版本的阅读记录保留。文本审查或事实审查新发现问题时仍按各自规则进入待办，不能被此前的阅读记录消除。

## Alt 阅读交互

官方后台整行不监听 Alt 悬停，以免编辑点击文本审查状态或原生操作时误切换稿件。官方后台标题单元格是唯一阅读触发区；插件已有 Alt 阅读层和点击标题展开正文两种本地阅读标记，官方后台还需实现 Alt 阅读与对应留痕。其他列、特别是文本审查接受/拒绝入口和原生操作区，不触发阅读切换。

- 按住 Alt 后，鼠标进入某行标题单元格时打开该稿件浮层。
- 离开触发区或经过该行其他区域时，当前浮层保持，不跟随普通鼠标移动。
- 按住 Alt 移到另一行的阅读触发区才切换稿件。
- 松开 Alt 关闭浮层。
- 浮层避让推送、编辑、下线等原生操作区域，不拦截点击。
- 官方后台正文成功展示后记录阅读；浮层打开失败或正文未加载不记录。插件侧已对 Alt 渲染成功与标题展开正文写入本地阅读状态。

浮层展示完整标题与正文、来源/子类型、发布时间和发布状态。正文是主要内容。文本审查发现问题时附原文片段、最小建议和原因；事实审查发现疑点时附当前结论及进入原文/证据对照的入口。没有问题时只显示简短状态。Hyperliquid 审阅优先级显示“—”；浮层突出完整成稿、事件变化摘要和时效，监测证据按需展开。

## 文本审查

文本审查状态和人工是否看过分开显示。表格内只显示紧凑状态，例如未检查、检查中、未发现问题、问题待反馈、已接受、已拒绝、执行失败；不在单元格内放“接受/拒绝”按钮。

- 鼠标悬停或点击文本问题状态时，打开独立悬浮窗，展示原文片段、建议修改、原因和“接受/拒绝”按钮。按钮只存在于悬浮窗，不占用表格列宽。
- 顶部“文本问题待反馈”只在值班人员通过插件或真正 Odaily 后台点击“接受/拒绝”后减少。插件已有反馈动作，官方后台需要新增。
- 接受表示编辑认可审查提示，不代表正文已修正。接受后如正文仍与提示时版本相同，行内持续明显显示“已接受 · 正文未变”；正文发生变化后显示“已修改 · 待复查”，不直接宣称错误已解决。
- 拒绝后显示“已拒绝”、操作者和时间，保留提示及反馈记录供复盘。
- 后续可以由审查系统或人工复查确认问题已解决；这个确认不能由打开编辑页、提交无关修改或复制文案代替。
- 状态反馈对所有人共享。若实际后台无法确认正文修改是否生效，展示“已接受，修正状态待核实”，不推断已解决。

## 事实审查

事实审查与文本审查是两列、两套状态，不合成一个“AI 审核通过”。行内状态至少区分：发布后检查、未审查、待查、审查中、豁免、未发现实质问题、发现疑点未查看、发现疑点已查看、无法确认、执行失败。

- 有疑点时行内显示数量和一句摘要；详细入口展示稿件原文、来源材料、逐项疑点及外部证据。
- 顶部“事实疑点待查看”在值班人员点击事实审查链接、跳转到 OdAIly 对应快讯详情后消除；只点击跳转即可记为已查看，不要求在官方后台复制整份审查材料。官方后台需要提供该链接，插件已有跳转入口。
- 在 OdAIly 管理台直接查看、插件展开/Alt 阅读以及仅进入普通编辑页不清除事实疑点待查看数量；必须通过事实审查链接产生跳转事件。
- 查看只表示值班人员已看到，不表示认同、核实完成或问题已修正。行内保留“发现疑点 · 已查看”。新版本或新疑点重新进入提醒。
- 豁免说明豁免原因；“无法确认”和“执行失败”不显示为通过。
- 现有事实审查者以已发布快讯为入口。尚未进入检查流程的稿件显示“待检查”，不可误呈现为已检查或通过，也不通过表格标签暴露发布状态。

## Odaily 原生操作

此需求为附加 UI 和审核留痕，不改变原生操作按钮、行为、可用条件或顺序：

- 未发布稿保留原生“推送”“编辑”等操作。
- 已发布稿保留原生“推送”“编辑”“下线”等操作。
- 不新增或替换“发布/不发/稍后决定”按钮，不改变推送参数和发布状态。
- 选稿行为只在已有原生发布操作之外另行记录；Hyperliquid 等后台稿是否发仍由值班人员按原流程处理。

## 共用留痕与管理识别

阅读状态、文本反馈和事实跳转状态在 OdAIly 与 Odaily 官方后台间同步，页面不另做领导汇总页或个人成绩面板。管理者从同一列表即可识别：

- 大面积“未审核”标识代表稿件尚未通过 Alt 展开放大正文的方式阅读。
- “文本问题 · 待反馈”代表有人尚未回应文本审查提示。
- “已接受 · 正文未变”代表认同的问题仍未见稿件修改。
- “事实疑点 · 未查看”代表已发布稿件的实质疑点尚未在 Odaily 后台呈现给值班人员。
- “事实疑点 · 已查看”只证明疑点看过，不作为解决结论。

状态详情显示操作者、时间和方式。应支持按未审核、文本待反馈、事实待查看过滤，并可按内容分区/来源、发布状态和时间筛选。任何单个状态都不能单独作为编辑质量或绩效结论；需要结合内容版本和问题处理记录抽查。
