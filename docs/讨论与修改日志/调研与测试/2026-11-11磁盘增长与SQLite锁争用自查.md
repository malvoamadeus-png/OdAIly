## 已证实的设计问题

1. 证据采用每份内容独立 gzip 文件。大约数百万小文件造成文件系统块与 inode 的显著放大。`SystemInformationStore.storage_health()` 每次用 `glob` 和 `stat` 扫全量证据文件，并以 `st_size` 求和；它低估实际占盘，不统计 inode，也会随文件数放大请求 I/O。`prune_orphan_evidence(limit=500)` 先汇集所有引用、注册项并遍历全部文件，再限制候选数，限制不能限制扫描成本。相关代码：`backend/packages/system_observability/store.py`。
2. 每日采样和孤儿清理由 `SystemReviewWorker` 执行，API 只有启用 `SYSTEM_REVIEW_ENABLED` 才启动它。检查时该开关不在 API 进程启动环境或 `.env` 中，代码默认关闭；观测库巡检运行表为空。生产状态显示每日维护链没有运行，不能仅凭此推断其他每分钟清理也停止。
3. WAL 同一数据库仍只有一个写者。21:17–21:25 的日志持续出现多个 worker 的 `database is locked`；21:21:51 内核锁快照显示文本审查者 PID 887 持有主库 WAL 写锁，投资线索 PID 908 持有 HotTopic WAL 写锁。快照只证明当时持锁，不证明它们是先前事故的唯一持锁者或其持锁持续时间。多个进程出现等待磁盘页，`vmstat` 两个间隔的 I/O wait 为 87% 和 77%，但当时包含本次只读调查负载。
4. 文本审查者领取任务原先在 `BEGIN IMMEDIATE` 后扫描、排序、计算内容 hash 并逐条查重；Writer3 在写事务内执行时间函数筛选、关联和排序；`trim_source_text` 在写事务内扫描任务和核查审核状态。均有在慢查询或 I/O 等待期间阻塞其他写者的结构性风险，不能据此推断三者都导致了此次事故。
5. 主库公共连接的 `timeout_seconds` 传给 `sqlite3.connect()` 后，又被固定的 `PRAGMA busy_timeout=30000` 覆盖；调用方传入其他超时并不能按预期生效。改动需要审计所有调用方的实际等待契约后测试。
6. 历史日志有锁错误、多服务失败及重启后短暂 502；未掌握阿里云 CPU、内存、I/O 和实例事件，不能将整机失联认定为 SQLite 锁的直接结果。21:21 可用内存约 4.5 GiB，swap 几乎用满；不能单凭 swap 占用断言发生 OOM。

## 已确认的业务边界与待实施方案

用户确认：普通、已结束业务的历史运行证据保留一周；已发布稿件、审核结论、来源身份、待处理及故障证据不属于这条删除范围。此确认不是对所有七天前文件直接删除的授权：证据可由多条记录、人工巡检和 pin 引用，需要先定义可判定的成功终态、具体证据类型、实际完成时间、共享引用和保护条件，不能用文件 mtime 判断业务完成时间。当前留存行为尚未修改，也没有删除生产证据。

建议实施顺序：

1. **实时止损与观测**：单独监控 `/`、`/data` 的可用字节与 inode、实际分配块、磁盘延迟与队列、数据库锁等待、长写事务、WAL 增长、worker 重启及后台积压；告警区分固定阈值与增长率。避免健康页全量扫描和在请求路径进行昂贵维护；检查阿里云实例监控和系统事件。
2. **七天策略落地**：对普通已结束记录建立有界、可恢复、幂等的候选清单；确认所有业务引用、审核、失败和 pin 后，先 dry run 并输出按业务/类型/数量/实际字节/inode 的预估，再进行小批次执行。先验证源引用、并发引用/清理和崩溃恢复；不要扩大到未确认的业务类别。独立维护调度，不应依赖 AI 巡检开关。
3. **减少数据放大**：评估小证据聚合归档或其他能按条寻址、校验和安全回收的存储，并设计旧引用兼容、迁移恢复与回滚；不能简单将文件合并后直接删除原件。必要时抑制无意义重复投影和索引膨胀，先按来源测量。
4. **控制锁范围**：优先验证和部署文本审查者修复；再按同样方式改造 Writer3、清理任务及其他热点，保证事务内复核、幂等领取、外部副作用不重复；在独立库上做多 worker 压测。考虑写入队列或按业务拆库时，先明确跨库事务、外部投递与失败恢复契约。
5. **空间回收**：对既有 SQLite 做表与索引归因、保留策略验证和完整备份恢复演练；充分评估空闲空间、写阻塞与外部副作用，再择机决定是否重建或 VACUUM。不要在生产繁忙期间为回收空页直接运行 VACUUM，也不要直接删除 WAL/SHM。

SQLite 与文件系统机制的一手资料见同目录 `SQLite并发与空间管理一手资料.md`。
