# Hyperliquid 地址命名：取数与调度规则

日期：2026-11-17。范围：Luna 离线命名试验与生产调度规则。离线子程序只接受显式 JSON；生产功能由独立命名worker实现，不能将离线子程序当作生产入口。

## 触发与优先级

本轮需求已从离线试验推进到生产实现，最终规则以 `../../OdAIly代码与整体设计/Hyperliquid地址自动称谓.md` 为准。

1. 全部已发现、未拉黑且未人工锁定的地址都进入命名范围，存量逐批处理，未来新地址自动处理；不以进入新闻或盈利地址池为前提。
2. 成功检查后每七天再次检查，覆盖全部符合条件的地址；普通增减仓不必改名，仍成立的名字优先延续。
3. 新事实直接推翻当前状态称谓，例如空头已清仓或反手转多，监测保存新快照时立即停用旧称谓，进入重新命名队列，不等待七天到期。重新命名期间写稿不沿用旧方向。
4. 人工保存备注后永久由人工维护，包括清空备注；现存人工备注保留。并发模型返回不能覆盖人工编辑。
5. 命名失败有界退避，不阻塞监测和新闻；名字不能成为新增新闻触发。

用户已明确选择“稳定特长优先，允许状态名；反手后立即停用并重新命名”。状态名只是当前证据下的亮点，不证明地址没有其他特长。

## 取数顺序与上限

先复用事件证据和本地持久化的合约历史汇总，不默认重新请求官方接口：

1. 读取目标事件、前后持仓、净操作、明确的平仓结果及时间。保留完整合约标识，如 `xyz:BRENTOIL`，读者称谓按用户确认简写为“原油”，例如“原油大多头0x0c”；底层仍区分布伦特、WTI等具体合约，不合并统计。
2. 汇总观察窗口内全部资产的盈利、轮数、胜率、实际首末成交日期、缺口和异常；优先看7天/30天，未覆盖完整窗口时展示实际日期，不填补未观察时段。零完整轮表示胜率未知。
3. 增补方向分层、持仓时长等已有可核查统计；当前没有的统计标为未取得，不要求AI猜测，不为取得名称临时全量扫历史。
4. 账户PnL单独保存来源、样本时间、是否含浮盈亏。它不能替代单资产交易盈亏。遵守现有“事件前1小时内”总盈亏展示规则；过期样本仅能作为带日期的历史背景，不能当成当前总盈亏。
5. 旧名、证据版本、编辑确认记录与上次命名时间一同输入，优先延续仍成立的称谓。

每地址最多提供最近8条非重复事件、全部资产的紧凑统计及当前可核查持仓。当前试验最大样本有31个合约，均保留，没有提前按SOL等预期名称筛选数据。若后续输入过大，按资产相关性分段汇总并保留遗漏数量及合计，不静默截断或只留下盈利资产。

命名支线默认不增加网络请求。如确有必要补查，只进入现有共享限流采集预算，低于正式监测优先级；每地址本轮最多补一个缺失摘要，完整历史回填独立排队，不阻塞写稿。不能另起一套无约束官方API轮询。

## Luna 调用与名字维护

- 模型固定为 `gpt-6-luna`。每个地址独立请求，失败仅在同模型重试一次，不静默换模型。
- 规则先判断是否需要调用：有效旧名且没有显著变化时直接复用。输入版本指纹一致时不重复调用；指纹由资产指标、状态、事件、覆盖标记、旧名及Prompt版本生成，不包含纯查询时间。
- 显著变化包括：新完成交易轮改变胜率称谓资格、主要盈利/交易资产改变、净盈利方向改变、原称谓依赖的仓位已清空/反转、新的大额兑现使新的特长明显更突出。普通价格变化或查询时间推进不自动触发改名。
- 生产使用独立worker逐批处理全部待检查地址，不设会遗漏存量地址的每日100地址门槛；每批规模、失败退避和运行命令见生产模块文档。命名不拖延新闻。
- AI只负责特征名及证据选择。程序按真实地址生成并固定显示前缀，默认 `0x` 加前两位十六进制字符，同名同前缀冲突时延长并保存。
- 生产接入建议保存称谓、备选、依据ID、选择原因、适用范围和失效条件。本轮离线脚本的模型输出只含称谓、备选、依据ID和理由；适用范围写在理由中，失效条件尚未结构化，标题例子由程序从原始事件组装。主名优先突出特长或中性亮点；其他资产亏损不要求进入名字。仅有突出负面特点时才考虑负面称谓。
- 标题和正文首次提及均使用“称谓＋前缀”，后文可写“其”。不得凭账户盈利推出目标资产高胜率，或把已清仓空单写成当前大空头。无全市场比较依据时不能写“最大”。

格式和引用ID校验通过，表示结果可进入人工试阅；不代表程序已经完成自然语言事实核查。首次上线前仍需核查称谓及标题逐词对应的证据。生产队列、证据版本、失效与人工保护机制由独立模块实现，验收与运行契约见生产模块文档；离线试跑结果本身不能代替上线验收。

## 本轮真实样本

通过 `odaily-official`、Linux用户 `root`、`/opt/OdAIly` 只读查询生产独立Hyperliquid库及关联任务，代码 `21b5475`，监测服务active。查询以只读URI和 `query_only` 运行，不复制整库，不修改数据。输入只保留真实地址前缀，所有事实标注历史观察时点，不代表查询时当前仓位。

选取 `0xf5`（跨资产、多种高胜率候选）、`0xb8`（大额ZEC空单兑现及跨资产清仓）、`0x0c`（布伦特原油大多单）三个类型；不预填主名，让Luna实际决定突出什么。输入中发现旧账户PnL超出1小时展示范围，已显式标为仅历史背景，不能直接写成当前总盈亏。
