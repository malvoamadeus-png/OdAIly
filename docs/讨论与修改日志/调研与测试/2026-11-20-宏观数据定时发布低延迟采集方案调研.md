# 宏观数据定时发布低延迟采集方案调研

> 更新日期：2026-11-20。范围是官方公共源与公开商业 API 文档中能核实的低延迟方法；不把网页显示速度当作供应商 SLA，也不推定第三方数据可公开再分发。

## 结论

低延迟宏观数据采集是成熟的商业能力，但公开资料呈现出两层：统计机构发布日历、API 和发布页是权威数据源；商业数据供应商另提供经济日历 API，有供应商提供长连接推送。我们查阅的 BLS 与 DOL 公共资料描述了日历、请求/响应 API 或网页/下载数据，没有发现面向公众的 webhook、发布推送订阅或“官方发布时间后 X 秒送达”承诺。Trading Economics 的公开文档则明确提供经济日历 WebSocket streaming；其日历快照包含 `Date`、`Actual`、`Previous`、`LastUpdate` 等字段，示例 `LastUpdate` 精确到毫秒，但这不是端到端延迟 SLA。

因此，网站在 21:30:00 左右展示实际值，可能来自商业日历/新闻数据 feed、对官方发布源的高频轮询，或两者并用；仅凭网页时间无法判断是哪种路径，也不能证明其公开 API 对所有用户同样快。

## 一手来源能提供什么

| 来源 | 可核实能力 | 公开文档的边界 |
| --- | --- | --- |
| BLS API 与发布页 | BLS API v2 允许客户端提交序列查询；CPI 与 Employment Situation 有正式发布页和发布时间表。 | API 文档描述请求/响应，没有发现 push/webhook 或具体发布后送达 SLA。HTML 发布页适合作为权威核对入口，但自动抓取须验证生产出口可达性、缓存与页面结构。 |
| DOL ETA Weekly Claims | DOL 提供 Weekly Claims 页面和历史数据入口；周初请的实际发布机构是 DOL ETA。 | 查阅入口为网页/数据页，没有发现通用 JSON 实时接口或公开延迟 SLA。数据序列镜像不能假定与新闻稿同时可见。 |
| Trading Economics | 经济日历 REST API 可按国家读取事件快照，字段含 `Actual`、`Previous`、`Date` 和 `LastUpdate`；另有 Economic Calendar Streaming 文档，说明可通过持久 WebSocket 接收 live calendar releases。 | 需要私钥/商业接入；公开页面未给出相对于官方首发时刻的数值延迟 SLA。`LastUpdate` 是供应商更新时间字段，不等于 OdAIly 收到数据的时间。需另核对价格、指标覆盖、事件口径和公开再分发许可。 |
| Finnhub | 官方 Economic Calendar API 文档描述 `actual`、`estimate`、`prev`、事件时间等字段。 | 文档标示相应日历接口需要 Premium；公开 schema 未构成发布后送达 SLA。需核对许可、更新时间和初请/CPI口径。 |

官方资料：BLS [API 文档](https://www.bls.gov/developers/)、[API v2 说明](https://www.bls.gov/developers/api_signature_v2.htm)、[新闻发布日历](https://www.bls.gov/schedule/news_release/)、[CPI 发布页](https://www.bls.gov/news.release/cpi.nr0.htm)、[Employment Situation 发布页](https://www.bls.gov/news.release/empsit.nr0.htm)；DOL [ETA 新闻稿](https://www.dol.gov/newsroom/releases/eta)、[Weekly Claims Data](https://oui.doleta.gov/unemploy/claims.asp)。

供应商资料：Trading Economics [美国经济日历 API](https://docs.tradingeconomics.com/economic_calendar/country/)、[日历 WebSocket Streaming](https://docs.tradingeconomics.com/economic_calendar/streaming/)、[API 定价与接入](https://tradingeconomics.com/analytics/api.aspx)；Finnhub [Economic Calendar API](https://finnhub.io/docs/api/economic-calendar)。

## 对 OdAIly 的落地建议

1. 为每项指标明确“权威首发源”和备用源。初请以 DOL ETA 当周新闻稿/Weekly Claims 数据为主，FRED `ICSA` 作为回退；CPI、非农优先走可从生产出口稳定访问的 BLS 官方入口，镜像只作回退。
2. 发布日之前载入排程、指标映射和稿件模板。发布窗口仅轮询到期指标；优先复用连接，遵从源端缓存语义，并记录 HTTP 状态、`Date`、`Last-Modified`、ETag、源内更新时间、首个含新统计期的原始响应和本机接收时间。响应头时间不能单独当作数据首次可见时间。
3. 首次收到匹配统计期且字段校验通过的值后立刻进入投递，不等待二次轮询或全指标任务；对照来源在后台核验，发现口径冲突才阻断或标记人工核查。
4. 把目标定义为“来源首次可读后 10 秒内完成发布”，同时单独报告“官方排定时间至来源首次可读”的延迟。前一项由 OdAIly 控制；后一项依赖机构公开时点和渠道，不能靠调低轮询间隔保证。
5. 若采用供应商 feed，先在实际生产网络和授权账号下测量至少数次 CPI、就业和初请发布：比较官方发布时间、供应商 `LastUpdate`、OdAIly 首次接收、投递开始与完成时间，并确认 SLA、覆盖率、修订处理、口径和公开分发权限。只有测到稳定收益后再把付费 feed 用作主触发源。

当前工作区的既有代码证据与公开源调研另见 [美国宏观指标自动快讯数据源调研](美国宏观指标自动快讯数据源调研.md)；运行时实际可达性和服务环境状态必须以生产环境测量为准。
