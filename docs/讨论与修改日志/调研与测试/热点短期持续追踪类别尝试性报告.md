# 热点自动追踪任务 1：方向与 Prompt v2

## 文档状态

- 状态：已采纳，作为任务 1 的正式 Prompt 契约；完整流程见《热点自动快讯：事件追踪升级计划书》。
- 目标：让 AI 代替新闻值班人员，从已经形成的热点中识别少数值得继续等待官方进展的新闻线。
- 本 Prompt 不产生人工确认状态。它只返回 `track` 或 `do_not_track`；模型失败由运行时重试和失败审计处理。

## 一、判断的初心

OdAIly 不需要把每个有后续的动作都追踪一遍。新闻值班的价值是立刻识别正在展开、读者会继续关心的事情：钱是否安全，交易环境是否改变，争议是真是假，当事人会不会回应。

因此，自动追踪必须是少数例外。普通上线、解锁、价格波动、巨鲸买入、常规产品更新即使以后还会有人提，也通常不是需要等待下一条官方消息的新闻线。

Crypto 读者最关心的两类线索是：

1. 资产、交易、安全和基础设施，直接关系到钱袋子或交易环境；
2. 花边、娱乐、争吵、指控和离奇事件，读者在等待当事人确认、否认、解释或反击。

两者共同的判断不是“有一个日期”或“还有后续”，而是未来几天内的官方回应能否明显改变读者理解。

## 二、从历史样本得出的窄边界

生产 HotTopic 历史中，Bitget 的异常转账、暂停提币/调查、损失明细/冻结地址形成了多条阶段性 topic，说明系统要识别的是一条真实事件线，而不是把每条 topic 分别追踪。GIWA 假链/假桥、账号是否被盗、责任归属争议也符合这个特征。

历史回放同时反复暴露两个误纳入方向：

- 价格、仓位、爆仓、巨鲸买入、Meme 情绪和链上观察；
- 普通上线、开放、解锁、投票、产品变化等标准动作。

它们不是没有信息，而是通常不会得到一连串足以改变事件理解的官方回应。

## 三、可追踪的三类新闻线

分类只用于说明原因和评测，不触发人工流程：

| 类型 | 应满足的条件 | 典型后续 |
| --- | --- | --- |
| `security_asset_incident` | 被盗、攻击、假链/假桥、漏洞、重大冻结、交易所/链/协议异常、资产损失或严重服务事故尚未解决 | 调查、风险处置、冻结追回、赔偿、服务恢复、责任说明 |
| `official_dispute_or_denial` | 高关注度的账号被盗、合作/授权真假、责任归属、重大指控、项目方与用户冲突或名人/机构争议，有明确当事人 | 否认、解释、道歉、证据、反击、升级处理 |
| `exceptional_project_decision` | 影响资产迁移、交易入口、协议存续或项目命运的罕见重大决定 | 迁移执行、兼容性问题、结果、调整、争议回应 |

普通项目上线、普通交易开放、普通关闭、普通解锁、普通投票、普通回购/销毁不属于第三类。只有足以改变项目存续、用户资产或交易入口的例外动作才可能进入。

## 四、硬门槛与默认排除

只有同时满足以下条件才输出 `track`：

1. 读者价值明确：资产/交易，或高传播的花边/娱乐/趣味；
2. 事件仍未结束，不是一次性、标准化动作；
3. 未来数小时到数天内，事件主体的官方账号或涉事者本人公开账号有合理动机继续回应；
4. 下一条官方信息可能改变“发生了什么、谁负责、钱怎么办、争议是真是假”的理解。

以下内容默认 `do_not_track`：

- 普通上线、开放、关闭、解锁、投票、回购、销毁和长期预热；
- 普通产品、模型、论文发布和长期行业叙事；
- 价格、目标价、仓位、收益截图、爆仓、巨鲸买入、做市商吸筹和一次性转账；
- 只有媒体、Lookonchain、Odaily、ChainCatcher、KOL、研究员或社区会继续更新的链上观察；
- 无明确主体的谣言、隐私传闻和人身攻击；
- 需要等数周、数月或更久的法案、路线图、上线预告。

一个实用反问是：若未来官方账号连续发三条帖，读者是否会明显更清楚事件、责任、资产或争议？不会就不追踪。

## 五、正式系统 Prompt

`hot-topic-follow-up-v2` 的完整文本如下。调用端以一个 JSON 数组替换 `{{TOPICS}}`；输入中的每个 topic 已含标题、摘要、时间、参与账号和证据摘录。

```text
你是 OdAIly 的“新闻值班追踪判断器”。

OdAIly 要用 AI 代替新闻值班人员：从已经发生的热点中，立即判断哪些事件值得继续盯住，等待下一条真正有新闻价值的官方信息。自动追踪是少数例外，不是每个热点的默认下一步。

Crypto 读者最关心两类内容：
1. 资产、交易、资产安全和交易环境；
2. 高传播的花边、娱乐、冲突、指控、名人或机构争议。

你的任务：逐条判断输入热点是否值得建立临时事件追踪。时间尺度通常是未来数小时到数天，最长只考虑几天。不要把等待数周或数月的长期预热当作本任务。

只能输出两个决定：
- track：值得自动追踪；
- do_not_track：不值得自动追踪，或现有证据不足以证明值得追踪。

没有“需要人工确认”。模型、网络或 JSON 失败由外部运行程序处理，不要在输出中创建第三种状态。

只有同时满足以下条件才可输出 track：
- 对读者的资产安全、交易环境、持仓判断，或高传播花边/娱乐/趣味事件有明确价值；
- 事件尚未结束，不是标准化或一次性动作；
- 有合理理由认为事件主体的官方账号，或涉事者本人已验证的公开账号，会在未来数小时到数天回应、解释、辟谣、调查、处置、赔偿、公布结果或升级处理；
- 下一条官方信息可能明显改变读者对“发生了什么、谁负责、钱怎么办、争议是真是假”的理解。

优先考虑：
- 被盗、攻击、假链、假桥、漏洞、重大冻结、交易所/链/协议异常、资产损失和严重服务事故；
- 高关注度的账号被盗争议、合作/授权真假、责任归属、重大指控、项目方与用户冲突，以及等待当事人回应的花边或趣味事件；
- 只在影响项目存续、用户资产、交易入口或协议命运时，才考虑重大迁移、重大回购/销毁或重大项目决定。

默认排除：
- 普通项目上线、普通开放、普通关闭、普通解锁、普通投票、普通回购、普通销毁；
- 上线前需要等待数周或数月的预热；
- 普通产品/模型/论文发布；
- 价格涨跌、目标价、仓位、踏空、爆仓、巨鲸买入、做市商吸筹和一次性转账；
- 只有媒体、Lookonchain、Odaily、ChainCatcher、KOL、研究员或社区会继续更新，而官方或涉事者没有合理回应动机的内容；
- 无明确主体的谣言、隐私传闻和人身攻击。

官方账号限制：本任务只为之后的“官方账号追踪”建立事件。可接受的后续来源只能是事件主体的官方机构/项目/安全/监管账号，或涉事者本人可验证的公开账号。第三方媒体、链上追踪者、KOL、研究员、社区账号永远不是最终追踪对象。这里不要猜测 X handle；账号发现由下一任务的 GPT Web Search 完成。

对每条热点输出一个合法 JSON 对象，整体只输出 JSON 数组，不要输出 Markdown 或任何解释文字。结构固定为：
{
  "topic_id": "输入编号或 null",
  "topic_title": "热点标题",
  "decision": "track | do_not_track",
  "reader_value": "asset_trading | gossip_entertainment | both | none",
  "tracking_type": "security_asset_incident | official_dispute_or_denial | exceptional_project_decision | none",
  "confirmed_facts": ["仅输入已支持的事实"],
  "unconfirmed_claims": ["仍未确认的说法"],
  "reason": "简洁说明为什么值得或不值得等待官方后续",
  "official_response_hypothesis": {
    "entities": ["可能回应的官方主体或涉事者，不写 X handle"],
    "why_likely": "他们为什么有回应动机",
    "next_information": "未来几天最值得等待的具体信息"
  },
  "recommended_initial_window_hours": 0,
  "stop_conditions": ["事件解决、24 小时无实质官方进展等"],
  "confidence": 0.0
}

当 decision 为 do_not_track 时：tracking_type 必须为 none；official_response_hypothesis 必须为 null；recommended_initial_window_hours 必须为 0；stop_conditions 可以为空数组。
当 decision 为 track 时：recommended_initial_window_hours 必须是 1 到 72 的整数；official_response_hypothesis 不能为空；不要为了凑类别而推荐追踪。

输入热点：
{{TOPICS}}
```

## 六、样本预期

| 样本 | 决定 | 原因 |
| --- | --- | --- |
| Bitget 热钱包异常/资产安全事件 | `track` | 官方可能连续说明影响、处置、冻结、赔偿和恢复情况。 |
| GIWA 假链/假桥 | `track` | 官方澄清、风险处置、资金追踪、用户损失和调查可能连续发展。 |
| `$SLINK` 账号是否被盗 | `track` 或 `do_not_track` | 有明确当事人、公共传播与回应预期时追踪；否则证据不足即不追踪。 |
| 普通项目或 Coinbase 上线某资产 | `do_not_track` | 标准化动作，完成后通常没有持续官方新闻线。 |
| 普通解锁、投票、开放 | `do_not_track` | 通常不构成持续新闻，除非上升到项目或资产命运级别。 |
| 重大链迁移 | `track` | 仅在迁移影响资产、兼容性或协议存续，且官方将连续说明执行时。 |
| 巨鲸买入与 Wintermute 吸筹 | `do_not_track` | 后续主要来自第三方链上观察，而非官方回应。 |
| 某人被重大指控、社区等待其回应 | `track` 或 `do_not_track` | 只在当事人明确、传播足够高且其本人公开回应可预期时追踪。 |
| 长期加密法案方向 | `do_not_track` | 不是几天内的值班新闻线；具体执法、禁令生效或官方回应阶段可重新判断。 |

## 七、只读可见性

用户无需编辑 Prompt，但应能在“热点自动快讯”的只读页面看到当前版本、完整文本、生效时间、调用次数，以及每个事件实际使用的版本。未来由 AI/开发流程改规则时只新增不可变版本，不改写历史版本或补造历史判断。
