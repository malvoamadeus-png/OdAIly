# 币安广场账号监控调研

## 结论摘要

截至 2026-08-16，币安广场（Binance Square）存在公开可索引的账号页和帖子页，但没有在币安官方开发者文档中发现面向 Square 内容的公开 REST API、RSS、WebSocket 流或通知订阅接口。因此，当前不能把“每 1-3 分钟监控指定账号新发言”视为有官方稳定接口支持的生产能力。

最接近的结论是：

- **公开入口：有。** 官方 Square 站点地图列出 `/en/square/profile/{slug}` 和 `/en/square/post/{post_id}` URL。
- **官方内容 API：未确认。** 官方开发者文档目录和完整文档中没有 Square 内容产品或 `/square` API 路径。
- **RSS / WebSocket / 通知订阅：未确认。** 官方文档中没有 Square 内容流、RSS 或 webhook/通知订阅契约。
- **1-3 分钟发现新帖：不可靠。** 站点地图只有 URL 和按日 `lastmod`，不能提供账号级近实时游标；官方公开页面在本次实测中被 WAF challenge 挡住，无法把页面字段当作稳定抓取契约。
- **可行性：** 生产上建议先按“无官方接口”处理；站点地图只适合低频发现/回填。无登录浏览器已经可以作为受控原型读取公开内容，但依赖未文档化、易变的网页内部接口，不应直接作为现有收集者-X 的等价替代。

## 研究范围与方法

- 只使用币安官方域名的开发者文档、帮助中心/条款入口、公开网页响应、`robots.txt` 和站点地图。
- 研究日期：2026-08-16。
- 未读取 Supabase、生产服务器或现有生产配置；未修改任何代码。
- “未发现”表示在本次抓取的官方文档索引/全文和官方公开 URL 中未发现，不等同于证明币安内部不存在未公开接口。

## 官方确认

### 1. 公开账号页和帖子页确实存在

币安官方 `robots.txt` 声明了 Square 站点地图：

- `https://www.binance.com/sitemap_output/domain=www.binance.com/sitemap_Square_index.xml`

该站点地图索引在本次读取时包含英文、简体中文等语言版本。英文分片：

- `https://www.binance.com/sitemap_output/domain=www.binance.com/sitemap_Square_en_1.xml`

本次读取该英文分片得到 1,525 个 URL，其中 663 个是 `/en/square/post/{post_id}`，862 个是 `/en/square/profile/{slug}`。例如：

- 帖子：`https://www.binance.com/en/square/post/356340080390338`
- 账号：`https://www.binance.com/en/square/profile/PhoenixToken0`

这确认了“存在公开 URL 和可被索引的账号/帖子资源”，但站点地图没有说明接口、鉴权、字段结构或轮询保证。

来源：

- [Binance robots.txt](https://www.binance.com/robots.txt)
- [Square sitemap index](https://www.binance.com/sitemap_output/domain=www.binance.com/sitemap_Square_index.xml)
- [Square English sitemap](https://www.binance.com/sitemap_output/domain=www.binance.com/sitemap_Square_en_1.xml)

### 2. 官方 API 文档没有 Square 内容 API

币安开发者文档提供官方机器可读目录和全文：

- [Binance Developer Docs index](https://developers.binance.com/en/docs/llms.txt)
- [Binance Developer Docs full text](https://developers.binance.com/en/docs/llms-full.txt)

在 2026-08-16 抓取的完整文档快照中：

- 没有名为 Square 的产品文档；
- 没有发现 `/square` API 路径；
- 文档中的小写 `square` 命中是交易参数示例等无关内容，不是 Square 社区内容接口。

因此，不能依据官方 API 文档构造一个类似 X 账号时间线的 Square API 客户端。

### 3. 官方 WebSocket 文档只覆盖交易/行情等流

官方 Spot WebSocket Streams 文档定义的地址为 `wss://stream.binance.com:9443` 或 `wss://stream.binance.com:443`，并说明 raw/combined stream、订阅格式、连接时长和连接限额。文档示例和 stream 名称围绕交易行情；没有 Square 帖子、作者或内容事件。

来源：[Spot WebSocket Streams](https://developers.binance.com/en/docs/products/spot/web-socket-streams)

这意味着“没有 Square WebSocket”是基于官方文档未提供该产品流的结论，而不是对币安所有内部 WebSocket 地址的扫描结论。

### 4. 官方 REST 文档的鉴权和限流不适用于未确认的 Square 页面

官方 Spot REST 文档说明：

- REST API 的公开 `NONE` 安全类型指公开市场数据；`TRADE`、`USER_DATA`、`USER_STREAM` 是交易或账户数据权限；
- API 支持 HMAC、RSA、Ed25519 密钥；
- 超过限额返回 429，持续不退避可能被 418 自动封禁；IP 封禁时长会从 2 分钟扩大到 3 天；
- API 限额按 IP 计算，而非按 API key 计算。

这些是 Binance Exchange API 的官方规则，不能推导出 Square 网页内部接口的鉴权方式或限额。官方文档也没有给出 Square 内容 endpoint、请求权重、API key 权限或响应 schema。

来源：[Spot REST API - General REST API Information](https://developers.binance.com/en/docs/products/spot/rest-api)

### 5. 机器人政策的可确认范围有限

官方 `robots.txt` 对搜索爬虫组明确列出：

- `/bapi/`、`/api/` 等路径不允许抓取；
- `/square/notification`、`/square/bookmark`、`/square/settings`、`/square/creator-center/` 不允许抓取；
- 同一份文件发布了 `Square_index.xml` 站点地图。

`robots.txt` 是爬虫访问规则，不是给业务方的 API 授权，也不是对所有自动化客户端的合同许可。它可以证明官方公开发布了 Square URL 索引和部分路径规则，但不能据此认定“每 3 分钟抓取网页一定被允许”。

来源：[Binance robots.txt](https://www.binance.com/robots.txt)

币安 API 文档的产品条款入口指向 [Binance Product Terms of Use](https://www.binance.com/en/terms)。本次直接访问条款页和帮助中心页时触发了 CloudFront/WAF challenge，未能读取条款正文，因此本报告不对网页自动化是否获得合同许可作肯定判断；上线前应由负责人按当前条款和币安许可确认。

## 实测观察

### 3. 无登录有头浏览器可以读取 CZ 主页和最新内容

2026-08-16 使用独立临时用户目录启动 Chrome 151，通过浏览器调试协议打开：

- `https://www.binance.com/zh-CN/square/profile/cz`
- 未登录币安账号。
- 不读取现有浏览器配置、Cookie 或登录态。

页面成功加载，标题为 `CZ的个人资料 | 币安广场`，页面显示 CZ 最新帖子为“1小时”。最新帖子信息：

- `id = 356343746142033`
- `username = CZ`
- `firstReleaseTime = 1786889184000`，即 `2026-08-16 22:06:24 +08:00`
- `webLink = https://www.binance.com/en/square/post/356343746142033`
- 正文包含英文和中文两部分，主题是测试 Trust Wallet 后处理地址内 meme coin。

### 4. 页面内存在可读的内容请求

在同一个无登录浏览器页面上下文中，页面调用了：

```text
GET /bapi/composite/v2/friendly/pgc/content/queryUserProfilePageContentsWithFilter
    ?targetSquareUid=dxCeCLOM7uOFJKX8EnS3Kw
    &timeOffset=-1
    &filterType=ALL
```

本次请求返回 HTTP 200，响应字段包括：

- `id`、`username`、`displayName`
- `bodyTextOnly` 和结构化 `body`
- `firstReleaseTime`、`latestReleaseTime`
- `webLink`
- `imageList`、`videoLink`
- `contentType`

一次响应返回 20 条内容。当前结果中普通帖子为 `contentType = 1`，音频直播回放为 `contentType = 4`；如果业务只监控发文，应先过滤普通帖子。最新列表可以用帖子 `id` 做去重，重复请求最新窗口不依赖站点地图。

这证明“无登录浏览器采集”具备原型可行性，但该 `bapi` 路径是网页内部接口，不是币安开发者文档中的公开 API，不能据此假定长期稳定、无限制或获得官方支持。`timeOffset` 看起来具有分页含义，但本次尚未把它当作稳定增量游标；第一版应以重复拉取最新窗口 + 帖子 ID 去重为主。

### 5. Headless 与 headed 的差异

本次 Linux 环境没有可用 Chromium；Playwright Python 包已安装，但 Playwright CDN 下载浏览器超时。随后使用 Windows Chrome 做验证：

- `--headless=new --dump-dom` 探针未在超时窗口内输出页面 DOM。
- 有头 Chrome 独立临时配置可以加载页面并读取上述结构化内容。

这不能证明币安永久禁止 headless，但当前证据更支持未来 Linux 先使用“有头 Chromium + `xvfb-run` + 持久化浏览器进程”做原型，再单独评估纯 headless 的稳定性。

### 1. 公开 URL 在本次环境中被 WAF challenge 拦截

对以下官方页面发起未带登录态的 GET：

- `https://www.binance.com/en/square`
- `https://www.binance.com/en/square/profile/PhoenixToken0`
- `https://www.binance.com/en/square/post/356340080390338`

三者均返回 HTTP 202，响应头含 `x-amzn-waf-action: challenge`，响应体长度为 0。本次观察只能说明“当前网络环境下，直接 HTTP 抓取不能拿到页面正文”，不能证明所有地区、浏览器或登录状态都必须登录，也不能证明页面一定没有公开内容。

### 2. 站点地图不是账号时间线

Square 英文站点地图只提供 URL 和 `lastmod` 日期。本次样本中的 `lastmod` 为 `2026-08-16` 这样的日期粒度，没有发布时间、作者、正文、媒体 URL 或分页游标。URL 列表同时包含帖子和账号，且没有官方字段说明如何由账号页得到该账号的全部帖子。

所以即便每 1-3 分钟轮询站点地图，也无法可靠回答：

- 某个指定账号刚刚是否发帖；
- 帖子的原始发布时间是什么；
- 作者显示名和稳定账号 ID 是什么；
- 正文和媒体内容是什么；
- 是否因为 sitemap 更新滞后而漏帖。

### 3. 直接网页访问没有形成可复用的字段证据

因为页面 GET 被 WAF challenge 拦截，本次没有把网页 HTML、脚本中的内部请求或登录后响应作为事实依据。尤其没有把可能存在的 `bapi` 请求路径写入实现建议；未文档化的网页内部请求不能当成官方 API。

## 与收集者-X 的字段对照

仓库的收集者-X 契约需要按账号轮询，发现新内容后保留原始作者、账号、正文、来源链接和原始发布时间，再做去重和后续流水线交接。按目前官方证据，币安广场的对应能力如下：

| 能力 | 收集者-X 需要 | Square 官方证据 | 结论 |
| --- | --- | --- | --- |
| 指定账号入口 | 账号用户名/主页 | `/square/profile/{slug}` | 有公开入口 |
| 指定账号新帖列表 | 稳定账号时间线或 API | 只有站点地图 URL，未见账号时间线契约 | 未确认 |
| 稳定唯一 ID | `source_item_id` | 帖子 URL 中有 `post_id` | 帖子 URL 可作为候选 ID，但未有 API 契约 |
| 原始发布时间 | 用于新鲜度与去重 | sitemap 只有日粒度 `lastmod` | 不足 |
| 作者 ID/显示名 | 入库元数据 | 页面字段本次未取到，官方 sitemap 不提供 | 未确认 |
| 正文 | `tasks.content` | sitemap 不提供；无官方 Square schema | 未确认 |
| 来源链接 | 原始 URL | 帖子 URL 已确认 | 有 |
| 媒体 | 图片/视频等 | sitemap 不提供；无官方 schema | 未确认 |
| 近实时发现 | 轮询或推送 | 无 Square API/RSS/WS/通知契约 | 不可靠 |
| 鉴权和限流 | 可配置、可退避 | 只有 Exchange API 的通用规则；Square 未定义 | 未确认 |

## 可行方案分级

### A 级：官方支持方案，当前不可直接落地

向币安申请或确认 Square 内容数据的官方合作接口、开发者权限或通知/订阅能力。只有拿到明确的 endpoint、鉴权、限流、分页、时间字段和内容 schema 后，才适合接入现有“按账号抓取”的流水线。

验收条件应至少包括：按账号查询、按发布时间或游标增量拉取、稳定帖子 ID、作者 ID/显示名、正文、原始链接、媒体字段、删除/编辑语义，以及明确的自动化使用许可。

### B 级：站点地图低频发现，适合回填，不适合实时监控

可以把官方 Square sitemap 当作公开 URL 目录，用于发现公开账号和帖子、做历史回填或人工核查。它不适合作为 1-3 分钟账号监控源，因为没有账号级时间线、时间戳和内容字段，且 sitemap 更新周期和覆盖策略没有实时 SLA。

### C 级：浏览器/网页内部请求原型，风险高

如果业务必须先验证可行性，可以在隔离环境做单账号、低频、短周期原型，优先使用不登录的公开页面，观察作者、时间、正文、媒体和稳定分页，并记录 WAF、会话失效、内容排序变化和漏帖情况。该方案必须先确认条款和币安许可；不能依赖绕过 WAF、批量注册、共享登录态或未授权接口。

即便原型成功，也应把它标为实验性收集器：网页改版、登录风控、内部接口变更、地区差异和账号权限都可能使监控中断或漏帖。不能把“每 3 分钟请求一次”本身当成合规或可靠性的保证。

### D 级：不建议

直接猜测或逆向调用 `bapi`/`api` 内部接口，或者用搜索引擎缓存/第三方镜像补齐正文和作者字段。这样既没有官方 schema 和限流承诺，也不能满足本仓库对原始来源链路和可审计性的要求。

## 最终建议

可以进入单账号、低频、隔离原型，但暂不把币安广场加入现有收集者-X 的同级生产源。建议原型保持不登录，使用独立浏览器上下文常驻运行，每 1-3 分钟重复请求 CZ 的最新 20 条内容，以 `id` 去重，只接收 `contentType = 1`，并记录页面加载失败、接口状态、WAF challenge、响应字段变化和浏览器重启次数。

原型验证通过后，再决定是否申请官方权限或另行设计容错采集器。生产版本仍需接受网页改版、内部接口变更、WAF 风控和地域网络差异带来的漏帖风险。
