# 项目推介任务书

## 目标

从 X Agent 已有账号中系统整理链上小市值、degen 和新项目的“项目 + 逻辑/理由/看法”，形成内部项目观察表，不发布快讯。

## 账号初始筛选

系统直接检查已有账号近期代表性内容，批量提出并写入项目推介订阅开关。优先纳入持续发现、研究或推介链上新项目的账号；链上大多数低流动性标的默认属于本模块。管理员通过网页开关纠错，系统不保存账号画像，也不覆盖人工修改。

### 任务 1：找出项目推介账号

1. 从 X Agent 已有账号中读取最近约 30 天内容，不从 X 快讯信源或其他信源扩充账号。
2. 识别持续谈论链上新项目、degen、低流动性代币、项目机制、空投、早期生态或新叙事的账号。
3. 重点寻找有自己逻辑和判断的账号，区分项目研究/推介与单纯转发、新闻搬运、抽奖和无上下文喊单。
4. 一个账号可以同时打开市场情绪和项目推介；两个模块分别依据帖子内容消费。
5. 样本不足或内容无法确认时不自动打开项目推介，只保留热点话题开关。
6. 输出初始化表：账号、建议开关、代表性帖子、推介信号和不确定性；初始化写入后由管理员网页纠错。

### 任务 2：提取“项目 + 逻辑/理由/看法”

1. 识别项目名称、代币 ticker、合约地址、官方链接和链信息。
2. 提取账号为什么提到或推介该项目：产品、技术、叙事、催化剂、团队、生态、估值、交易计划或其他明确理由。
3. 允许保存研究分析、明确推荐、持仓披露和项目介绍；没有项目主体或没有可理解逻辑的内容不进入主表。
4. 主结果只包含项目、逻辑/理由/看法、最近提及时间、账号和原帖链接；不保存推介强度、账号画像或额外解释字段。
5. 有合约地址或官方链接时按稳定身份归并；身份不稳定的同名项目暂不合并。
6. 同一账号重复表达相同逻辑只更新最近时间；出现新逻辑时追加一条来源观点。

### 任务 3：呈现和管理追踪账号

1. 复用 X Agent 账号一览表，展示项目推介开关、最近采集、最近分析和错误。
2. 提供“已打开项目推介/未打开”筛选与批量开关。
3. 项目一览按最近提及时间排序，支持 24 小时、7 天、30 天筛选。
4. 项目详情展示项目标准身份、不同账号的逻辑、最近时间和原帖链接；来源分页加载。
5. 不增加独立的账号类型管理页，避免账号画像与订阅开关重复。

### 任务 4：共享采集与性能

1. 项目推介使用 X Agent 共享采集结果，不单独轮询账号。
2. 账号开关点击只更新配置，不触发即时全量分析；新开关从下一批内容或受控补算任务开始生效。
3. 使用稳定来源 ID、项目身份键和逻辑摘要键去重，避免重复模型调用和重复项目行。
4. 模型任务进入有界队列；单个项目或账号失败不能阻塞其他账号。
5. 内容分析、项目归并和页面查询分开，页面只读取已提交结果，不等待模型。

### 额外任务与验收

- 建立链上项目身份归一化规则，记录链、合约地址和官方链接的来源优先级。
- 历史回放覆盖新项目、degen、主流资产普通讨论、转发、同名项目、缺少合约地址和只有口号没有逻辑的内容。
- 验收项目误合并、同一项目重复行、逻辑丢失、转发误纳入和模型失败误生成结果。
- 本模块任何结果不得写入普通快讯发布队列。

## 内容处理

识别项目名、代币符号、合约地址或官方链接，并提取账号表达的逻辑、理由和看法。明确推荐、研究分析、持仓披露和项目介绍均可形成候选；纯转发、无观点提及和无法确认主体的内容不进入主表，但可作为失败或待确认记录。

同一项目优先使用合约地址或官方链接归并；没有稳定身份时不强行合并同名项目。主表只展示项目、逻辑、最近提及时间、账号和原帖链接；不增加推介强度、画像或额外人工判定字段。

## 失败与验收

项目主体不清、逻辑无法提取或模型失败进入可见失败记录。重复运行必须幂等，同一账号相同逻辑的重复提及只更新时间。验收覆盖新项目推介、链上 degen、主流资产普通讨论、转发、同名项目和合约地址缺失等样本。
