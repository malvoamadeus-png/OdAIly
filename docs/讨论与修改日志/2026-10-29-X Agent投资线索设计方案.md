# X Agent「投资线索」设计方案

日期：2026-10-29。状态：已在本地工作区实施，尚未部署生产。本文件记录设计目标；运行契约以《控制台-X Agent-投资线索》及代码为准。

## 1. 产品目标与边界

从 X Agent 收集的材料中输出两个核心内容：**驱动逻辑、标的**。

基本思路是「发生了什么变化 → 可能改变什么 → 哪些资产可能受影响」。允许直接提取、沿一至两层关系推导，以及组合不同帖子形成方向判断。标的暂时找不到，也可以保留有具体驱动的线索。

不核查原帖真假、报告可靠性、逻辑是否成立、收入是否持续、代币能否捕获价值、股价是否已经反映。原帖说法和系统推导分开保存；保留原文中的测试、拟议、预计、条件和时间，避免改写时改变含义。

输出位于 X Agent 内部，供人继续思考、调研。不接入快讯发布、自动交易或新增通知渠道。

## 2. 第四个开关：投资线索

账号目录增加「投资线索」，字段建议为 `investment_leads_enabled`，模块名为 `investment_leads`。

| 场景 | 方案 |
| --- | --- |
| 上线时已有账号 | 一次性全部开启，包括目前三个开关都关闭的账号；这些账号将重新进入共享轮询 |
| 网页新增、批量导入、脚本新增账号 | 默认开启投资线索，不经过账号画像或历史帖子筛选 |
| 用户手动关闭 | 停止该账号后续材料进入本模块，保留已生成结果 |
| 重启、再次导入、重复迁移 | 保留人工选择，不重新强制打开 |
| 关闭其余三个开关 | 投资线索仍可独立运行 |
| 四个开关全部关闭 | 停止该账号共享采集 |
| 重新开启 | 处理之后新增的材料，不自动回放关闭期间的历史 |

「所有账号」指 X Agent 账号目录中的所有账号。账号引用、转发的目录外作者内容也可成为材料，但不会因此自动订阅目录外作者。

一次性启用需要持久化迁移版本。建表默认值、新增接口、种子导入、筛选报告导入、状态变更、调度查询和批量开关均须覆盖第四项；仅增加数据库默认值不足以实现要求。

关闭开关时取消未开始任务，运行中任务在落库前重新检查资格。同一材料若还由另一个已开启账号收集，仍可继续处理，不能只按第一次收集者决定资格。

## 3. 总体流程

```text
现有共享抓取：每个账号仍只抓一次
    ↓
保存原帖／引用／转发正文及来源关系
    ↓
第一阶段：批量语义扫描，提取变化与可组合材料
    ↓
查找少量相关历史材料，去除同源重复
    ↓
第二阶段：形成驱动逻辑，定位标的
    ↓
按事件和驱动归并，展示于 X Agent／投资线索
```

成本通过去重、批处理、候选分析和有界上下文控制。所有已开启账号的已采集材料都有扫描机会，不用账号类型、金融关键词、ticker 或 Crypto 词表决定是否能进入第一阶段。

### 3.1 复用抓取，补齐材料边界

现有情绪和推介模块只读取账号自己的正文，纯转发在采集转换时被过滤。投资线索需要自己的材料适配层：从同一次 FXTwitter 响应中提取正文，不继承上述限制。

- 原创：正文及可用链接、附件信息。
- 引用：账号自己的评论和被引用正文分别保存，标明各自作者。
- 纯转发：读取响应中可用的被转发正文，记录原作者和转发账号。
- 回复：读取回复正文；响应中有父帖时保存父帖，没有则标记上下文缺失。
- 多人转发同一原帖：正文只分析一次，保留每次收集的账号关系。转发次数不等于独立事件数。

第一版以抓取响应中已有的文字为基础。模型判断核心变化仅在图片或外链中时，创建有界补充读取任务；成功后重新入队，失败或预算不足显示「材料不完整」，不计为「无投资线索」。不为每条帖子默认抓全文、做 OCR 或搜索。

「全账号」不等于获得这些账号的全部历史内容。沿用上游返回数量和轮询配额约束，展示轮询延迟、截断、抓取失败和材料缺失情况。

### 3.2 第一阶段：找变化，也保留可组合的事件

使用现有 X Agent 模型路由，批量读取材料。初始建议每批最多 20 条，并受输入 token 上限约束；低流量时最多等待 60 秒。长帖按段落拆分并保留同帖关系，不直接截去尾部。

每条材料返回以下一种结果，并附简短原因：

| 结果 | 含义 | 后续 |
| --- | --- | --- |
| 驱动候选 | 有具体变化，能初步提出影响方向 | 进入第二阶段 |
| 可组合材料 | 有具体事件或变化，但单独不足以形成投资逻辑 | 保存结构化事件摘要，供关联检索 |
| 无候选 | 日常闲聊、重复表述、缺少变化的静态介绍等 | 保存简短判定，不做后续推导 |
| 材料不完整 | 无法从现有内容读出核心信息 | 进入有界补充读取或待处理状态 |

识别视角包括需求扩张、供给约束、替代路线、竞争格局、资金买卖、成本和利润分配、规则变化、风险转移，以及资本和关注方向的变化。这些是启发方式，不是必须命中的封闭分类。

“变化”可以是数据变化、开始测试新方案、两个行业开始合作，或新披露的瓶颈。不要求帖子明确写出同比、环比或投资结论。模型可以延伸思考，但要写出延伸的中间关系。

两项排除原则：

1. **静态知识本身不足以形成驱动。** 介绍某种钢材用于半导体设备，不自动推出买供应商；开始替换材料、显著增加用量或出现交付瓶颈，才有变化。
2. **内部占比上升本身不足以形成驱动。** 某业务占平台持仓 43%，没有额外需求、收入或竞争变化时不产出。但不能因此排除所有公司内部指标：奈飞观看时长下降、回购额度增加仍然具有明确变化。

### 3.3 跨帖组合：避免只看懂单条新闻

第一阶段为候选和可组合材料保存主体、行业、动作、时间、变化对象和潜在影响关系。新材料到达时，检索最近 7 天的相关摘要，最多取 20 条去重材料；对明确命中的同一事件或主体，可补充最近 30 天上下文。

先按主体和事件召回，再按语义补充，不对所有帖子两两推理。上述时间与数量是初始可配置值，不承诺覆盖所有跨期联系。

例如一条 AI 公司收购医药企业的帖子可成为可组合材料；另一家公司出现类似动作时，第二阶段看到两件独立事件，尝试提出「AI 公司资本开始进入药物研发／Agent 医药组合」的驱动。不能要求第一条帖子已经包含投资观点，否则第二条到来时无材料可用。

仅仅“同属 AI”不足以合并。需说明两条材料共同支持哪项具体变化；同一新闻的多次转述不能作为两家公司独立行动。

### 3.4 第二阶段：生成逻辑与标的

模型读取候选、相关事件摘要和必要原文，输出短内容：

- **驱动逻辑**：变化 → 传导关系 → 潜在影响，一至三句话。
- **标的**：名称、代码／市场（知道时填写）、方向，以及该资产与驱动之间的一句话关系。
- **原文与推导边界**：哪些来自帖子，哪些由系统延伸；引用具体来源。
- **条件**：仅保留材料已有或推导必需的条件，不展开核查清单。

不强行生成标的清单。能定位一个就写一个；没有具体资产时显示「标的待定位：实验猴供应商」等。不能靠泛化行业受益名单填满结果。

有明确公司名但缺交易代码，或方向明确但缺公司身份时，可以做一次浅搜索，最多读取三个结果摘要，只解决标的身份。仍不明确就保留待定位，不继续研究收入贡献、估值或逻辑真实性。搜索开销单独统计。

暂沿用现有 `X_AGENT_MODEL` 路由，为两个阶段分别设置并发、批量、超时与 token 预算；不预设必须更换模型。候选阶段按具体驱动判断是否保留，不用高分前 N 条永久丢弃其余候选。

## 4. 结果页设计

X Agent 增加「投资线索」页。账号目录出现第四列开关、对应筛选和订阅账号数。

结果主表仅突出：**驱动逻辑｜标的及方向｜来源时间**。支持 24 小时／7 天／30 天、标的待定位、账号及关键词筛选，服务端分页。

展示示例：

> **头部云厂商产能提前售出，未满足需求可能流向独立 GPU 云。**
> 标的：Nebius（NBIS），偏多。
> 来源：原帖账号、发布时间、原帖链接。

> **两家 AI 公司分别收购医药相关企业，可能提升市场对 AI＋医药方向的关注。**
> 标的待定位：相关上市公司。
> 来源：两个独立事件及各自原帖。

展开详情显示原文摘录、作者与转发／引用关系、推导链条、条件、首次发现和最近实质更新时间。不展示真假评分、买卖建议强度或预期收益。

同一事件的同一驱动合为一张卡，新增不同传导关系可保留独立逻辑。新增来源只增加来源记录，不刷新实质更新时间；有新变量、条件变化或新标的关系才生成修订。旧材料重新被转发时显示原始日期，不包装成新事件。

## 5. 执行与存储

### 5.1 独立消费，复用现有数据库

建议新增 `investment_leads` 包及独立分析 worker，逻辑归属 X Agent，仍使用 `hottopic.sqlite`。共享采集进程只负责将材料和任务持久化，不等待本模块模型完成。

理由：当前情绪／推介任务表的模块约束仅含两项，处理代码也有二选一分支；投资线索还需要批量扫描和跨帖关联。为其建立独立任务表，比直接扩展旧表更清楚，也可避免大量新调用阻塞共享轮询。

建议独立服务名为 `odaily-investment-leads.service`。它不自行抓取 X 时间线；抓取仍由现有进程统一节流。附件补充若涉及同一上游 API，也必须通过共享采集调度，不能另开绕过节流的请求通道。

### 5.2 建议数据结构

| 数据 | 主要内容 |
| --- | --- |
| 材料快照 | 原始 ID、正文、引用／转发关系、原始发布时间、收集时间、内容摘要哈希、完整性状态 |
| 账号观察关系 | 哪个目录账号在何时提供该材料，支持同源去重和开关资格检查 |
| 阶段任务 | 阶段、材料／候选 ID、状态、尝试次数、租约、下次重试时间、错误、Prompt 版本、模型与用量 |
| 事件摘要 | 第一阶段提取的主体、动作、变化、关联标签，供短期组合检索 |
| 线索及修订 | 驱动逻辑、条件、标的及方向、来源关系、首次发现、实质更新时间、版本 |

材料以原始内容身份和内容版本去重；阶段任务以材料版本及分析版本幂等。组合任务使用去重来源集合和分析版本，避免不断重复分析相同组合。

模型和搜索请求在 SQLite 写事务外执行。数据库只做短事务领取、保存结果与更新租约；worker 崩溃后按租约回收。任务初始最多尝试三次，失败可见，并提供有界手动重试。失败、预算暂停、无候选分开统计。

共享 inbox 当前存在短期清理，本模块不能只保存一个可能被删除的 inbox ID。落地时独立保存所需公开材料快照及来源关系。

初始保留策略：非结果原文及失败任务材料保留 30 天，组合摘要保留 30 天；已生成线索所引用的必要摘录、来源链接和结果修订随线索长期保留。到期未处理任务标为已过期并计数，不伪装成分析成功；不无限保留失败原始数据。

### 5.3 成本和积压控制

- 第一阶段去重后批处理；第二阶段只处理候选与相关事件组合。
- 两个阶段初始各一路模型并发，补充读取／搜索单独限额，均可配置。
- 为新材料扫描和候选推导分配独立处理额度，避免互相饿死；账号之间按待处理顺序轮转，避免高频账号长期挤占。
- 设置每日输入 token、第二阶段调用、外链读取及搜索预算。预算具体值在实施时按采集量和模型单价计算，不能只以账号数估算。
- 达到预算后显示「预算暂停」，保留任务和积压；恢复后继续，不标为无候选。临近保留期限或持续积压时在控制台显示异常。
- 页面展示：抓取覆盖与延迟、待扫描／待推导数、最老任务等待时间、各阶段用量、候选率、失败和缺失材料数。

端到端速度受共享轮询约束。60 秒只是已收集材料的凑批等待上限，不能据此承诺发帖后一分钟发现。

## 6. 启用与历史边界

建议上线时从启用时刻开始收集本模块材料，不自动扫描整个存量库。

现有账号切换不回放历史；新账号首次抓取可以处理最近 24 小时的可用帖子，明确显示原始日期。纯转发优先按转发发生时间判断是否新活动，原始帖子日期仍单独保存；上游未提供活动时间时标记时间不完整，不把老原帖当作刚发生的新闻。

模块使用独立启用时间和采集游标，不沿用 HotTopic 的部署起点。之后如需要历史回放，单独提供时间与数量有界、显式标注历史来源的操作。

## 7. 实施涉及的文件与契约

实现边界与主要模块如下：

1. `backend/packages/hottopic/service.py`：第四开关迁移、全部账号入口、任意开关调度、材料持久化及新任务入队、总览计数。
2. `backend/packages/hottopic/capture.py`：从共享响应提供投资线索所需的引用与转发材料，保留既有消费者的输入语义。
3. 新增投资线索包和 worker 入口：批扫描、关联检索、推导、归并、修订、重试及保留清理。
4. `backend/packages/editor_plugin_api.py`：扩展既有订阅接口，新增线索列表、详情、运行状态和失败重试接口，复用管理员鉴权。
5. `frontend/src/xCaptureStore.ts`、`frontend/src/XAgentPanel.tsx`：第四开关、类型与计数、投资线索分页及详情、运行状态。
6. 实施时同步更新《完整程序架构》《控制台-X Agent》，新增《X Agent-投资线索》模块细节，记录服务、Prompt、任务状态、预算和失败处理。

不将本模块混入市场情绪或项目推介的金融／Crypto 词表过滤，也不让原有账号筛选报告覆盖投资线索开关。

## 8. 后续实施时的验收重点

本轮未执行验收测试。后续验收应覆盖：

- 全部旧账号一次性开启，新账号各入口默认开启；人工关闭经重启、导入后不被重置；仅第四项开启也会采集。
- 原创、引用、纯转发均能提供材料；同源多账号不重复推导，关闭其中一个不误伤另一个。
- AWS 产能紧张能延伸至独立云；两条 AI 医药收购能组合；没有 ticker 的猴子需求线索不被金融词表拦截。
- Variational 内部占比和静态钢材工艺介绍单独不产出；材料替代测试、观看时长下降和回购增加可以成为候选。
- 生益材料保留测试阶段，关税保留生效条件，PURR 回购不误写为新增购买 HYPE。
- 找不到标的时允许留空；模型失败和材料缺失不算无候选；重复新闻不制造新增驱动。
- 新 worker 停止不阻塞共享采集；重启不丢任务、不重复结果；结果来源不因共享 inbox 清理而消失。

前期已选案例用于检查语义边界。评估实际漏检与成本时，还需要随机样本，不能用刻意找出的好案例推算全量效果。
