# 写作审阅报告

## 目的

`writing-review-report` 是一个离线复盘命令，只评价 AI 已生成快讯的标题和正文写法，不参与主写作链路，不改变任务状态，也不判断稿件是否应该发布。

它读取本地 SQLite 中 `x_task_pipeline.write_completed_at`、`writer_model`、`final_title`、`final_content`（缺失时回退到 `draft_title`、`draft_content`），默认审阅最近 12 小时的结果。只要写作阶段已完成且存在 `writer_model`，就视为 AI 写作样本；最终稿优先于草稿。

## 命令

在仓库根目录执行：

```bash
PYTHONPATH=backend python backend/src/main.py writing-review-report
```

常用参数：

- `--hours 12`：修改审阅窗口，最大 720 小时。
- `--path /path/to/odaily.sqlite`：覆盖 `ODAILY_SQLITE_PATH`，数据库以只读方式打开。
- `--limit 50`：只审阅最新的若干条。
- `--model MODEL`：临时覆盖 `WRITING_REVIEW_MODEL` 和 `AUDITOR_MODEL`。
- `--output-dir DIR`：覆盖默认输出目录 `data/exports/writing_review`。

每次运行生成同名时间戳的 `.md` 和 `.json` 文件。报告逐条保存当前标题、正文、判断、问题片段、改写建议和可复用问题模式；汇总区统计 `no_change`、`minor_edit`、`rewrite` 和调用失败数量。

## 审阅边界

Prompt 只要求编辑批评和改写：标题重点、结果/动作前置、人物与背景取舍、重复、中文自然度、正文结构、快讯感，以及标题和正文内部的时间/动作逻辑。原始输入仅用于理解上下文。

Prompt 明确排除事实核查、来源可靠性、发布决策、竞品/营销分类、流水线状态、标点风格和外部知识纠错。没有明显收益时必须输出 `no_change`，不能为了产生意见而改写。

每条调用单独捕获异常；某条失败会进入报告的“审阅失败”，其余条目继续处理。命令不会写入主 SQLite 或 `auditor_checks`。
