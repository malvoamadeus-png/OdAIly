# 收集者-币安广场

## 职责与安全边界

收集者-币安广场按控制台配置的官方账号主页监控公开普通帖子。该能力依赖币安网页内部、未公开承诺的响应结构，属于实验性信源。生产默认总开关关闭，systemd unit 只安装不启动。

启用必须同时满足：

- `binance_square_settings.enabled = 1`；
- `odaily-binance-square.service` 已由运维启动；
- 账号自身 `enabled = 1`。

任一条件不满足都不启动浏览器、不访问币安、不创建任务。总开关打开不会自动操作 systemd。

## 输入与采集

- 账号入口只接受 `www.binance.com/{locale}/square/profile/{slug}`，保存时规范为英文主页 URL。
- worker 使用 `xvfb-run` 下的有头 Playwright Chromium，不读取登录 Cookie。
- 固定每 180 秒读取一次启用账号，捕获主页自身发出的 `queryUserProfilePageContentsWithFilter` 内容响应。
- 只接收 `contentType = 1`、同时具有帖子 ID 和非空正文的记录；直播等其他类型忽略。
- 保存帖子 ID、作者、正文、原始发布时间、原帖链接、图片/视频 URL 和原始 payload。

页面改版、WAF、超时或响应字段异常均记为采集失败，不猜测数据、不创建空任务，也不尝试绕过风控。

## 基线、去重与交接

账号第一次成功抓取时，把最新窗口最多 20 条普通帖子写入 `binance_square_seen_posts`，并设置 `seeded_at`，不创建历史任务。后续轮询以帖子 ID 去重，按发布时间从旧到新处理新增内容。

新增帖子写入主库 `tasks`：

- `source = binance_square`
- `source_item_id = 帖子 ID`
- `source_url = 币安广场原帖链接`
- metadata 保留账号、作者、写作名和媒体字段

任务成功提交本地 `write_flow` 队列后才标记帖子已处理。队列提交失败时保留同一任务并在下轮重提，避免丢帖或重复任务。

创建任务前复用 `x` 路径的信源排除规则；命中后只标记帖子已处理，不创建任务。

## 后续处理与发布

`binance_square` 复用 X 常规 Crypto 链路：判断者-Crypto、查重、常规/链上/融资写作、格式化、发布者。Prompt 的来源名称使用“币安广场”，作者优先取账号配置的写作名。

发布阶段有不可配置的安全边界：所有币安广场任务固定使用 `binance_square_manual_only`，以 `isPublish=false` 挂后台并进入 `ready_review`。现有 X 发布者规则无法让其自动发布。

## 命令与服务

```bash
python backend/src/main.py binance-square-init-db
python backend/src/main.py binance-square-worker --once
python backend/src/main.py binance-square-worker
```

生产 unit 为 `deploy/odaily-binance-square.service`。首次部署只复制 unit 并执行 `systemctl daemon-reload`，不得默认 enable/start。
