# 中文写作风格规范

本规范约束面向读者的中文内容及相关写作 Prompt。目标是让读者直接看见谁做了什么、材料实际支持什么，以及这些事实为什么重要。

## 句子结构

优先写明确主体、语义准确的谓语和具体对象或结果。可把它理解为“主体 + 动作 + 对象/结果”，但不要求每句机械套用语法上的 SVO：中文状态句可以没有宾语，例如“SK 海力士相关 ADR 仍以约 28% 的溢价交易”。

- 主体是行动者时，让行动者承担句子动作：“XX 账号否认出售和收购传闻。”
- 主体是信息来源时，直接写来源做了什么：“公司公告否认出售传闻。”“报告预计需求供应比分别达到 121% 和 129%。”
- 陈述已核实的状态或数据时，可以直接写事实：“SK 海力士相关 ADR 仍以约 28% 的溢价交易。”来源会影响判断时，再在句中明确归属。
- 一句话优先承载一个主要事实。先写主体和动作，再补充时间、条件、数据等必要信息。

“SVO”是主体和动作清楚的检查方法，不是必须出现施事者和宾语的公式。被动句、无主句或状态句在确有表达需要时可以使用；默认选择更直接、读者更容易理解的结构。

## 动词与关系

让谓语本身说清楚发生了什么。优先使用“宣布、否认、收购、出售、上调、下调、支付、部署、上涨、达到、维持”等具体动词；少用“出现、存在、进行、涉及、提到、被认为、得到关注”等只搭起句子却没有交代事实的泛化表达。

避免用抽象或口语化的操作动词代替事实关系，尤其避免反复使用“拿……做……”“把……放在……”“把……接到……上”“把……写进……”“将……作为核心锚点”等结构。根据实际关系直接写“简介列出……”“帖子写道……”“项目运行于……”“账号称……”“报告将……预计为……”。

“把”“将”“做”“接”“锚定”“抓手”“映射”“承接”等词并非一律禁用。只有在它们准确表达材料支持的具体动作或关系时才使用；删去后若能直接说清事实，就删去这层抽象转述。

## 来源与归因

具体来源不能被空泛的第三方说法替代。避免“有材料提到”“有消息显示”“外界认为”“出现了……的描述”等元话语；应写清公司、账号、机构、报告、帖子、群聊或数据分别做了什么。

- 来源主体明确时，写出主体：“XX 账号否认出售和收购说法。”
- 观点或传言需要归属时，写出具体来源类型：“群聊中的用户称……”“X 用户声称……”“该公司公告否认……”
- 数据主体重要时，写清数据来自哪里：“公司财报显示……”“交易所数据显示……”
- 材料不足以判断主体或关系时，不要补造行动者、身份、部署关系或因果；贴近原文说明账号写了什么、页面列了什么，或省略该推断。

归因要准确且就近。不要把社区说法写成确定事实，也不要用结尾免责句代替正文归因。只有当不确定性会影响读者判断时，才用具体来源和限定语说明它。

## 忠于材料

描述原始内容，不虚构发布者的意图或策略。简介写有“dev and researcher”，只能说明账号简介列出这些词；不能据此断言账号“将自己定位为开发者”，更不能推断项目已部署在简介提到的链上。

避免把读者带进材料处理过程。正文不应描述“材料如何被拿来锚定、连接、映射或延展”，而应直接说帖子写了什么、谁提出什么主张、项目做了什么，以及材料之间有何明确关系。

把背景和理由分开。背景交代事情发生的环境；理由说明读者为什么会炒作、关注或作出判断。写叙事时优先说明可核实的具体理由及其逻辑关系，不用行情反应、监控次数或泛泛情绪替代理由。

## 避免的表达

| 避免 | 优先写法 |
| --- | --- |
| 已出现对出售和收购说法的否认。 | XX 账号否认出售和收购说法。 |
| 有材料提到 SK 海力士相关 ADR 仍以约 28% 的溢价交易。 | SK 海力士相关 ADR 仍以约 28% 的溢价交易。需要归因时，写明数据来源。 |
| 韩国市场出现半导体大盘股和多数股票同步上行的描述。 | 韩国半导体大盘股普遍上涨。 |
| ALBINOGATOR 拿 Claude 鳄鱼、加州科学院和 Anthropic 的 Claude 品牌做核心锚点。 | ALBINOGATOR 的帖子同时提到 Claude 鳄鱼、加州科学院和 Anthropic 的 Claude 品牌。 |
| 小圣人生把一句话写进创建帖，又把自身接到某种身份上。 | 小圣人生在创建帖中写道：“……”，随后称：“……”。 |
| ZER 创建账号将自己定位为开发者、把项目放在 Robinhood Chain 上。 | ZER 创建账号的简介列出“dev and researcher”“V4 hooks”和“Robinhood Chain”。 |

改写示例用于说明句法方向，不代表可脱离来源核查而断言示例中的事实。

## 写后检查

1. 读者能否从句子看出谁说了、做了、预计了或否认了什么？
2. 谓语是否直接表达实际动作、状态或判断，而不是“出现了描述”“进行了相关工作”等空壳？
3. 来源、观点、传言和数据归属是否准确？是否把简介标签推成了未证实的项目事实？
4. 是否连续堆叠“把/将 + 对象 + 抽象关系”，或用“拿、接、锚点、抓手”等词转述本可直接表达的关系？
5. 正文写的是读者关心的事实和理由，还是采集过程、情绪反应、空泛背景或免责套话？

具体业务的叙事规范、发布格式和固定文案优先约束对应输出；本规范提供通用句法与表达默认值，不覆盖事实审查或来源规则。
