# 控制台-快讯及数据总览

## 边界

`快讯及数据总览` 是控制台一级标签，统一承载 Odaily 已发布快讯的人工运营字段、值班排班、值班绩效、贡献快讯和事件首发复盘。浏览器只调用认证后的 `POST /console/newsflash-operations`，不直连 SQLite，也不在前端拼接跨表统计。

该模块不改变 `tasks` 状态，不领取 worker 任务。权威基础快讯仍是主 SQLite 的 `odaily_reference_items`；事件与首发来自 `newsflash_items / newsflash_events / newsflash_event_sources`；人工事实写入独立的 `newsflash_*` 运营表。

OdAIly 管理台的 `快讯总览` 是只读展示后台：逐条对应 Odaily 快讯字段，并展示产出来源、审阅优先级、文本审查状态、事实审查状态、查重和阅读状态；这些审查与阅读字段不提供操作入口。它不提供 Alt 放大、未读底色或官方推送/上下线控件。Odaily 官方后台审核工作台是另一套未来项目，包含完整审核交互，设计边界见 `docs/讨论与修改日志/OdAIly后台审核工作台设计方案.md`。本轮只实现前者的字段展示。

周贡献明细通过 `contributions` action 查询，月度总览通过 `contributions_month` action 查询；两者都由后端完成跨表统计和评分，浏览器只负责选择周/月并展示返回结果。首发单位人工覆盖也由同一认证接口写入运营事实。

## 二级标签

- `快讯总览`：固定每页 50 条，按发布时间倒序；支持标题包含搜索、快讯 ID 精确定位，以及日期、发布类型、操作人、推送、贡献者、贡献类型、首发状态和首发单位筛选。沿用既有的发布人归属、贡献归属和优质快讯运营字段；产出来源、审阅优先级、文本审查、事实审查、查重和阅读状态均为只读展示，不增加这些状态的反馈、阅读留痕或官方后台操作。
- `排班表`：按月展示自然周日历。工作日默认三班，周末默认两班；某日可以人工切换班制。
- `数据总览`：按 `日期 + 班次 + 值班人` 展示，并支持自然周和人工归属月份汇总。
- `优质快讯`：从 `2026-08-03` 起按北京时间自然周计算浏览量门槛，按值班人展示入选快讯和达标但被规则排除的快讯；支持按周明细和月度总览，月度总览按归属完整自然周展示每位值班人各周及月份合计的入选条数、排除条数和 KPI；快讯总览和明细表均可设置人工“自动判断 / 直接入选 / 直接排除”。
- `贡献快讯`：提供“按周明细”和“月度总览”。按周明细按北京时间自然周和贡献者分组，展示周基准 A、数量、总浏览量、平均浏览量、逐条分数和人员周总分，并保留快讯明细编辑；首发单位可逐条选择“自动”或人工指定为 Odaily、BlockBeats、PANews、金色财经；月度总览按归属月份展示每位贡献者各自然周的数量、总分、总浏览量、平均浏览量，以及月份合计，并在表格下提供可自定义多选时间、维度和人员的原生 SVG 柱状图。图表默认只显示月份合计、总分和除 Malvo 外的全部启用贡献者。
- `事件与首发`：固定每页 50 个事件，展示事件代表标题、首发单位、首发时间、来源数和来源明细；搜索同时匹配事件代表标题、事件内来源快讯标题和来源快讯 ID，便于从任意子事件反查所属事件合集。来源明细链接使用来源媒体自己的详情页，不使用媒体引用的外部原文链接。

页面首次进入和顶部手动刷新时读取当前数据，不做前端自动轮询。

## 快讯字段

快讯总览字段为：

- 快讯 ID
- 快讯标题
- 文本审查状态：来自 `auditor_checks` 中与当前标题、正文版本匹配的结果；显示未审查、待审查、审查中、未发现问题、发现问题、执行失败或无需审查。只读展示，不提供接受/拒绝等反馈操作。
- 事实审查：未审查、待查、审查中、无需审查（`—`）、豁免、未发现问题、发现疑点、无法确认、执行失败；支持状态筛选与当前筛选范围数量，点击进入独立详情页查看原文对照、外部证据及历史版本。
- 查重：显示搜索者在对应发布流水线保存的判定；无重复显示 `—`，重复时显示标记并附目标和原因；未查重、待关联、历史未记录分别表达。
- 阅读状态：显示 Odaily 官方后台共享阅读状态；当前没有该状态的同步接口，统一显示“未同步”，不通过 OdAIly 页面访问或个人信息流回执推断，也不在本后台记录阅读动作。
- 产出来源：显示 X、币安广场、竞品、外媒、热点自动快讯、Hyperliquid 监控、Gate 行情、股票行情、Meme 速递、定时简报或人工发布；匹配尚未确认显示“来源待匹配”，本功能启用前的旧记录显示“历史未记录”。
- 审阅优先级：`高 / 中 / 低`，并展示一句等级理由；未评估、评估失败、历史未记录和不适用分别保留独立状态，不以“低”代表未评估。行情、Meme 速递、定时简报和人工发布显示 `—`。
- 发布时间
- 是否推送
- 操作人 / 发布人归属
- 当前浏览量
- 贡献者
- 贡献类型
- 优质快讯人工覆盖
- 首发单位

基础来源暂时拿不到操作人、浏览量或推送状态时显示 `—`，不按 `0` 或 `否` 处理。浏览量只保存数据源当前值，不保存历史绩效快照；统计同时返回已知值覆盖率。

事实审查结果来自发布后异步 `fact_checks`，网页读取不调用模型；只关联与当前标题、正文、原文定位链接及审查策略版本一致的结果。无记录显示“未审查”，不等同无需审查或通过。`fact_review` action 通过 `source_item_id` 和可选 `check_id` 获取详情；页面入口为 `?view=newsflash&fact_review={ID}`。详情页将原文对照的事实问题与补充建议分开展示；补充建议不计为事实问题，不改变状态筛选与数量。完整处理契约见 `事实审查者.md`。原中文质量审核者的对外名称改为“文本审查者”，既有技术标识保留兼容。

人工字段保存在 `newsflash_operation_facts`。人工修改发布人后设置 `publisher_locked = 1`，后续来源同步不得覆盖；所有网页人工修改写入 `newsflash_operation_audit`。

来源、优先级和查重结果保存在主 SQLite 的 `newsflash_production_metadata`，按推送幂等键保存稳定来源键、Odaily ID、推送标题和时刻、优先级结果及查重快照。Push API 响应中只有一个可识别快讯 ID 时以该 ID 关联；返回多个 ID 时保持待匹配，不退化为标题关联。没有 ID 时仅在标题完全一致、发布时间相差不超过 5 分钟，且来源记录与 Odaily 快讯两侧都唯一时绑定。多条候选、无匹配或时间不明时不猜测关联，显示“来源待匹配”。不会扫描并回填功能启用前的历史记录。新人工快讯只有在启用时间之后同时存在人工发布者归属和发布时间时显示“人工发布”。

优先级只依据快讯标题和正文明确表达的事件重要性：高表示直接影响交易判断或具有广泛传播价值的重大进展；中表示有明确行业价值但范围或影响有限；低表示常规、局部或影响有限的动态。它不是事实准确性、风险、文本质量或发布资格结论，也不读取审查疑点、阅读状态或发布决定。常规发布者在同一次模型调用中输出两项结果，解析优先级失败不改变既有直发/挂后台决定；发布者按规则跳过模型时，在推送成功后另行评估，失败状态不回写发布状态。热点自动快讯在现有写稿调用中产出优先级。

文本审查状态读取 `auditor_checks` 中与当前标题、正文内容哈希一致的最近结果；标题或正文修改后，旧版本状态不沿用。查重结果由主流水线在发布时随来源元数据保存，普通发布快讯会记录已完成且未判重的结果；没有查重结果的来源显示“未查重”。阅读状态当前没有官方共享数据源，在接口接通前只显示“未同步”。三类状态都不改变发布决定，OdAIly 总览不提供审查反馈或阅读操作。

`quality_override` 取 `none / include / exclude`。`include` 会跳过浏览量门槛和自动排除条件，`exclude` 会把达到自动门槛的快讯直接放入“达标但排除”；两者都不改变“必须是已映射人类发布者且成功归入值班班次”的候选边界。`first_source_override` 为空时使用事件自动归并结果；不为空时以人工指定的首发单位作为展示和相关首发判断结果。两类人工覆盖修改同样写入 `newsflash_operation_audit`。

## 发布人归属

- 操作人非空：按 `newsflash_roster_aliases` 做大小写和首尾空格不敏感匹配；命中后归属人类，未命中显示原始名称并标记未映射。
- 操作人为空：在操作人 / 浏览量导入时按本次导入的快讯对照 OdAIly 发布记录。优先解析发布响应里的远端快讯 ID；没有 ID 时使用最终标题完全一致且发布时间相差不超过 5 分钟。总览和统计读取不会为缺失事实逐条回溯流水线。
- 空操作人发布后 10 分钟仍未匹配 OdAIly：归为 `其他 AI`。
- 运营事实缺失或未分类时，快讯总览和数据总览按时间状态显示为 `其他 AI` 或 `识别中`；不会在读取时逐条回溯流水线。待操作人 / 浏览量导入后，由导入流程绑定并归类为 `OdAIly`。
- 发布类型与贡献标记独立维护；即使快讯暂时归为 `其他 AI / 识别中`，也始终可以在快讯总览中选择贡献者和贡献类型。
- 数据总览只统计人工值班者和全天值班的 OdAIly；其他 AI 只在快讯总览展示。

初始历史别名包括：`Z -> Zoey`、`蔡 / 蔡聪 -> Harbour`、`LEO / CryptoLeo -> Leo`、`shark -> Shark`、`jk -> Dc.`、`南枳 -> Malvo`、`Asher -> asher`。人员停用时不删除历史排班和统计。

## 贡献快讯

- 页面不提供独立的贡献勾选入口；选择唯一贡献者即标记为贡献快讯。
- 清空贡献者即取消贡献，后端同步清空贡献者并恢复 `regular` 类型。
- 贡献类型严格为 `regular / night / ppp`，页面显示 `常规 / 夜间 / PPP`，默认 `regular`。
- 后端仍保存 `is_contribution` 作为兼容性和统计字段，但前端以贡献者是否存在作为唯一操作入口。
- 任意贡献快讯都从操作人的值班绩效中排除，不因贡献者与操作人是否相同而改变。

初始贡献者为 Zoey、Harbour、Shark、Leo、Malvo、Golem、wenser、asher、azuma、Dc.。

贡献快讯周评分使用当周所有已推送且浏览量已知快讯的浏览量均值作为 A，缺失浏览量不进入 A 的分母；贡献明细则包含当周所有贡献快讯，包括未推送快讯。常规贡献快讯按浏览量分档：低于 `0.5A` 为 0 分，`[0.5A, 0.75A)` 为 0.25 分，`[0.75A, 2A]` 为 0.5 分，超过 `2A` 为基础分 1 分并额外奖励 0.5 分。夜间 / PPP 固定 0.5 分，超过 2A 不追加奖励；常规浏览量未知时为 0 分。

贡献快讯在上述浏览量评分前检查优质快讯使用的固定 28 个常规 X 信源和竞品首发事实；命中任一规则时基础分、超 `2A` 奖励和计入分数均为 0。接口保留按浏览量原本可得的分数及归零原因，便于区分“浏览量本身为 0 分”和“被规则归零”。该判定对历史贡献快讯同样实时生效，不需要回写历史运营事实。

每个人的基础分先按 `min(基础分合计, 5)` 封顶；原始基础分合计低于 5 时不计算任何 `2A` 奖励，达到 5 后才计算全部符合条件的奖励，最终总分为 `min(原始基础分合计, 5 + 2A 奖励)`，因此不会超过原始基础分合计。没有已知推送浏览量时，页面标记 A 数据不足，常规快讯计 0 分，夜间 / PPP 仍计 0.5 分。A 和分数均实时重算，不保存历史评分快照。

月度总览以 `report_month` 查询被归属到该月份的完整自然周；每周仍独立使用该周的 A、封顶和超 `2A` 奖励规则。人员月度总分为各归属周人员总分之和，月度总浏览量为各周总浏览量之和，月度平均浏览量按所有贡献快讯中已知浏览量加权计算；A 不足的周仍保留在表格中并标注“ A不足”。

## 排班与统计

三班制固定为北京时间：

- 早班 `08:00-13:30`
- 中班 `13:30-19:30`
- 晚班 `19:30-次日 01:00`

两班制固定为：

- 早班 `08:00-16:00`
- 晚班 `16:00-次日 00:00`

每个班次统计窗口向前、向后各扩展 30 分钟，但一条快讯只归入一个班。要求发布人等于该班值班人，且发布时间落入扩展窗口。同一人值相邻两班时按真实班次边界切分，不使用重叠缓冲；非相邻窗口发生重叠时归入距离真实班次最近的一班。允许同一人一天值多个班，前端只给出确认提示。

某日从两班切三班或三班切两班时，后端清空当天人工排班，要求重新选择。OdAIly 始终作为不可编辑的全天值班行，按北京时间自然日统计，不使用人工班次缓冲。

排班人员颜色只由前端根据稳定 `person_key` 生成，不写数据库。同一人员跨月份保持相同的浅色背景、边框和深色文字；已排班下拉框使用该人员颜色，未排班保持中性样式。日历上方仅为当月可值班人员显示颜色图例，姓名和边框仍是必要识别信息，颜色不是唯一提示。

统计字段：发布数量、推送数量、平均浏览量、推送浏览量。浏览量为空时从平均值分母排除；推送状态为空时不视为否；推送浏览量只累计已知浏览量。

## 优质快讯

`quality` action 是优质快讯周明细查询入口，`quality_month` action 是优质快讯月度总览查询入口；前端不拼接排班、首发或信源过滤。省略 `week_start` 时返回最近一个存在已知推送浏览量的自然周；显式日期会归一到周一，早于 `2026-08-03` 的请求被拒绝。

`quality_month` action 查询指定 `report_month` 的优质快讯月度总览。它复用每个归属完整自然周的 `quality` 结果，按值班人汇总入选条数、达标但排除条数和 KPI；月份内没有完整归属周时返回空表。

当周门槛使用该自然周所有 `is_pushed = 1` 且 `view_count` 已知快讯的浏览量均值，不限制发布者和贡献状态。比较使用未舍入值，只有 `view_count > average × 1.5` 才达标；没有已知浏览量的推送快讯时返回 `insufficient`，不产生入选结果或 KPI。

达标快讯还必须是已映射的人类发布者，并通过现有扩展班次窗口归入该发布人的值班班次。未映射或未归班的人类快讯不展示、不计分，接口单独返回数量供页面提示。每条无排除原因的快讯计 `0.2` KPI，无上限；总分始终按 `入选条数 × 0.2` 重算。

达标后可以同时记录多个排除原因：

- `contribution`：贡献快讯。
- `competitor_first`：首发事件已具备有效首发数据，且首发单位全部不含 Odaily；Odaily 与竞品并列、未匹配、数据不足或事件已排除状态均不命中。
- `regular_source`：原文链接是固定附录中的 28 个 X 账号，账号和域名匹配忽略大小写并兼容 X / Twitter 常见域名。
- `automated_coverage`：原文链接命中当周冻结的已启用 X 监控账号，或已启用媒体监控与固定外媒的域名。
- `jin10_content`：快讯正文包含“金十”。

排除词组按各自冻结的匹配范围判定：组内所有词都出现时命中该组，任一组命中即排除。`BTC + 爆仓`、`ETH + 爆仓`、`SOL + 爆仓` 匹配标题和正文合并文本；`早讯`、`午讯`、`晚讯` 只匹配标题；`SoSoValue` 只匹配正文。命中原因会在明细中显示。人工“直接入选”会跳过这些词组和其他自动排除条件。

原文链接优先读取 `odaily_reference_items.raw_payload.sourceUrl`；仅当它为空且 `source_url` 不是 Odaily 站内链接时回退。无原文链接不触发常规信源或自动覆盖排除，明细明确显示“无原文链接”。

## 自然周与月份

自然周以周一日期为稳定键。完全位于同一月份的自然周自动归入该月；跨月自然周在排班表人工选择该周实际覆盖的两个相邻月份之一。月统计由归入该月的完整自然周组成，不按月初和月末裁断。

前端周选择保留日期日历，但统一显示为“年月 + 月内第几周 + 起止日期”，例如 `2026年7月第4周（7月20日 - 7月26日）`。用户选择任意日期后，系统自动归一到该自然周周一；排班表中的周卡片使用相同格式。

## 事件与首发

首发比较范围为 Odaily、BlockBeats、PANews、金色财经。首发只使用来源系统归一后的发布时间，不用首次抓取时间替代；PANews 在原始发布时间基础上固定顺延 1 分钟，以抵消其回改发布时间提前造成的偏差。来源缺时间时不参与排序，全部来源都缺时间时显示 `数据不足`。多个来源系统归一发布时间精确到秒完全一致时，`first_sources` 保存全部并列单位。

事件代表标题使用最早具有有效发布时间的来源标题；全部缺时间时使用最早入库记录的标题，但首发仍为数据不足。

命中 `competitor` 排除规则的任何来源快讯都不进入 embedding、事件聚类、首发或对标数据。Odaily 命中后仍写入 `odaily_reference_items` 并出现在快讯总览，首发状态显示 `事件已排除（未参与事件归并）`，意思是该条快讯没有进入事件聚类和首发比较，不是删除或取消贡献标记。排除事实写入 `newsflash_event_exclusions`。规则变更只影响后续新处理，不自动重算历史事件。

事件来源保留 `source_url` 作为外部原文字段，同时返回按来源媒体识别出的 `media_url`；“事件与首发”页面只将 `media_url` 作为来源标题链接，无法识别媒体详情页时不展示外部原文链接。

## SQLite 表

- `newsflash_roster`：人员显示名、值班资格、贡献资格和启用状态。
- `newsflash_roster_aliases`：历史操作人名称到人员稳定键的映射。
- `newsflash_operation_facts`：操作人、发布人类型、浏览量、推送、贡献、首发单位人工覆盖、优质快讯人工覆盖及锁定状态。
- `newsflash_daily_modes`：每日两班 / 三班模式。
- `newsflash_shift_assignments`：日期、班次和值班人。
- `newsflash_reporting_weeks`：自然周到统计月份的人工归属。
- `newsflash_operation_audit`：控制台人工修改审计。
- `newsflash_event_exclusions`：新处理时命中竞品排除规则、不进入事件的来源项目。
- `newsflash_quality_week_rules`：以自然周周一为主键的优质快讯不可变规则快照；结果和 KPI 不做快照。
- `newsflash_production_metadata`：新快讯的稳定产出来源、Odaily ID 关联和独立审阅优先级；无历史回填。
- `newsflash_metadata_state`：记录来源/优先级字段启用时间，用于区分新人工发布与历史未记录快讯。

## 命令

```powershell
python backend\src\main.py competitor-init-db
python backend\src\main.py newsflash-ops-init-db
python backend\src\main.py newsflash-ops-import-xlsx --path data\raw\七月第四周.xlsx --start-date 2026-07-20 --end-date 2026-07-27
python backend\src\main.py newsflash-ops-seed-confirmed-week
```

`--end-date` 是北京时间排他上界。XLSX 导入只更新主库已存在的快讯 ID；缺失 ID 跳过并输出数量。重复执行按快讯 ID 更新同一条来源事实，不创建重复数据。该命令只用于本次正式历史数据接入，未来来源 API 直接调用相同 repository 写入契约。

## 无参数浏览量补齐

本地工作区根目录或 `data/raw/` 中放入快讯统计 XLSX 后，可以直接运行：

```bash
python3 scripts/import_newsflash_views.py
```

该脚本只扫描根目录和 `data/raw/` 下名称匹配 `快讯统计*.xlsx` 的文件，按北京时间自然周列出本地覆盖，使用 Windows OpenSSH 只读查询 `odaily-official:/opt/OdAIly` 的已有运营事实，再按文件修改时间从旧到新上传临时文件并导入，最后修改的版本覆盖前面版本。已有 `newsflash_operation_facts` 不再作为跳过条件，空浏览量占位记录也会被最新 XLSX 补齐；人工锁定的发布人仍由后端保护。远程临时文件在每个文件处理后删除，不创建数据库备份。
