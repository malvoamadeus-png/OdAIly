# 收集者-竞品

## 职责

收集者-竞品负责：

- 抓取 BlockBeats、PANews、金色财经快讯
- 抓取 Odaily 快讯作为参考语料
- 将竞品快讯写入 `tasks`
- 为新竞品快讯提交本地流水线 `write_flow` job
- 将 Odaily 参考语料写入 `odaily_reference_items`
- 将竞品与 Odaily 快讯写入 `newsflash_*` 事件聚合和来源归属链路

当前实现仍使用 `competitor_monitor` 包和 `competitor-monitor-worker` 命令名，文档统一称“收集者-竞品”。

## 存储边界

### Linux 主 SQLite

仍然是权威业务存储，负责：

- `tasks`
- `odaily_reference_items`
- `newsflash_items`
- `newsflash_events`
- `newsflash_event_sources`
- `newsflash_event_exclusions`
- 事件归属和聚合摘要，供后端档案与查重辅助使用

### 本地 SQLite

本轮新增竞品运行时库：

- `data/processed/competitor_monitor/competitor_monitor.sqlite`

当前本地库承载：

- 最近窗口的 `newsflash_items` 镜像
- 已知 `event_sources` 归属镜像
- recent window 预热标记

本地库缺失或损坏时：

- worker 会从主 SQLite 读取最近窗口重建
- 重建完成后恢复到 local-first 模式

### 本地 JSON 配置

BlockBeats API Key 与额度状态保存在 Linux 本地 JSON，不进入业务主 SQLite：

- 默认路径：`data/config/blockbeats_key.json`
- 覆盖环境变量：`BLOCKBEATS_KEY_CONFIG_PATH`
- 文件字段：`api_key`、`status`、`last_checked_at`、`last_success_at`、`last_quota_error_at`、`last_error`、`last_error_payload`、`updated_at`、`updated_by`、`auto_register_status`、`last_auto_register_at`、`last_auto_register_error`、`last_auto_register_error_payload`

`competitor-monitor-worker` 每轮抓取 BlockBeats 前都会读取该文件的最新内容；本地文件 `api_key` 优先，缺失时再兜底读取 `.env` / 环境变量里的 `BLOCKBEATS_API_KEY`。

默认启用 BlockBeats 自动注册：

- 首次没有可用 key 时，worker 自动申请并验证一个新 key。
- 当前 key 返回额度不足或 HTTP 429 时，worker 记录额度错误，调用 `blockbeats_registration` 内置注册器申请新 key，替换本地 JSON 后只重试 BlockBeats 一次。
- 新 key 注册失败时保留旧 key，不覆盖人工配置；失败状态和错误摘要写入同一个本地 JSON。
- 自动注册失败后默认冷却 `3600` 秒；`BLOCKBEATS_AUTO_REGISTER_ENABLED=false` 可关闭自动注册。
- 临时邮箱、邮箱密码和注册密码不落盘。

## 处理流程

### 1. 抓取与清洗

- 拉取竞品快讯与 Odaily 快讯
- 做标题/正文清洗
- 对全部四个来源计算统一 `competitor` 路径事件排除；`match_target = title` 只用标题匹配，`match_target = all` 同时使用标题和正文匹配。Odaily 命中时仍保留 reference，但不进入事件聚类
- 默认规则组包含 `MAGNE.AI 竞品屏蔽`：`scopes = ['competitor']`、`terms = ['MAGNE.AI']`、`match_target = all`，标题或正文命中都不创建任务
- BlockBeats 抓取成功时写回 `status = ok` 与 `last_success_at`
- BlockBeats 缺 key 时写回 `status = missing_key`
- BlockBeats 返回额度不足或 429 时写回 `status = quota_exhausted`、错误摘要和 payload 摘要
- BlockBeats 自动注册成功后替换 `api_key`，并在新 key 的单次重试成功后写回 `status = ok`
- BlockBeats 自动注册失败时保留原 `api_key`，写回 `auto_register_status = failed` 和自动申请错误摘要；冷却期间不重复申请
- BlockBeats 普通请求失败时写回 `status = request_failed`
- BlockBeats 只在 API 返回外部原文链接时才保存 `source_url`，优先从 `sourceUrl` / `source_url` / `originalUrl` / `original_url` / `sourceLink` / `source_link` / `jumpUrl` / `jump_url` / `link` / `url` 等字段中取非 `theblockbeats.info` / `blockbeats.info` 域名的链接
- 如果 BlockBeats 只返回律动站内页，或没有外部原文链接，则 `source_url` 留空，避免把竞品站内页透出到我方后台
- 金色财经只在 API 返回外部原文链接时才保存 `source_url`，优先取 `link`，其次取外部 `jump_url`
- 如果金色财经只返回站内 `jinse` 页面，或没有外部原文链接，则 `source_url` 留空，避免把竞品站内页透出到我方后台

BlockBeats 的 `missing_key`、`quota_exhausted` 或 `request_failed` 只标记该来源失败，PANews、金色财经和 Odaily 仍会继续执行。

竞品排除规则组命中后：

- BlockBeats、PANews、金色财经不进入 `tasks`
- 任意来源都不进入 embedding、`newsflash_items`、事件聚类、首发和对标统计
- Odaily 仍进入 `odaily_reference_items`，供快讯总览和搜索者查重使用
- 新处理命中写入 `newsflash_event_exclusions`，用于快讯总览显示 `事件已排除（未参与事件归并）`；这不删除 Odaily 参考快讯，也不自动取消人工贡献标记
- 规则修改不回扫、不重算历史事件；已有事件归属不会因后续规则变化自动删除

### 2. 写入远端业务表并提交本地流水线

- 竞品快讯：按时效规则决定是否写入 `tasks`
- Odaily 快讯：写入 `odaily_reference_items`
- 未命中事件排除规则的竞品和 Odaily 写入 `newsflash_items`
- 四个来源的发布时间解析后统一转换为 UTC，再写入 `tasks.published_at`、`odaily_reference_items.published_at`、`newsflash_items.published_at` 和事件摘要时间；PANews 的系统时间在此基础上固定顺延 1 分钟，用于时效窗、最近窗口、事件聚合和首发排序，以抵消其可能回改发布时间提前的偏差。PANews 原始值不改写，仅保留在 `raw_payload`。历史修复命令按同一规则重算。
- Odaily 无论是否命中事件排除规则都写入 `odaily_reference_items`；因此宽排除词不会删除搜索者查重参考语料，只会阻止该条进入事件与首发比较。
- Odaily 参考语料的正文清洗只应去掉 UI 噪音、媒体前缀和固定栏目包装，不应删除会影响语义判断的正文词语，例如 `利好`、`利空` 等内容词。
- Odaily 参考语料若原始 HTML 已用 `<p>`、`<br>` 等标签分段，写入 `odaily_reference_items.content` 时必须保留这些语义段落边界，但统一压成“单换行分段”；不能把相邻段落直接压成一行，也不能保留空白段落或双空行，否则会把 `交易对` 与下一行 `交易开放时间：` 粘连，或在后台正文里留下无效空行。
- 新竞品快讯入库后提交 `write_flow` job

竞品快讯进入本地流水线后的执行顺序为：

```text
search -> judge_crypto -> write -> format_publish -> publish
```

也就是说，竞品先查重，再判断，再生成和发布。

来自 `blockbeats / panews / jinse` 的任务在 `judge_crypto` 节点只调用一次判断模型，但使用竞品专用自然语言 Prompt 和 Schema。非 Crypto AI、无关传统财经、营销活动与例行公司新闻可在这里直接丢弃；结构化解析失败进入重试 / 失败状态，不再按关键词强行放行。

竞品抓取与事件 AI 复核共用 `COMPETITOR_REQUEST_TIMEOUT_SECONDS`，默认客户端超时为 `90` 秒。

本地流水线 job 唯一键是 `source + source_item_id`。入队失败时，本轮会记录失败并等待下轮重试，不把这条竞品快讯视为已经成功交给发布链路。

### 3. 回填本地工作集

远端写入完成后，worker 会把事件聚合需要的最近语料镜像到本地 SQLite。

额外约定：

- Odaily 参考语料保存成功后，也会同步镜像到共享 `searcher.sqlite`
- 这样搜索者不需要再为这批热语料反复读取主 SQLite

### 4. 事件聚合

事件聚合当前是“本地最近窗口镜像优先”：

- `list_recent_event_sources(...)` 默认从本地 SQLite 读取
- 如果本地 recent window 尚未建立，先从主 SQLite 读取最近窗口，再落入热缓存
- 针对当前 item 的既有归属，如果本地缺失，可按 item_id 回源补齐，不会整窗重拉

聚合完成后：

- 事件归属和聚合摘要写回主 SQLite；控制台通过 `快讯及数据总览 / 事件与首发` 复盘，但不恢复收藏和备注入口。事件来源接口保留 `source_url` 的外部原文语义，另计算 `media_url` 作为来源媒体详情链接，避免把媒体引用的上一级原文链接当成媒体文章链接
- 本地镜像同步更新归属结果

业务判断口径是“同一报道”，表结构和代码包仍使用 `newsflash_events` / `competitor_monitor` 等实现名。目标是把同一份原始文章、社交媒体发言、公告、报告或明确事实披露的不同品牌改写归入一组，用于比较谁先发和谁写得好；相同主题、相同主体或同一场大事件不自动视为同一报道。

报道归属按以下顺序执行：

- 同一原始文章 URL、同一 X status URL 或同一来源文档 URL（规范化协议、域名、尾部斜杠并移除常见跟踪参数）直接归入同一报道；仅同域名或同一 X 账号不构成直接匹配。
- Embedding 输入仍是标题和正文。相似度达到 `event_duplicate_threshold`（默认 `0.88`）直接合并，保留高相似自动路径。
- 相似度低于 `event_ai_review_threshold` 不合并；中间区间交给 AI。生产环境可通过 `COMPETITOR_EVENT_AI_REVIEW_THRESHOLD` 或 `SEARCH_AI_REVIEW_THRESHOLD` 配置下限。
- AI 输入来源、原始链接、标题和正文，不输入 embedding 相似度；AI 只输出 `is_same_event: true/false`。代码只读取这个布尔裁决，保存的审计结果不再包含会参与判断的 `reason` 字段。
- AI 的 `true` 只表示两条内容报道同一份原始消息或同一时点的同一项声明、动作、数据发布或事实披露。仅主题相同、不同分析/预测/评论、预告与后续进展、单项报道与综合要闻、部分事实重合或证据不足均返回 `false`。
- 事件已有来源使用最早有有效发布时间的来源作为稳定基准；新来源必须与基准报道匹配，不能因为分别与组内不同条目匹配而通过链式关系扩大事件。

首发摘要只使用来源的系统归一发布时间；其中 PANews 比其原始发布时间顺延 1 分钟。缺少原始发布时间的来源不使用 `first_seen_at` 兜底，也不参与首发排序；全部来源都缺时间时首发为空。多个来源系统归一发布时间精确到秒相同时写入 `newsflash_events.first_sources` 作为并列首发列表。事件代表标题使用最早具有有效发布时间的来源标题；全部缺时间时回退最早入库标题。

如果 AI 网关返回空响应、非 JSON、缺少布尔裁决或临时异常，本轮会把对应候选对视为“不合并”，继续完成其余事件归属。

如果事件聚合外围仍出现临时异常，收集者-竞品会记录日志，并在 heartbeat metadata 的 `event_error` 中保留错误；但这类事件聚合辅助链路失败不会让整轮抓取失败，也不会阻断成功心跳。

常驻 worker 会捕获单轮外围异常并在下一轮继续运行，避免一次主 SQLite、事件聚合或本地流水线提交波动导致收集者-竞品进程退出。

## 与搜索者的关系

收集者-竞品维护两类会被搜索者复用的数据：

- `odaily_reference_items`：保存 Odaily 已发布快讯的 主 SQLite 历史镜像；`x_processing` 和 `external_media_alert` 查重实时刷新优先调用 Odaily 官方快讯 API，仅在 API 不可用时回退读取该表
- `newsflash_*`：保存事件聚合、来源归属和后端档案信息

BlockBeats API Key 与额度状态的控制台读写走 `editor-plugin-api-server` 的 `/console/blockbeats-key/get` 和 `/console/blockbeats-key/save`，不新增业务表。

## 时效规则

竞品写入 `tasks` 时仍受发布链路时效窗限制：

- 默认由 `PROCESSING_FRESHNESS_WINDOW_SECONDS=1200` 控制
- 超过窗口的竞品快讯不进入 AI 发布主链路

但事件聚合链路不使用这个 10 分钟窗口裁切：

- 旧快讯仍可进入 `newsflash_*`
- 用于服务重启后的最近窗口补齐和事件连续性维护

## 心跳

收集者-竞品会写 `pipeline_worker_heartbeats`，但已改为降频策略：

- 稳定态最多 60 秒一条
- 状态变更立即写
- 失败立即写

## 运行命令

```powershell
python backend\src\main.py competitor-init-db
python backend\src\main.py competitor-monitor-worker --once
python backend\src\main.py competitor-monitor-worker
python backend\src\main.py competitor-repair-newsflash-time --source panews --since 2026-07-28 --until 2026-08-29
```

`competitor-repair-newsflash-time` 是显式历史修复命令：根据来源原始 payload 重新解析发布时间，把主库参考快讯、竞品任务、事件源及审核者/编写者3派生时间归一为 UTC，并对 PANews 应用固定顺延 1 分钟，再重算受影响事件摘要。可用 `--source` 限定来源，`--since` / `--until` 使用北京时间日期（前者包含、后者排除）限定范围。普通 worker 启动不会自动批量重写历史数据。
