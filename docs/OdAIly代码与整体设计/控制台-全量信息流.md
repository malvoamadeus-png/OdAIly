# 控制台-全量信息流

## 职责与边界

全量信息流是跨业务只读查询入口，不接管原有业务状态机，不触发采集、写作、重试、发布或 Telegram。后端认证后只开放 `list`、`detail`、`registry`、`health` 四类受约束动作；浏览器不传 SQL、表名、文件路径或业务库地址。

查询库和巡检状态默认共用 `data/runtime/system_information.sqlite`，压缩证据默认位于同级 `system_information/evidence/`。设置 `ODAILY_SYSTEM_OBSERVABILITY_DIR` 可切换整个目录。生产推荐 `/data/OdAIly/system-observability`；切换目录只影响新增观测库，不搬动或替代主 SQLite、HotTopic、Meme、行情等业务库。

投影、巡检和列表请求共用的观测 SQLite 使用 WAL，写锁等待上限为 60 秒；连接使用退出上下文即关闭的连接类。只读业务库统一经 `connect_sqlite_readonly` 打开并设置 `query_only`。标准库 `sqlite3.Connection` 的上下文管理只提交/回滚事务，不关闭连接。短间隔 worker 若漏用关闭型连接会耗尽 API 的文件描述符并导致 SQLite 无法打开，回归测试覆盖该生命周期。观测库写入失败会在健康状态暴露，并由常驻投影/巡检线程在下一轮继续处理。

## 新闻视图与诊断视图

`list` API 默认 `view=news`；显式 `view=diagnostic` 查询技术主体。默认新闻视图展示通过门槛的主任务及重复项，价值不足的原始材料、配置、采集尝试、股票行情、内部研究和审查记录不单独占据新闻列表。搜索先于判断而停止的重复项仍展示，准入标识为重复，不补造“价值通过”。`deduped` 表示通过前置步骤，不代表重复；`publisher_pending` 表示等待投递决定，不代表已挂后台。直发、挂后台等状态直接解释本系统 API 的内部状态，不核验官网。

标题优先使用稿件标题、原始标题及正文摘录，纯数字 ID 不作为主标题。详情增加准入结论、重复命中对象、来源名和已知的来源更新时间；未知时间保持空值。关联按 task_id、精确来源键以及 delivery_key 与审查稿件 ID 完成；无法精确关联的技术行仍仅保留在诊断入口，不做标题相似猜测。发布后审查作为原稿详情事件，不替换原稿发布状态。

默认按最后实际处理操作时间倒序，取任务时间、阶段时间和尝试时间的最大值；关联后续处理也刷新原稿。只更新时间不会另存证据或追加历史事件；页面读取、投影时刻和心跳不刷新业务排序。查询继续使用现有观测库，保留创建时间排序和显式时间范围；不传范围时搜索当前保留的全部新闻记录，没有隐含当天限制。

## 数据模型与查询

- `system_information_items` 保存一条稳定业务身份的轻量快照；重试不创建新主体。新增 `news_visible`、`admission`、`parent_item_id`、`duplicate_json`、`source_name`、`source_updated_at_ms` 和新闻活动时间部分索引。首次升级按有界水位重新分类历史主体，不重置来源 outbox 水位。
- `system_information_events` 保存投影观察到的状态变化、历史初始快照和 X 阶段尝试事件。X 阶段尝试保存在主库的 `x_processing_attempts` / `x_processing_attempt_events`；主库只留模型返回的内容引用、SHA-256、字节数和短摘录，完整压缩证据直接写到 `ODAILY_SYSTEM_OBSERVABILITY_DIR` 下的内容寻址归档，再进行解析或业务校验。
- `system_information_evidence` 登记内容寻址压缩文件；重复 JSON 只存一份。详情读取时才解压。
- `system_information_search` 每条主体、每种二元组最多存一行，先交集筛选候选，再按证据文件解压并验证关键词是连续子串；中文两字词和英文大小写不敏感。关键词至少两个字符、最多 400 字符；只索引标题、摘要、来源身份与链接、来源正文、初稿和定稿等可读文本，不索引原始载荷、模型输入、规则和查重 JSON。已清理的原文不再支持全文搜索。旧索引由后台按主体 rowid 每分钟最多整理 25 条；迁移期间旧索引可能产生额外候选，查询仍按当前可读文本校验。旧位置表的重建流程保留，迁移期间健康接口标记索引未就绪。
- `idx_system_information_business_source` 覆盖健康页按业务和来源聚合的来源统计；`idx_system_information_business_activity` 支持按业务过滤后按最近活动时间倒序。新闻活动部分索引支持默认视图；无关键词新闻列表与总数显式使用该索引，避免升级后无统计信息时误选 parent_item_id=NULL 并全表扫描。来源数据库/表/行 ID 组合索引支持逐条归档核对，证据引用索引支持跨日清理引用闭包，避免对每条材料重复扫描全部历史事件。上述索引避免大库查询建临时分组/排序表，首次升级由 SQLite 幂等创建。
- 时间在读模型内统一保存 UTC epoch 毫秒。列表先服务端过滤，默认按最近活动时间倒序，也可切换为创建时间；时间缺失的记录排在已知时间之后。游标按 `(time,item_id)` 稳定分页。详情才返回大证据。
- 每页默认 50 条，游标不随新入库记录漂移；刷新会重新读取快照，不做页面自动轮询。

### 详情读取与页面性能

详情在同一个 SQLite 连接中读取主体、关联事件及证据文件索引，证据引用每批最多 500 个；同一请求内相同引用只解压一次。不跨请求缓存证据，后续请求仍遵守清理、脱敏和跨日外部错误隐藏规则。返回内容及缺失证据的表达保持原契约。

`/console/system-information` 对超过 4096 字节、客户端接受 gzip 的 JSON 响应启用压缩，并返回 `Vary: Accept-Encoding`；跨域预检允许缓存 600 秒。这只缓存预检许可，不缓存业务响应，不跳过请求认证。

前端保留完整详情响应，模型原始返回、原文、写作输出、投递回执、输入规则和技术 JSON 的折叠区只在展开时生成文本节点；关闭后卸载正文，重新展开仍可查看完整内容。此优化减少大详情首次渲染开销，不截断或删除审计证据。

## 主流程尝试写入

主 X 流水线在领取任务后创建阶段尝试；模型调用前记录实际 Prompt、模板 key/version、规则、模型、思考等级、输入摘要和代码 revision。模型返回先直接 gzip 写入独立观测卷的内容寻址归档，来源主库只保存引用、hash、字节数和最多 1000 字摘录，再进行 JSON 解析和业务校验。证据在投影前由 pin 保护；投影后详情复用同一证据引用。成功、失败和停止事件按留存规则追加写入；跨日外部错误明细例外删除，不承诺保留早先失败详情；调用超时但未取得响应时保留异常和失败，不伪造原始返回或 request ID。生产 API 与 X worker 均要求 `/data` 挂载并写入 `/data/OdAIly/system-observability`，避免大响应占用根盘。

其他可变业务表的触发器在原 SQLite 写事务内追加精简状态事件。业务 outbox 只含受限身份、状态、错误/理由、投递摘要和时间；配置 outbox 另按字段白名单记录启停、间隔、适用范围和版本元数据。两类记录都排除凭据；业务 outbox 不复制正文或模型返回，配置 outbox 不复制请求头或任意配置 JSON。更新触发器仍把时间戳放入实际状态变化事件 payload，但只刷新 `updated_at`、`last_seen_at`、`last_polled_at`、`last_checked_at`、`heartbeat_at`、`last_attempt_at`、`last_success_at`、`polled_at` 或 `checked_at` 时不追加事件。X 采集尝试只记录插入和真实字段更新，7 天保留清理的删除不入 outbox；既有此类删除事件在投影时跳过并推进水位。触发器定义带版本号，投影器发现版本变化时幂等重建。观测库不可用时，来源事务仍可在 outbox 表内留待重试，投影失败不触发业务重试或外部投递。X 尝试表仍属于观测扩展与业务更新的分步写入，不能把模型响应审计等同于发布 outbox。投影按水位恢复，稳定事件 ID 防止重复；来源 outbox 每批默认读取 2000 条、上限 5000 条，并在查询库单个事务内提交主体、时间线和水位。时间线事件按各自留存规则保留；同一批中一个业务行的最新状态快照只写入一次。来源库 outbox 每 5 分钟最多清理 5000 条，且只删除已投影并超过 24 小时的事件；不存在到期记录时不启动来源库写事务。清理遇到写锁最多等待 2 秒，后续周期重试。

`tasks` 的事务 outbox 既追加每次主流程状态变化，也更新同一任务的当前快照。投影为 outbox 新建任务主体时补齐任务 ID、业务分类和准入/新闻可见性；更新既有主体时只改状态、阶段、摘要和活动时间，保留主快照中的稿件标题、来源材料、证据及查重关系。重复任务在新闻视图中仍可见。快照仅接受时间不早于已保存状态的事件，避免积压旧事件覆盖较新的主流程状态；这样即使全量历史回填存在积压，任务状态也可由 outbox 及时推进。

## 留存和磁盘

新闻主体、稿件、审核结论、来源身份和已有链接保留。常规新闻任务完成 30 天后，清理源正文、原始载荷和 metadata 中的原文上下文；关联的事实审查等待或执行中时暂缓，无法关联时采用保守保护。待处理、挂后台、失败任务以及确定性生成的数据任务不在该规则内。主库中竞品原文在 30 天后且其事件无近期变更时清除，Odaily 已发布正文保留。信息流仅在确认对应源正文已清除后剔除当前快照中的原文；已用于审核和巡检的问题证据按其保全规则继续保留。各阶段每分钟按主键最多扫描 100 行，游标循环，积压不会在恰满 30 天时立即清完；删除不自动缩小 SQLite 文件。

主写作流程的终态任务超过七天后，分批清理 `x_task_pipeline.search_result`、信息流当前快照和已过期候选的比较细节，保留判断、命中目标身份、标题及链接。待处理、挂后台及失败任务保持原样；实时查重热缓存不受影响。各独立业务中尚未登记的原文和查重字段不在本规则覆盖范围内。

外部依赖错误具体内容仅留北京时间当天。投影器每分钟有界清理来源表、事务 outbox、观测主体、时间线、证据及搜索索引中的跨日副本；来源事务计数器在失败写入同一事务增加日期/来源/阶段/类别计数，不保存对象清单。同一失败的管线、队列和投影副本不重复计数；重试次数变化可计为新尝试。首次接入只统计尚存的历史失败，不能重建已丢失尝试。查询层在物理清理尚未追平时也隐藏过期外部错误；对应业务失败状态、恢复输入与调度信息保留。健康页通过 external_error_daily 展示汇总。正常空结果/过期筛选不归入故障；本机 SQLite 锁、磁盘与程序问题仍保留可行动诊断。仅覆盖注册适配表及受管理观测材料，不清理 systemd journal 等操作系统日志。

每日巡检不自动将 90 天证据改写成摘录及 hash，也不再仅凭观测库引用清理孤立文件。已结束主任务的普通状态事件在七天后分批清理。来源阶段尝试及其信息流事件，只有任务已正常结束七天、阶段成功、同任务无失败或未完成尝试、来源事件已投影且不影响活动审核时，才清除原始响应、输入、规则和过程证据引用；时间线身份、结果、稿件与审核结论保留。审核关联无法确认时暂缓。已明确释放的证据进入有界回收队列；源库、信息流、pin 和审核引用全部复核后才删除文件，七天内重新登记的内容也保留。历史来源不明的孤立文件不自动删除。已结束采集尝试及队列技术事件也分批清理；其他业务事件保留。跨业务 outbox 按 15 秒间隔增量投影并在查询库单事务内提交每批事件与水位；纯时间戳刷新不生成 outbox 事件。已投影源事件超过 24 小时后每 5 分钟限量清理，每批最多 5000 条。

主任务普通状态事件清理同样复核主库当前状态、失败尝试和活动审核；源库不可用或审核关联不明时保留事件。复核按主库、信息流的顺序获取写锁，避免与证据写入顺序相反。

阶段尝试及文件回收由 `ODAILY_COMPLETED_EVIDENCE_RETENTION_ENABLED=1` 启用，默认关闭；上线前必须切换所有证据写入进程至同一版本，避免旧进程绕过写入与删除的并发保护。执行情况及错误分别记录在信息流 state 的 `attempt_retention`、`attempt_event_retention`、`attempt_evidence_reclaim` 对应结果字段中，累计回收文件数与删除前分配空间估计单独记录；候选和引用无法核实则保留。

已成功结束的 X 和币安广场采集事件，超过七天后可将明确无故障的过期快照加入同一回收队列；先保留账号身份，账号身份不明或快照包含错误时不清除。每轮最多登记 5 个文件，文件仍须通过其他引用检查后才回收。

无候选轻决定索引保留 30 天，并保存来源/账号、业务、阶段、时间、状态、已有理由和可找到的规则版本。D 巡检每日分层抽样最多 50 条无候选记录、压缩原文合计不超过 20 MiB；抽样证据 pin 14 天，问题卡详情和模型输入只按需读取，最多展开 30 条并为单条证据提供 8,000 字符摘要与完整性 hash。已完成快讯、Meme 和 X Agent 输出每天最多另抽查 30 项；这类样本引用现有保留证据，不另复制全文或延长其期限。样本和问题卡均表明证据缺失/截断，不能从样本推算总体准确率。

存储健康页展示所在文件系统总量、可用量、最低安全余量 `max(10 GiB, 15%)`、查询库和证据体积、采样天数及按历史样本估算的未来 30 天增长。生产 API 将查询库、巡检记录与压缩证据放在 `/data/OdAIly/system-observability`；2026-11-03 实测 `/data` 为约 98 GiB ext4 卷、可用约 92 GiB，根盘仍接近满载，因此观测数据继续全部放在 `/data`。无足够样本时增长估算为零但会同时显示样本数，不能据此解释为增长为零。巡检不会自动删除主业务库或关键证据腾空间。

## 生产启用与回退

1. 在官方服务器确认 `/data` 持久挂载和余量后，将 systemd API 环境配置设为 `ODAILY_SYSTEM_OBSERVABILITY_DIR=/data/OdAIly/system-observability`，建立仅 `root` 可读写的目录。
2. 拉取代码并重启 `odaily-editor-plugin-api.service`。service 固定设置 `ODAILY_SYSTEM_OBSERVABILITY_DIR=/data/OdAIly/system-observability`；独立查询库从空库幂等初始化，并为登记的可变来源表创建 SQLite outbox 触发器。投影器按 `tasks` ID、来源 rowid 与 outbox 水位有界回填，不调用模型、不推进业务、不投递内容。
3. 检查 `GET` 对应受认证接口返回 `search_index_ready`、按实际剩余任务行统计的投影 lag 和适配器状态，再验证代表业务、中文检索、详情和人工巡检决定。
4. 关闭时回退 API 代码版本或设置 `ODAILY_SYSTEM_OBSERVABILITY_DIR` 回默认路径；保留 `/data` 上新增库和证据。关闭投影/巡检不停止原有 worker，不删除证据，不重投已提交稿件。

生产首启应保留原代码版本，并记录目录权限、挂载 UUID、查询库路径和新服务心跳。主业务库可由独立运维步骤通过既有 `ODAILY_SQLITE_PATH` 切换到 `/data`，本次代码不会搬动文件、执行 VACUUM 或释放根盘空间；迁移仍需按 `SQLite主存储迁移.md` 完成停写、一致性核对和回退准备。
