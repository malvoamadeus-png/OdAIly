# 控制台-股票行情播报

## 职责与边界

`股票行情播报` 是独立的 Binance 股票类别合约监测与推送模块，业务实现位于
`backend/packages/stock_market_broadcast/`。它不创建主库 `tasks`，不进入
判断者、搜索者、编写者或发布者状态机，也不复用 Gate行情播报的规则、数据库和 worker。

## 合约发现与行情

worker 每小时读取 Binance USDⓈ-M Futures `exchangeInfo`，选择状态为
`TRADING`、合约类型为 `TRADIFI_PERPETUAL` 的以下 underlying type：

| Binance underlying type | 市场 | 文案冠名 |
|---|---|---|
| `EQUITY` | 美股 | 据MSX.COM数据 |
| `CN_EQUITY` | A股 | 据行情数据 |
| `HK_EQUITY` | 港股 | 据行情数据 |
| `KR_EQUITY` | 韩股 | 据Gate数据 |
| `JP_EQUITY` | 日股（若 Binance 后续提供） | 据Gate数据 |

股票类别内的 ETF 一并监测。其他 underlying type 不会被选择；`underlyingSubType`
中含 Pre-IPO、指数、商品或外汇的标的也会排除。所有行情均来自 Binance。对外文案使用合约代码去掉末尾 `USDT` 后的资产名，例如 `AAPLUSDT` 写作 `AAPL`；不推测或翻译公司全名。内部标识仍使用完整合约代码，现价单位为 USDT。

每30秒通过一次批量 `/fapi/v1/ticker/24hr` 请求读取当前合约现价与 Binance
滚动24小时涨跌幅。1小时涨跌使用本地最新报价与一小时前90秒容差内的样本计算。
缺报价、报价超过90秒或时间戳明显位于未来时，跳过该合约本轮判断并记录错误。

## 候选、合并与发布

1. 每30秒扫描1小时和24小时涨跌，使用未舍入值判断，文案显示一位小数。达到5%为后台候选，达到10%为直发候选；同时受下述恢复价格门槛约束，最终取两道条件中较低的档位。单轮跨级只保留直发。
2. 按“市场＋涨跌方向”收集候选，第一只也等待3分钟。一个资产的1H/24H只占一个位置，文案可同时列出两个周期，取较高档位。
3. 到期使用本轮新鲜行情重新判断。缺失、过期、退市或已回落至5%以内的候选不发；候选从5%升至10%时直接升级，不重复写两篇。
4. 每组分别合成后台稿和直发稿；同一资产只属于其中一篇。只有一只时写单标的稿；两只及以上合并，不在正文解释内部阈值或本档达标数量。普通稿按绝对涨跌幅从大到小最多列5只代表资产（同幅度按合约代码排序）；主题稿每个主题最多列5只，未归入主题的成员分开描述。未展开的成员仍计入播报记录及去重。
5. 该组任一稿件生成后，下一次汇总时间设为30分钟后。在此之前新增的候选积累到该时间统一处理；无候选、无进一步行情就不发。间隔已经过去后才出现新候选，则重新等待3分钟收集。本组一次汇总最多产生一篇后台稿和一篇直发稿，不影响其他市场或相反方向。

### 普涨、普跌口径

合并成员都有同一个达标周期时，优先24小时，其次1小时，计算该市场在这一周期的广度。只有满足以下全部条件才写“普涨/普跌”：

- 本轮有效报价且有该周期数据的资产至少2只，覆盖该市场在监测合约的至少80%。
- 有效样本中至少70%的资产同向上涨/下跌。
- 全部有效样本的涨跌幅中位数在该方向达到3%。

广度分母包括未达到5%的资产，不只统计候选。未满足条件时写“多只……涨幅/跌幅扩大”；混合周期没有共同达标窗口时分别写明各资产周期，不声称普涨/普跌。文案描述“美股相关合约”等监测范围，不把合约样本等同于整个股票市场。

### 恢复价格门槛

首次启动、每次进程重启、新资产首次有效报价和行情中断恢复时，为各资产记录第一笔有效价格 `resume_price` 与建立时间 `resumed_at`，本轮静默。后续必须同时满足：

- 至少一个滚动窗口（1H或24H）在该方向达到5%，且实际价格相对恢复价同向变化至少5%，才可挂后台。
- 至少一个滚动窗口在该方向达到10%，且实际价格相对恢复价同向变化至少10%，才可直发。
- 例如恢复价100、当时24H已涨20%，现价101不发、105最多挂后台、110才允许直发。下跌对称使用95、90。不是拿24H百分数做差，也不会把恢复前涨幅计入恢复价格门槛。

这道门槛在入队和最终汇总时都检查；窗口显示和对外文案继续使用真实滚动涨跌幅。合并、30分钟后续汇总、价格步长和升级极值规则继续同时生效。恢复价在当前连续运行阶段内保留，6小时价格去重锁到期不会清除恢复价；下一次启动或行情中断恢复时重新记录。恢复价及时间持久化在 `broadcast_state` 并由只读接口返回，控制台显示基线价格。

### 按价格抑制重复

- 每个资产的上涨、下跌各有一份价格记录，1H/24H、后台稿/直发稿和单标的/合并稿共用。
- 稿件生成时记录实际价格，锁定6小时。从这份价格再向同方向走出至少5%，才允许再次进入候选。例如上涨已在100播报，下一次需达到105；下跌已在100播报，下一次需达到95。阈值附近来回穿越不重新武装，仅滚动涨跌幅扩大也不够。
- 后台稿可升级直发一次，但现价必须超过这轮上涨最高价或低于下跌最低价；单纯24小时参考价变化不触发升级。已经进入升级候选的资产在汇总时仍须保持超过入队前的极值。升级同样受市场30分钟汇总时间约束。
- 每次消耗候选并生成稿件后，6小时从本次重新计时；已直发过的方向保留直发标记，不能通过回落为后台档再次获取“升级”资格。方向极值保留至本轮6小时记录到期。
- 6小时到期仅以当前价格和涨跌建立新基线，不因已有大幅涨跌立刻补发。基线已有5%/10%波动不会补发，后续仍需进一步价格变化、恢复价格门槛和合规升级。基线观察不视为已经真实发出后台稿或直发稿。
- 首次启动、新合约、重启或该资产有效行情中断超过90秒后，第一笔有效报价静默；重启清空待发候选，保留未到期价格记录和市场汇总时间；恢复报价若已向播报方向走得更远，则将静默基线向前推进，防止下一轮补发中断期间的波动，回调则不会降低原有再次播报价格门槛。重启时缺失报价的资产，延迟到其第一笔有效报价时单独静默。新出现的1小时窗口先建立自己的基线，不独立触发历史波动。

### 文案与发布边界

省略突破/回调分类和开盘、休市口径。资产名无 `USDT` 后缀，例如：

```text
Odaily星球日报讯 据 MSX.COM 数据，AAA 24 小时上涨12.3%，现报123.45 USDT。
Odaily星球日报讯 据 MSX.COM 数据，多只美股相关合约24 小时跌幅扩大，AAA 下跌11.6%，现报16.97 USDT；BBB 下跌6.6%，现报52.83 USDT。
Odaily星球日报讯 据 Gate 数据，005930 24 小时下跌10.2%，现报67800 USDT。
```

现价按交易所精度四舍五入后去除无意义尾零。美股多标的合并稿会把合约代码交给编写者模型识别公司及共同主题；至少70%的成员以不低于0.8的置信度归入同一主题时，标题和正文用主题概括，并将未归入主题的成员单独说明。识别结果不完整、置信度不足、主题不集中或模型不可用时，回退到“美股相关合约”描述。主题识别单次请求超时为8秒，不改变涨跌幅、现价或代表资产排序。

正文复用编写者2的确定性 `format_brief` 格式器，统一整理 `Odaily星球日报讯 ` 前缀、空格和标点；不创建主链路编写者2任务。生产配置默认启用主题识别，可通过 `STOCK_MARKET_THEME_CLASSIFICATION_ENABLED=false` 关闭；未配置模型凭据时自动使用通用描述。

候选、汇总时间、价格记录、行情样本和事件在同一 SQLite 事务中提交，再调用 Push Data API。后台稿使用 `isPublish=false`，直发稿使用 `isPublish=true`，均为 `isPush=false`。

事件键按市场、方向、汇总时刻和档位生成；只有首次插入成功的事件才请求接口。接口缺少可靠的幂等承诺，失败、超时或进程在调用前后崩溃均不自动重发；已经消耗的价格记录保留。事件结果为 `backend_created`、`published` 或 `push_failed`；`publishing` 表示已经消耗但尚未确认请求结果。

## SQLite 与运行

默认数据库为 `data/runtime/stock_market.sqlite`，可通过
`STOCK_MARKET_DB_PATH` 覆盖。`price_samples` 保留最近3小时数据；触发状态持久化，
`trigger_events` 保留最近500条，包含合并稿的全部资产明细；`broadcast_state` 保存价格记录和合并队列快照。旧版本事件原文保留，不转换为待发候选。旧版 `trigger_state` 表可留作历史资产，新规则不再读取它。
worker 状态、最近轮询和合约发现错误也写入该库。

```bash
python backend/src/main.py stock-market init-db
python backend/src/main.py stock-market status
python backend/src/main.py stock-market run --once
python backend/src/main.py stock-market run
```

生产运行单元为 `deploy/odaily-stock-market-broadcast.service`。可配置环境变量：

- `STOCK_MARKET_DB_PATH`
- `STOCK_MARKET_BINANCE_API_BASE`
- `STOCK_MARKET_REQUEST_TIMEOUT_SECONDS`
- `STOCK_MARKET_THEME_CLASSIFICATION_ENABLED`
- `ODAILY_PUSH_ENDPOINT`

## 控制台

只读一级页面位于 `Gate行情播报` 下方，通过认证的
`GET /console/stock-market/get` 读取 Linux 本地 SQLite。页面展示运行状态、
可搜索和筛选市场的资产行情表、1H/24H涨跌、上涨/下跌价格记录、待合并候选及计划汇总时间、最近事件及推送结果；页面打开时
每30秒刷新快照，离开页面后停止。没有规则编辑、单合约启停或手动发布入口。

运行状态同时检查最近轮询时间；超过90秒没有新轮询时显示“未检测到近期轮询”，避免停机后仍显示历史正常状态。本轮部分合约缺行情不会把整轮状态长期显示为首次基线。
