# 控制台-AI审阅

## 边界

AI 审阅只处理竞品事件及其原始信源，不再挖掘 X Agent 账号，也不修改 X Agent、X Capture 或媒体源配置。它复用主 SQLite 中已归并的事件、竞品来源原文和发布记录，不发起 X 抓取、外部网页搜索或发布操作。

队列、证据快照、人工决定和用量记录保存在 **data/runtime/ai_review.sqlite**。人工决定仅作为后续同类信源判断的少量示例，不写入发布或追踪配置。

## 每日运行

`odaily-hottopic.service` 的既有轮询在北京时间每天 06:00 后检查审阅任务，不增加常驻 worker。扫描回看最近 3 天；稳定项目键阻止重复入队。事件扫描策略和分析 Prompt 分别通过版本状态管理；分析每批最多 50 条，在后续轮询继续，直到队列完成或触及事件每日 token 上限。

只保留以下两类已归并事件，Hyperbot 来源的事件全部跳过：

- 竞品先发布，Odaily 随后由 AI 发布。按 Odaily 发布任务状态标记“直发”或“挂后台”；没有可关联的竞品来源 AI 发布任务时不入队。
- 至少两家不同竞品发布，Odaily 没有发布。

事件只用于发现竞品报道明确链接的原始信源。系统从竞品材料的来源 URL、结构化原文链接字段及正文 URL 提取链接，排除 Odaily 和竞品媒体自身域名，并解析为 X 账号或网站域名。只识别实际链接，不根据人名或账号提及猜测信源；没有原始链接时不入队。同一事件的相同信源合并为一个候选，不同信源分别判断。X 账号和网站会标记是否已在现有配置中追踪；网站仅作为线索，不自动创建监控。

AI 判断原始信源是否值得持续关注，而不是判断竞品是否值得跟发。Crypto 一手数据、研究、公告和读者交易决策信息可优先考虑；只有一次性文章、项目页面或临时活动且缺少持续产出证据的信源应不建议跟进。判断分为“优先考虑 / 可考虑 / 不建议跟进”，界面只展示“优先考虑”；其余判断保留在 SQLite。竞品文章作为发现依据折叠展示，原始信源链接是主内容。审阅台不提供添加账号或网站的操作。

重复扫描刷新候选证据；过期或不符合两类范围的事件候选会清理。人工处理过的决定可作为同类别的少量示例。

## 用量与失败

事件研究每日最多 **50,000,000 tokens**。分析前按本地 token 估算和输出上限预留预算；模型返回 usage 时按输入、输出 token 结算，缺失时估算。预算耗尽的队列顺延到下一北京时间日期。默认使用 `gpt-6-luna`，思考等级为 `none`；模型路由或返回失败时记录失败并最多重试三次。

AI 不修改事件、账号配置或发布状态。人工决定只作为后续同类信源判断的有限示例，不自动改写规则或执行微调。

## 接口

所有操作使用管理员会话保护的 `POST /console/ai-review`：

- `action=list`：按类别、状态和分页参数读取已完成且“优先考虑”的事件信源建议，并返回事件用量和近期决定统计。
- `action=detail`：按稳定 `item_key` 读取建议与证据。
- `action=decide`：将建议标为认可、驳回或暂缓。

事件类别为 `competitor_first_ai` 和 `multiple_competitors_no_odaily`；决定状态为 `pending / accepted / rejected / deferred`，分析状态为 `queued / completed / failed`。重复扫描按稳定候选键幂等。

## 控制台

页面提供两个事件类别筛选、决定状态筛选、分页、AI 判断、原始 X 账号或网站域名、原始链接、追踪状态、竞品发现文章和人工决定。网站域名只作提示，不会从审阅台写入媒体监控配置。进入页面或主动刷新时读取快照，不自动轮询。
