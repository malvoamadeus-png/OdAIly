# 控制台-AI文本自我升级

## 职责

AI文本自我升级用于研究文本审核者与编写者1之间的文本质量分歧。它把可可靠关联的已发布案例、文本审核者意见、编写者1素材及稿件版本提供给第三个模型逐案判断，并留存人工复核结果。它不修改写作 Prompt、文本审核规则、稿件或发布状态。

## 案例范围与关联

首次初始化时在模块数据库中保存 `enabled_at`。只收录此时间之后产生的 `auditor_checks.status = 'flagged'` 记录；既有标记不补审。

案例必须同时满足以下条件：

- `newsflash_production_metadata` 以 `id_match_status = 'matched'` 将已发布 `odaily_id` 唯一关联到 `delivery_key = 'odaily-task-{task_id}'`。
- `x_task_pipeline` 存在对应任务的写作和发布完成时间，且保存了编写者模型、草稿和定稿。
- 文本审核者记录的标题与正文哈希等于 `x_task_pipeline.final_title / final_content` 的审核哈希。稿件版本不同、发布 ID 未匹配或关联不完整时不建立案例，并计入批次未关联数。

案例按 `source_item_id + content_hash` 幂等去重。同一发布稿若存在多个文本审核版本，只取启用后最近一次标记作为该案例的审核证据。案例快照保存已审核标题/正文、审核结果和 Prompt 版本、来源链接与素材、编写者1草稿/定稿、模型和 Prompt 版本信息。模块不读取生产数据之外的存储，也不写回主 SQLite。

## 调度与模型

worker 在控制台 API 进程内运行，每 30 秒检查当前北京时间 4 小时时槽。时槽为每天 `00:00 / 04:00 / 08:00 / 12:00 / 16:00 / 20:00`；运行键以时槽为单位持久化，防止重复执行。空队列会记录零案例批次，不调用模型。服务重启时将未完成的批次和分析标记为失败，案例在后续时槽重试。

每个案例独立调用 `gpt-6-luna`，思考等级为 `medium`。结构化结果包含判断方向、置信度、理由和原文证据：

- `writer1_error`：文本审核者指出的问题成立，且在编写者1稿件中存在。
- `auditor_false_positive`：问题不成立，或只是审核范围外的风格偏好。

证据引用必须能在对应的已审核稿、编写者1草稿或来源素材中逐字核对；无法解析的模型响应会作为失败保留，在后续批次重试。一个案例失败不会中止同批其他案例。

## 人工决定与接口

认证后的 `/console/ai-text-self-upgrade` 接受 `list`、`detail`、`decide` 操作。列表按人工决定筛选，详情展示已发布稿、审核意见、来源素材、编写者1草稿/定稿及 AI 结论。

人工决定值为 `accepted / rejected / ignored`：

- `accepted` 表示认可 AI 判断，并纳入后续研究样本。
- `rejected` 表示不认可 AI 判断，不作为研究样本。
- `ignored` 表示特殊例外，不作为研究样本。

决定备注可选。每次决定都会追加历史记录，允许后来重新决定。案件、判断及决定历史不自动过期；任何决定都不触发系统改进。

## 存储与失败处理

案例、快照、批次和决定保存在 `ODAILY_SYSTEM_OBSERVABILITY_DIR/ai_text_self_upgrade.sqlite`；未设置该环境变量时沿用既有 system observability 目录。该 SQLite 与全量信息流、系统巡检库分开。模型及解析失败会保存错误和尝试次数，下一时槽再次尝试；批次运行错误保存在最近运行记录中。生产主 SQLite 始终只读。
