# 控制台-AI自我辩论

## 职责

AI自我辩论用于研究编写者1稿件与事实审核者的分歧。模块把可可靠关联的已发布快讯、事实审核意见及原文证据、编写者1素材和稿件版本交给第三个模型逐案判断，并保存人工复核结果。它不修改写作 Prompt、事实审核规则、稿件或发布状态。

## 案例范围与关联

首次启用事实自我辩论时在模块数据库保存 `fact_enabled_at`。只收录此时间之后由 `fact_check_runs` 新产生且当前 `fact_checks.status = 'flagged'` 的事实审核结果；更早的事实审核记录不补审。此前文本审核流程创建的案例仍保存在数据库，但标记为旧来源类型，不展示、不分析，也不纳入研究样本。

案例必须同时满足以下条件：

- `newsflash_production_metadata` 以 `id_match_status = 'matched'` 将事实审核的 `source_item_id` 唯一关联到 `delivery_key = 'odaily-task-{task_id}'`。
- `x_task_pipeline` 存在对应任务的写作和发布完成时间，且保存了编写者模型、草稿和定稿。
- 事实审核记录的标题与正文哈希等于 `x_task_pipeline.final_title / final_content` 的稿件哈希。稿件版本不同、发布 ID 未匹配或流水线信息不完整时不建立案例，并计入批次未关联数。

案例键由 `source_item_id + 已发布稿件内容哈希` 稳定生成。同一快讯有多个事实审核策略版本时，只取最近一次仍为 `flagged` 的当前审核结果。案例快照保存事实审核状态、策略版本、疑点、审核原文、结构化审查结果和外部搜索证据，以及来源链接与素材、编写者1草稿/定稿、模型和 Prompt 版本信息。模块只读主 SQLite，不写回。

## 调度与模型

worker 在控制台 API 进程内运行，每 30 秒检查当前北京时间 4 小时时槽。时槽为每天 `00:00 / 04:00 / 08:00 / 12:00 / 16:00 / 20:00`；运行键以时槽为单位持久化，防止重复执行。空队列会记录零案例批次，不调用模型。服务重启时将未完成的批次和分析标记为失败，案例在后续时槽重试。

每个案例独立调用 `gpt-6-luna`，思考等级为 `medium`。结构化结果包含判断方向、置信度、理由和原文证据：

- `writer1_error`：事实审核者指出了有证据支持的实质事实错误或误导性遗漏，且问题已存在于编写者1草稿中。
- `fact_auditor_error`：事实审核疑点被原始材料或审核证据否定，属于无依据或不成立的推断。
- `inconclusive`：原文缺失或不匹配、证据相互冲突、疑点无法验证，或问题只在编写者1之后的阶段出现。此时不把错误归给任一方。

涉及交易决策或主体身份的判断要求直接证据；证据不足时不得强行归因。证据引用必须能在已发布稿、编写者1草稿、来源素材或事实审核记录中逐字核对。无法解析或无法核对证据的模型结果作为失败保留，在后续时槽重试；单案失败不阻塞同批其他案例。

## 人工决定与接口

认证后的 `/console/ai-text-self-upgrade` 接受 `list`、`detail`、`decide` 操作。列表按人工决定筛选；详情展示已发布稿、事实审核意见和外部搜索证据、事实审核原文、编写者1素材、草稿/定稿及 AI 结论。

人工决定值为 `accepted / rejected / ignored`：

- `accepted` 表示认可 AI 的辩论结论，并纳入后续人工研究样本。
- `rejected` 表示不认可 AI 结论，不作为研究样本。
- `ignored` 表示特殊例外，不作为研究样本。

决定备注可选。每次决定都会追加历史记录，允许后来重新决定。案件、判断及决定历史不自动过期；任何决定都不触发系统改进。

## 存储与失败处理

案例、快照、批次和决定保存在 `ODAILY_SYSTEM_OBSERVABILITY_DIR/ai_text_self_upgrade.sqlite`；未设置该环境变量时沿用既有 system observability 目录。该 SQLite 与全量信息流、系统巡检库分开。旧文本审核案例在迁移时保留但从事实自我辩论范围排除。模型及解析失败会保存错误和尝试次数，下一时槽再次尝试；批次运行错误保存在最近运行记录中。生产主 SQLite 始终只读。
