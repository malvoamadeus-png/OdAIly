# 控制台-商务快讯

## 页面定位

- `商务快讯` 是 OdAIly 控制台一级标签，展示商务 Telegram 群消息的收件、AI 分类、Writer4 脱水、Writer2 定稿及挂后台状态。
- 页面面向多个客户群；SoSo 只是测试群，不作为独立业务逻辑或默认过滤条件。
- 首版生产仅启用 Soso 群；新发现的其他群默认为停用。
- 页面只读展示处理结果，并提供客户群映射配置；不承担 AI 处理、重试、人工审核或发布操作。

## 页面结构

页面含 `消息记录` 与 `客户群` 两个视图。

### 消息记录

- 默认按接收时间倒序分页，单页 50 条。
- 列表字段：接收时间、客户名、群名、发送者、AI 分类、快讯属性、处理状态、来源链接和挂后台结果。
- 顶部筛选支持客户群、AI 分类、处理状态、时间范围和关键词。
- 可筛选的 AI 分类：快讯、活动、长内容、其他、不确定。
- 快讯属性仅对快讯显示：朴素、宣传性。宣传性快讯显示 Writer4 脱水后的标题正文。
- 点开详情展示 AI 简短判定理由、原文（如仍保留）、Writer4 结果、Writer2 定稿、来源 URL、状态变更时间及 Push API 结果。
- 活动项显示原文和 `待接 API`，不显示 Writer4 脱水稿、Writer2 定稿或发布结果。
- 字数过滤、其他、长内容、不确定和处理失败项显示 AI 结果或失败原因。无文字的媒体更新不进入消息列表；旧版 `skipped_non_text` 行从列表和计数中排除。原文依照业务保留策略删除后，详情明确显示“原文已清理”，不尝试恢复。
- 页面不提供重新处理、重试、改分类、人工发布或人工审核操作。

### 客户群

- 群由 Telegram Bot `my_chat_member` 更新或该群首条更新自动登记，初始为未启用。
- 列表字段：`chat_id`、Telegram 群名、客户名、首次发现时间、启用状态和最近消息时间。
- 操作者可以编辑客户名并启用/停用群；新群在配置客户名并启用前不进入 AI 处理。
- 启停只作用于之后收到的新消息，不回放启用前或停用期间的历史消息。
- 多个群共用一个 Bot token 和收件器；控制台不配置群级轮询周期。

## 处理状态展示

- `pending`：已写入收件箱，等待处理。
- `processing`：已领取，等待 Writer4 分类。
- `filtered_short`：去掉空白及 URL 后少于 15 个 Unicode 字符。
- `activity_pending_api`：分类为活动，保留原文等待后续 API。
- `skipped_long_content`：主要内容位于外部链接的长内容。
- `skipped_other`：AI 识别为其他内容。
- `skipped_uncertain`：AI 无法可靠分类。
- `formatting`：快讯已生成，正在调用 Writer2 格式整理。
- `publishing`：Writer2 已定稿，Push API 请求已开始。
- `backgrounded`：Push API 已成功挂后台。
- `discarded_failure`：AI、Writer2 或 Push API 失败，或服务在处理中途退出；按业务约定不重试。

状态可以在列表显示为简短中文标签，详情保留稳定状态码，供排障和后续统计使用。

## 数据与接口

- `business_telegram_groups` 保存群 ID、Telegram 群名、客户名、启停状态、发现和更新时间。
- `business_message_inbox` 保存消息去重键、群/发送者/消息元数据、AI 分类和理由、Writer4 / Writer2 结果、来源 URL、处理状态、Push API 结果及插件提示结果。
- `business_telegram_recent_messages` 仅暂存最近 10 分钟的群消息 ID、发送者、URL 与临时文本，供候选消息扫描相邻原文链接；不会合并正文，过期文本随新收件清理。
- `business_telegram_state.last_update_id` 保存 Telegram update 游标。首次启动消费并跳过启动前积压消息，同时登记群；之后才处理新到消息。
- 已挂后台快讯与待接 API 活动保留原文。被跳过的原文只保留到相邻 URL 扫描和分类完成，随后清理；其处理元数据和必要的 AI 分类结果可用于页面列表。
- 前端通过认证后的 `editor-plugin-api-server` 专用接口 `POST /console/business-news/get` 读取消息与群列表，通过 `POST /console/business-news/groups/save` 保存客户名和启停状态；浏览器不直连 SQLite，也不使用任意 SQL 的通用表接口写入处理状态。
- 建议接口：`POST /console/business-news/get` 用于筛选分页，`POST /console/business-news/groups/save` 用于保存群客户名和启停状态。业务结果表只由 Telegram 接收器和处理 worker 写入。

## 刷新

- 页面进入、切换筛选或操作者点击刷新时读取一次。
- 页面不自动轮询；避免控制台无人查看时重复读取主 SQLite。消息接收和处理不依赖页面是否打开。
