# 控制台-系统巡检

## 职责

系统巡检在既有信源扩展建议之外，汇总渠道、覆盖、产出审核、规则执行、故障恢复和留存问题。它先用确定性逻辑产生有范围的候选，再异步调用模型复核证据。输出是供人工审阅的问题卡，不自动改 Prompt、监控配置、发布资格、稿件或已发送内容。

除跨日外部依赖错误例外清理外，问题卡保存稳定问题键、类别、预期与实际、影响范围、正反证据、首次/最近发现、运行恢复状态、分析状态、用量、错误、请求 ID、原始响应、人工决定和决定历史。人工认可/驳回/暂缓与运行恢复分离；实质新证据会重开同键问题但不会删除旧决定。

## 六类巡检

| 类别 | 当前执行逻辑 | 明确限制 |
| --- | --- | --- |
| A 信源扩展建议 | 继续使用 `packages.hottopic.ai_review` 的既有每日任务与独立预算。 | 不添加 X Agent 账号或自动改监控。 |
| B 渠道中断 | 每 5 分钟检查心跳、启用账号/站点配置和任务间隔；只对配置目录中当前启用的组件检查，缺失心跳或越过 `max(3×间隔,15分钟)` 窗口形成问题；最近失败需连续 3 个不同窗口确认。心跳按组件归并，仅取最新运行实例；有 PID 的 worker 重启历史不会逐条生成问题。 | 当前确定性配置覆盖 X 抓取、非主流媒体、金十、两类巨鲸、本地队列及币安广场。币安广场读取数据库总开关、worker 状态和启用账号的最近轮询/成功/错误；关闭总开关或账号不纳入预期。未登记或未启用组件的历史心跳忽略；启用配置无法读取时不能据此证明组件已停用，健康读取错误须单独呈现。成功空结果不视为故障。 |
| C 漏闻复盘 | 读取竞品事件表最近 3 天、竞品先发或需复核事件；按精确来源与来源 ID 关联原文、已登记无候选轻索引、任务及投递回执。Crypto/AI站点能匹配 `non_mainstream_media_sources.site_key` 时，附对应配置变更事件。 | 只呈现已观测到的配置变更，不用当前配置回填过去。配置变更记录缺失、来源无法精确映射或历史投递/公开关联不存在时标记未知；事件窗口有界，不执行全账号回扫。 |
| D 产出与审核复盘 | 检查最近一天新增文本/事实审核标记；从已完成的快讯、Meme 与 X Agent 结果中按业务/来源分层抽查最多 30 项，并另行抽查无候选决定样本。无候选样本每日最多 50 条，跨系统原文最多 20 MiB，原文证据 pin 14 天、轻索引保留 30 天。问题卡和 AI 输入按需展开至多 30 条样本证据。 | 抽样不推算总体正确率。历史稿件版本或人工改动没有记录时保持未知；样本证据缺失或已截断时不能判定语义错误。 |
| E 规则冲突与执行 | 对当前活动 Prompt 和同模板启用的特色模式做确定性正反约束扫描，再异步 AI 复核；检查链上模板固定开头、Hyperliquid 强制后台、固定刊头、金额/比例格式及样本时间清理等代码已明确的输出不变量。 | 只比较同一模板组合；发布者筛选规则属于下游阶段，不与写作 Prompt 跨阶段判冲突。格式检查复用现有代码规则，不新增编辑要求。 |
| F 持续故障 | 只检查可归因于本机存储或内部程序/输出校验的失败；过去 7 天内同一根因至少在 3 个自然日出现，且仍有未恢复对象时，按根因合并成一张问题卡。来源、阶段和规则版本作为影响范围，不再拆分问题；影响对象按卡内唯一任务/账号计数。任务当前状态仍为失败才计入未恢复，已进入待审核、自动发布、丢弃或过期等非失败状态的任务计为已恢复/已结束。 | 外部依赖错误、预期结果、未知归因、一次性失败和已恢复问题不作为持续故障展示。X 阶段尝试最多读取主键最新 50,000 条，X/币安采集尝试各最多读取最新 20,000 条，并结合 7 天时间窗；任务快照只查询明确的失败状态。只保留当前状态且无法确认跨日反复的本地队列错误不推断为长期故障。 |

每日巡检使用北京时间 06:00 后首次机会运行，以日期和策略版本幂等。渠道检查每 5 分钟运行且按五分钟 bucket 幂等。D 巡检开始时建立当日无候选抽样，再生成已完成产出和无候选两类复核问题；大证据不放入列表，详情和模型请求按样本键延迟取回并截断到 8,000 字节字符。任务运行、完成、失败和留存维护写入 `system_review_runs`；worker 最后心跳和异常写入独立 state。观测库采用 WAL、60 秒写锁等待；若锁持续导致状态记录失败，线程会记录该次错误并继续下一轮，不因错误持久化失败而退出。质量问题集中在控制台，不为常规巡检增加 Telegram 消息。

留存健康每日日志记录信息流 SQLite、WAL/SHM 与压缩证据目录尺寸，使用数据库所在文件系统计算余量。至少保留 `max(10 GiB, 文件系统容量的 15%)` 可用空间；首次日采样只有一个样本时，30 天增长预测返回空值并显示“样本不足”，不把缺少基线误报为零增长。已有两个及以上日样本后，按观测区间估算日均增长并外推 30 天。每日维护不再按 90 天将证据截断为摘录和 hash；无引用证据仍会清理。

外部超时、鉴权/额度、HTTP 和网络故障仅在北京时间当天形成可展开的问题卡；跨日后列表、待分析队列、详情和巡检运行错误读取均屏蔽明细，投影清理逐批移除持久副本。健康页展示按日分类次数，不能解释为唯一受影响新闻数。正常空结果与 freshness 筛除不形成故障聚合，本机存储问题优先单独分类。历史供应商错误没有逐新闻追因或最小摘要保留。

F 类持续故障不复用健康页的单日错误次数口径。单个任务失败属于业务结果，不自动等于系统级故障；只有内部可修根因跨日反复且仍未恢复时才进入巡检问题列表。默认待处理列表隐藏已恢复的旧 F 类聚合卡，历史决定仍可从历史筛选中查看。

## 模型预算与错误

新增模型巡检每日最多 100 次请求、1,000,000 输入 tokens；请求前原子预留，响应或调用边界失败后按已知实际输入用量结算，未发送请求释放预留。预算不足标记 `budget_paused` 并保留积压，不当作通过。一次调用失败最多自动尝试 3 次；超过后保留失败状态，需新证据或人工触发后再处理。

模型复核在 API 自身 worker 线程中执行，不在写作、发布或控制台同步请求线程内调用。当天保留上游 request ID、原始响应证据和解析错误；外部依赖故障跨日后清除技术详情及 AI 分析，保留日期、来源、阶段与错误类别的汇总次数。已有人工接受或拒绝时，保留该决定及清除详情后的问题卡。模型输出解析失败属于程序/输出校验问题，仍可保留诊断证据。当前路由复用 `search_ai_review_*`，模型可由 `SYSTEM_REVIEW_MODEL` 覆盖；超时可由 `SYSTEM_REVIEW_TIMEOUT_SECONDS` 覆盖。外部 API、抓取和发布不会被巡检重复调用。

## 当前文档级测试例

- `test_channel_checks_follow_enabled_config_and_detect_missing_heartbeat`：显式停用渠道不报中断，启用计划缺心跳可见。
- `test_binance_square_channel_checks_settings_worker_and_enabled_accounts`：检查币安广场总开关、worker 与账号状态，并忽略停用账号。
- `test_channel_failure_requires_three_consecutive_observations`：同一 bucket 幂等，连续不同 bucket 才累积，成功清零。
- `test_observability_store_uses_wal_and_extended_busy_timeout`：确认共享观测库使用 WAL 和 60 秒锁等待。
- `test_system_review_worker_survives_lock_while_persisting_error`：错误状态写入也遇锁时，巡检线程仍继续下一轮。
- `test_system_review_parse_failure_keeps_raw_response_and_settles_tokens`：JSON 解析失败仍保留原始响应、请求 ID、实际用量及引用。
- `test_budget_paused_review_retries_on_next_available_budget`：预算解除后继续队列。
- `test_new_evidence_reopens_review_item_without_erasing_decision_history`：新证据重开问题但保留之前人工决定。
- `test_rule_conflict_checks_only_active_template_versions`：不把未激活 Prompt 旧版本报为当前冲突。
- `test_no_candidate_samples_feed_review_card_detail_and_ai_input`：验证无候选抽样进入问题卡、详情和 AI 输入，已完成研究输出的证据也按需展开。
- `test_coverage_review_joins_source_links_decisions_config_changes_and_pipeline_receipts`：按精确来源 ID 关联原文、已登记轻决定、可用的站点配置变更和任务投递回执。
- `test_coverage_review_marks_missing_configuration_history_unknown`：缺少可回放配置变更时显示未知，不从当前配置推断历史状态。
- `test_rule_execution_checks_existing_onchain_opener_hyperliquid_backend_and_format_rules`：验证固定开头、强制后台、数字格式和样本时间不变量。
- `test_failure_clusters_only_report_multiday_internal_errors_and_count_recovery`：验证跨 3 个自然日重复的内部故障按根因合并，并扣除后续成功恢复的对象；单日及外部依赖错误不形成持续故障卡。

执行完整离线验收：

```bash
tools/dev pytest -q backend/test_system_observability.py
```

巡检线程运行于 `odaily-editor-plugin-api.service`，不是 `pipeline-supervisor` 的替代品。API 启动时会把前一进程留下的 `running` 巡检 run 标记为失败并记录重启中断，便于界面区分卡死和正在执行。竞品监控与竞品事件数据当前共用活动主 SQLite，巡检和投影均读取同一路径；不得按已废弃的独立竞品数据库目录判断覆盖缺失。生产信息流数据库与证据目录、停用方式见 `控制台-全量信息流.md`。
