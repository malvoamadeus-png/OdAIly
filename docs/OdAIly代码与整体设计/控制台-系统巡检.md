# 控制台-系统巡检

## 职责

系统巡检在既有信源扩展建议之外，汇总渠道、覆盖、产出审核、规则执行、故障恢复和留存问题。它先用确定性逻辑产生有范围的候选，再异步调用模型复核证据。输出是供人工审阅的问题卡，不自动改 Prompt、监控配置、发布资格、稿件或已发送内容。

问题卡保存稳定问题键、类别、预期与实际、影响范围、正反证据、首次/最近发现、运行恢复状态、分析状态、用量、错误、请求 ID、原始响应、人工决定和决定历史。人工认可/驳回/暂缓与运行恢复分离；实质新证据会重开同键问题但不会删除旧决定。

## 六类巡检

| 类别 | 当前执行逻辑 | 明确限制 |
| --- | --- | --- |
| A 信源扩展建议 | 继续使用 `packages.hottopic.ai_review` 的既有每日任务与独立预算。 | 不添加 X Agent 账号或自动改监控。 |
| B 渠道中断 | 每 5 分钟检查心跳、启用账号/站点配置和任务间隔；缺失心跳或越过 `max(3×间隔,15分钟)` 窗口形成问题；最近失败需连续 3 个不同窗口确认。 | 当前确定性配置覆盖 X 抓取、非主流媒体、金十、两类巨鲸、本地队列及币安广场。币安广场读取数据库总开关、worker 状态和启用账号的最近轮询/成功/错误；关闭总开关或账号不纳入预期。主库/竞品库中已有心跳的其他 worker 按心跳检查，但没有配置快照的 worker 暂不能检测“启用但从未启动”。成功空结果不视为故障。 |
| C 漏闻复盘 | 读取竞品事件表最近 3 天、竞品先发或需复核事件，并带原文链接、Odaily 覆盖字段及来源证据。 | 这是有界复核候选，不是逐原帖回查启用配置、采集决定、任务、后台回执与公开稿的完整漏闻判定；无历史证据不得定责。 |
| D 产出与审核复盘 | 检查最近一天文本/事实审查标记、失败、无法确认及稳定 ID 抽样的通过项；问题卡明确要求对齐原稿、定稿、提交稿、镜像和审查版本。 | 当前不自动比对所有稿件版本；审核表字段不支持的版本关系保持未知。抽样最多 30 条/类别。 |
| E 规则冲突与执行 | 扫描活动 Prompt 版本、特色模式和发布附加规则，确定性发现同模板正反词句，再异步 AI 复核。 | 关键词扫描只给“可能冲突”，并不证明两条规则适用于同一场景。未接入的结构化金额/时间规则不能声称已覆盖。 |
| F 故障与恢复汇总 | 聚合 X 阶段失败/停止、主任务当前失败及本地队列 last_error，按来源/阶段/错误签名合并，比较任务当前状态估计恢复数量。 | 精确重试序列只对已启用 X 尝试日志可靠；队列和其他业务库目前是当前快照，不能据此重建每次恢复。根因未知时继续标为未知。 |

每日巡检使用北京时间 06:00 后首次机会运行，以日期和策略版本幂等。渠道检查每 5 分钟运行且按五分钟 bucket 幂等。任务运行、完成、失败和留存维护写入 `system_review_runs`；worker 最后心跳和异常写入独立 state。质量问题集中在控制台，不为常规巡检增加 Telegram 消息。

## 模型预算与错误

新增模型巡检每日最多 100 次请求、1,000,000 输入 tokens；请求前原子预留，响应或调用边界失败后按已知实际输入用量结算，未发送请求释放预留。预算不足标记 `budget_paused` 并保留积压，不当作通过。一次调用失败最多自动尝试 3 次；超过后保留失败状态，需新证据或人工触发后再处理。

模型复核在 API 自身 worker 线程中执行，不在写作、发布或控制台同步请求线程内调用。保留上游 request ID、原始响应证据和解析错误。当前路由复用 `search_ai_review_*`，模型可由 `SYSTEM_REVIEW_MODEL` 覆盖；超时可由 `SYSTEM_REVIEW_TIMEOUT_SECONDS` 覆盖。外部 API、抓取和发布不会被巡检重复调用。

## 当前文档级测试例

- `test_channel_checks_follow_enabled_config_and_detect_missing_heartbeat`：显式停用渠道不报中断，启用计划缺心跳可见。
- `test_binance_square_channel_checks_settings_worker_and_enabled_accounts`：检查币安广场总开关、worker 与账号状态，并忽略停用账号。
- `test_channel_failure_requires_three_consecutive_observations`：同一 bucket 幂等，连续不同 bucket 才累积，成功清零。
- `test_system_review_parse_failure_keeps_raw_response_and_settles_tokens`：JSON 解析失败仍保留原始响应、请求 ID、实际用量及引用。
- `test_budget_paused_review_retries_on_next_available_budget`：预算解除后继续队列。
- `test_new_evidence_reopens_review_item_without_erasing_decision_history`：新证据重开问题但保留之前人工决定。
- `test_rule_conflict_checks_only_active_template_versions`：不把未激活 Prompt 旧版本报为当前冲突。

执行完整离线验收：

```bash
tools/dev pytest -q backend/test_system_observability.py
```

巡检线程运行于 `odaily-editor-plugin-api.service`，不是 `pipeline-supervisor` 的替代品。生产启用路径、数据库目录、停用方式见 `控制台-全量信息流.md`。
