# 控制台

## 职责

控制台负责维护人工可配置的数据和复盘视图，不承载 worker 内部运行逻辑。

控制台主体是 Vite 前端。业务表通过认证后的受约束接口访问 Linux 本地 SQLite；文件配置、耗时看板、Gate 行情、Meme速递和系统观测通过各自后端接口访问运行资产。浏览器不直连数据库。AI 审阅建议和人工决定保存在独立的 `data/runtime/ai_review.sqlite`；全量信息流和系统巡检默认共用独立 `data/runtime/system_information.sqlite` 及其压缩证据目录，可用 `ODAILY_SYSTEM_OBSERVABILITY_DIR` 移至持久卷。

## 访问控制

- 控制台与插件共用本地单操作者邮箱密码登录。
- 后端从 SQLite 中读取 bcrypt 密码哈希，签发不透明 Bearer session；前端只保存该 session。
- 当前唯一账号为 `odaily2026@gmail.com`，不提供注册、换号或远程认证回退。
- `tasks` 是多来源共用档案表，控制台白名单用户需要能读取所有来源；前端页面再按模块自行筛选来源，不在 RLS 层限制为 `x`。
- 控制台不开放前端自助注册，账号由部署代码与本地主库初始化。

- `全量信息流`：服务端过滤、中文连续子串搜索、稳定游标分页，覆盖主快讯流水线和已登记的独立业务结果；详情懒加载证据、阶段历史和版本。投影落后、来源未映射和历史信息不足分别展示。完整适配范围见 `控制台-全量信息流.md`。

- `AI查重`：控制台一级标签，允许编辑粘贴一段快讯内容，复用插件现有搜索者查重接口，返回疑似重复的已发布快讯和运行中候选。细节见 `控制台-AI查重.md`。
- `排除词`：按规则组维护整组词表、启用状态、适用路径和适用范围，并提供不持久化的测试文本命中预览。
- `Prompt及规则管理`：包含 `可编辑 Prompt`、`内置规则`、`知名人物`；知名人物名单通过服务器接口读写 Linux 本地 `data/config/known_title_subjects.json`。

- `控制台-Prompt.md`：Prompt 模板、版本、删除、发布/回滚、特色模式开关和特色模式文本。
- `控制台-金十.md`：金十链路总开关、轮询频率、接口配置、最近运行状态和最近入库任务。

- `prompt_template_versions`
- `publisher_settings`
- `publisher_channels`
- `jin10_settings`
- `jin10_seen_items`
- `source_exclusion_rule_groups`
- `pipeline_timing_snapshots`
- `newsflash_roster`
- `newsflash_roster_aliases`
- `newsflash_operation_facts`
- `newsflash_daily_modes`

- `newsflash_reporting_weeks`

控制台不直接推进任务状态，不替代 worker 的锁、重试和失败处理。

其中 `x_capture_accounts` 除抓取频率、启停等账号规则外，还维护 X 写作链路使用的账号级 `写作名`。该字段由自动化 X 主链路与插件 `快讯生成` 共用。

`全量信息流` 从独立查询库读取，先在服务端执行时间、业务、来源、环节、状态、结果、故障类别和关键词过滤，再用 `(时间, item_id)` 稳定游标分页。中文关键词以每记录去重二元组筛选候选，再解压证据验证连续匹配；过短词明确拒绝。列表只读轻摘要，详情才解压证据。初次投影按有界批次推进，并显示更新时间、按实际任务行数统计的 lag 和索引初始化状态。独立业务表目前通过只读增量快照适配；X 主流水线另保存阶段尝试与模型原始返回。未保存的历史阶段、独立业务库中的中间状态或已清理原文不会由流程目录推断补齐。信息流、覆盖和保留细节见 `控制台-全量信息流.md`。

任务展开层通过认证后的 `/console/failure-diagnostics/get?id=...` 懒加载单条诊断，不扫描全部失败任务。该接口以 `tasks.status` 判断失败环节，读取主 SQLite 中来源对应的 `x_task_pipeline` 或 `external_media_alert_pipeline` 的 `last_error`，并按当前 `ODAILY_STORAGE_EPOCH` 关联 `data/runtime/local_pipeline.sqlite` 中的 job 状态、尝试次数、下次重试时间和队列错误。失败任务额外展示统一的故障分类、故障代码、面向值班人员的具体原因、可核对证据、排查建议和脱敏后的原始错误；处理中任务展示任务锁、`local_pipeline` worker 最近心跳以及是否疑似卡住。`exhausted` 只表示队列重试次数耗尽，不作为根因。页面提供“复制故障摘要”，用于向开发者反馈标准化的任务 ID、环节、分类、模型、HTTP 状态、超时、重试和原始错误。

生产写作完成后，信息周期监控同时读取 `writer_output.trace`、Prompt key / version、writer model 和特色模式开关。普通行最多显示非 `plain` 标题策略与“特色已用”两个徽标；展开层显示策略及原因、确定性命中的知名主体、命中规则、特色模式配置 / 实际采用、判断规则版本、Prompt 和模型。原始 trace JSON 放在二级折叠区；旧任务显示“旧任务无标题溯源”，当前任务的无效或不完整溯源显示“溯源不完整”。页面支持按标题策略、特色实际采用和知名主体命中筛选。

`耗时看板` 的前端不直接读取 `tasks`、`x_task_pipeline` 或 `pipeline_timing_snapshots`。`editor-plugin-api-server` 每小时从主 SQLite 读取必要轻量字段计算聚合结果，写入 `data/runtime/pipeline_timing.sqlite`。

`信源管理 / 律动key` 子页通过 `/console/blockbeats-key/get` 和 `/console/blockbeats-key/save` 读写 Linux 本地 `data/config/blockbeats_key.json`；路径可由 `BLOCKBEATS_KEY_CONFIG_PATH` 覆盖，接口复用本地操作者 session。自动申请由收集者-竞品 worker 在额度不足或无 key 时执行，控制台只保留人工替换当前 key 的入口。

`Gate行情播报` 页面通过 `/console/gate-market/get` 只读 Linux 本地 `data/runtime/gate_market.sqlite`，接口鉴权复用本地操作者 session。

`股票行情播报` 页面通过认证的 `GET /console/stock-market/get` 只读 Linux 本地 `data/runtime/stock_market.sqlite`，不提供规则编辑、单合约启停或发布操作；只有该页面处于打开状态时，前端每30秒读取一次 SQLite 快照。

`Meme速递` 页面通过 `/console/meme/get` 只读 OdAIly 的
`data/processed/meme_scanner.sqlite3`，可由 `MEME_SCANNER_DB_PATH` 覆盖；控制台不写该库、不推进 Meme 任务。

`商务快讯` 页面通过认证后的专用接口分页读取 `business_message_inbox`，并更新 `business_telegram_groups` 中的客户名和启停状态。群消息处理结果只由商务 Telegram worker 写入，页面不推进处理状态。接口和字段细节见 `控制台-商务快讯.md`。

`Odaily快讯总览` 不使用通用 `/console/data` 拼接跨表结果，而是通过 `/console/newsflash-operations` 执行受约束的分页搜索、排班保存、人工字段更新、周/月统计、优质快讯评估、贡献快讯周评分与月度聚合和事件查询动作。优质快讯的人工覆盖写入运营事实并保留审计记录，浏览器不接收任意 SQL、表名或字段名。

`系统巡检问题` 由 `editor-plugin-api-server` 内的独立线程异步执行。每 5 分钟读取启用计划与心跳，每日 06:00 后幂等执行覆盖、审核、规则、失败恢复和留存检查；模型分析使用独立每日预算。AI 审阅旧模块保持独立，人工决定写入巡检库并保留决定历史。详见 `控制台-系统巡检.md`。

`AI查重` 页面通过已认证的 `POST /plugin/news-gen/search` 调用搜索者查重能力。请求只提交编辑粘贴的正文，不创建任务、不推进发布状态；结果展示搜索者返回的结论和最多 5 条按相似度排序的候选快讯。

## 配置生效

配置变更的基本要求：

- worker 启动时主动加载当前配置。
- 控制台发布或保存配置后，worker 通过本地配置读取或下一轮轮询看到变化。
- worker 不依赖高频轮询发现配置变化。

不同模块的通知机制见对应控制台子文档。

## 控制台读取策略

- 控制台页面默认按当前页首次进入时加载该页所需数据，不在后台统一预加载所有模块。
- 顶部刷新按钮只刷新当前页。
- 默认不做前端自动轮询；需要高时效的模块须在对应子文档说明刷新频率与原因。
- 这条约束用于控制主 SQLite 读取与接口负载，避免控制台在无人关注时持续刷新。
- `耗时看板` 遵循同一策略：进入页面或点击刷新时只读取本地 API 当前快照，不触发实时重算；快照由后端小时级线程维护。
- `Gate行情播报` 同样只在首次进入或点击刷新时读取当前 SQLite 快照，不在前端自动轮询行情。
- `股票行情播报` 页面打开时每30秒刷新只读 SQLite 快照，离开页面即停止；行情采集由独立 worker 固定每30秒批量请求 Binance。
- `Meme速递` 同样只在首次进入或点击刷新时读取最近 100 条任务，不自动轮询，不触发 GMGN 或 Telegram 查询。
- `商务快讯` 同样只在进入页面、修改筛选或点击刷新时读取，不自动轮询；Telegram 收件和 AI 处理在后台独立运行。
- `热点话题` 和 `热点自动快讯` 只在进入或点击刷新时读取独立 HotTopic SQLite 的当前快照；账号新增和三个订阅开关统一在 X Agent 账号目录维护，不触发 OdAIly 的 X 快讯采集链路。热点自动快讯的只读视图会另外显示事件、官方账号、进展、发布结果和 Prompt 版本；细节见 `控制台-热点话题.md` 与 `控制台-X Agent.md`。
- `快讯及数据总览` 同样只在进入二级标签、切换查询范围或点击顶部刷新时加载数据，不自动轮询；浏览量展示来源当前值。
- `AI查重` 不自动轮询；只有编辑点击“开始查重”时才发起一次搜索请求。

## 本地开发

```powershell
cd frontend
npm install
npm run dev
```

前端需要：

```text
VITE_CONSOLE_API_BASE_URL=
```

生产环境的 `VITE_CONSOLE_API_BASE_URL` 应指向发布者控制接口的 HTTPS 地址，例如：

```text
https://console-api.example.com
```

OdAIly 生产环境使用：

```text
VITE_CONSOLE_API_BASE_URL=https://api.odaily.uk
```

前端由 Vercel 从 GitHub 的 `frontend` 目录构建；后端由 Odaily 官方服务器的 `editor-plugin-api-server` 提供。前端切换 API 地址后必须重新构建部署，旧共享服务器不再作为控制台后端。

首次启动轻服务会在主 SQLite 初始化固定本地操作者。可用以下命令核对当前账号：

```powershell
python backend\src\main.py console-list-admins
```

## 巨鲸控制台

- 控制台新增一级标签 `巨鲸`，页面内包含 `链上` 与 `Hyperliquid`。
- `链上` 负责维护 EVM 地址和自定义标签，支持启用、停用、删除，并展示 worker 写回的链状态与最近播报。
- `Hyperliquid` 负责维护 Hyperliquid 地址和自定义标签，支持启用、停用、删除，并展示最近轮询状态与播报历史。
- `Hyperliquid` 还提供三个人工可修改参数：`单次门槛`、`聚合门槛`、`聚合时长`。
- 新增控制台数据表：`whale_watch_addresses`、`whale_watch_chain_states`、`whale_watch_activities`、`whale_watch_hyperliquid_settings`、`whale_watch_hyperliquid_addresses`、`whale_watch_hyperliquid_states`、`whale_watch_hyperliquid_activities`。
- 前端只写地址配置和 Hyperliquid 阈值配置；链选择、轮询、活动识别、滚动聚合窗口计算和 Telegram 发送分别由 `whale-watch-worker` 与 `whale-watch-hyperliquid-worker` 负责。
- 巨鲸地址配置会记录 `created_by`、`updated_by` 作为审计字段；链上地址表在数据库侧额外限制总量上限 `500`，超过后会拒绝新地址插入，避免异常批量写入继续扩大。
- 模块细节见 `docs/OdAIly代码与整体设计/巨鲸.md`。
