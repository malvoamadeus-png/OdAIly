# 控制台

## 职责

控制台负责维护人工可配置的数据和复盘视图，不承载 worker 内部运行逻辑。

控制台主体是 Vite 前端。全部业务表通过 HTTPS `/console/data` 白名单接口访问 Linux 主 SQLite；文件配置、耗时看板、Gate 行情和 Meme速递通过各自后端接口访问本地运行资产。浏览器不直连数据库。

## 访问控制

- 控制台与插件共用本地单操作者邮箱密码登录。
- 后端从 SQLite 中读取 bcrypt 密码哈希，签发不透明 Bearer session；前端只保存该 session。
- 当前唯一账号为 `odaily2026@gmail.com`，不提供注册、换号或远程认证回退。
- `tasks` 是多来源共用档案表，控制台白名单用户需要能读取所有来源；前端页面再按模块自行筛选来源，不在 RLS 层限制为 `x`。
- 控制台不开放前端自助注册，账号由部署代码与本地主库初始化。

## 数据边界

控制台可以写入配置类和复盘类表：

- `x_capture_settings`
- `x_capture_accounts`
- `tasks`
- `x_task_pipeline`
- `non_mainstream_media_settings`
- `non_mainstream_media_sources`
- `prompt_templates`
- `prompt_template_versions`
- `publisher_settings`
- `publisher_channels`
- `jin10_settings`
- `jin10_seen_items`
- `source_exclusion_rule_groups`
- `newsflash_event_favorites`
- `newsflash_event_notes`
- `newsflash_item_notes`
- `pipeline_timing_snapshots`

控制台不直接推进任务状态，不替代 worker 的锁、重试和失败处理。

其中 `x_capture_accounts` 除抓取频率、启停等账号规则外，还维护 X 写作链路使用的账号级 `写作名`。该字段由自动化 X 主链路与插件 `快讯生成` 共用。

`信息周期监控` 只读 `tasks` 与 `x_task_pipeline`。它以全部受支持来源作为一个查询范围，按 `created_at` 倒序分页读取，每页固定 50 条，并额外读取一条判断是否存在下一页；不会再按来源分别拉取大量任务，也不扫描全表。来源、关键词、标题策略、特色模式和知名主体筛选均作用于当前页。展示和搜索优先使用流水线最终标题 / 正文，缺失时回退到入库原始标题 / 正文。发布者说明优先来自 `publisher_output.reason`，这是发布者模型或保守挂后台分支写给编辑看的业务理由。

生产写作完成后，信息周期监控同时读取 `writer_output.trace`、Prompt key / version、writer model 和特色模式开关。普通行最多显示非 `plain` 标题策略与“特色已用”两个徽标；展开层显示策略及原因、确定性命中的知名主体、命中规则、特色模式配置 / 实际采用、判断规则版本、Prompt 和模型。原始 trace JSON 放在二级折叠区，历史任务显示“旧任务无标题溯源”。页面支持按标题策略、特色实际采用和知名主体命中筛选。

`耗时看板` 的前端不直接读取 `tasks`、`x_task_pipeline` 或 `pipeline_timing_snapshots`。`editor-plugin-api-server` 每小时从主 SQLite 读取必要轻量字段计算聚合结果，写入 `data/runtime/pipeline_timing.sqlite`。

`信源管理 / 律动key` 子页通过 `/console/blockbeats-key/get` 和 `/console/blockbeats-key/save` 读写 Linux 本地 `data/config/blockbeats_key.json`；路径可由 `BLOCKBEATS_KEY_CONFIG_PATH` 覆盖，接口复用本地操作者 session。自动申请由收集者-竞品 worker 在额度不足或无 key 时执行，控制台只保留人工替换当前 key 的入口。

`Gate行情播报` 页面通过 `/console/gate-market/get` 只读 Linux 本地 `data/runtime/gate_market.sqlite`，接口鉴权复用本地操作者 session。

`Meme速递` 页面通过 `/console/meme/get` 只读 OdAIly 的
`data/processed/meme_scanner.sqlite3`，可由 `MEME_SCANNER_DB_PATH` 覆盖；控制台不写该库、不推进 Meme 任务。

## 配置生效

配置变更的基本要求：

- worker 启动时主动加载当前配置。
- 控制台发布或保存配置后，worker 通过本地配置读取或下一轮轮询看到变化。
- worker 不依赖高频轮询发现配置变化。

不同模块的通知机制见对应控制台子文档。

## 控制台读取策略

- 控制台页面默认按当前页首次进入时加载该页所需数据，不在后台统一预加载所有模块。
- 顶部刷新按钮只刷新当前页。
- 默认不做前端自动轮询；如果后续某个模块需要更高时效，应在对应子文档单独说明刷新频率与原因。
- 这条约束用于控制主 SQLite 读取与接口负载，避免控制台在无人关注时持续刷新。
- `耗时看板` 遵循同一策略：进入页面或点击刷新时只读取本地 API 当前快照，不触发实时重算；快照由后端小时级线程维护。
- `Gate行情播报` 同样只在首次进入或点击刷新时读取当前 SQLite 快照，不在前端自动轮询行情。
- `Meme速递` 同样只在首次进入或点击刷新时读取最近 100 条任务，不自动轮询，不触发 GMGN 或 Telegram 查询。

## 本地开发

```powershell
cd frontend
npm install
npm run dev
```

前端需要：

```text
VITE_CONSOLE_API_BASE_URL=
```

生产环境的 `VITE_CONSOLE_API_BASE_URL` 应指向发布者控制接口的 HTTPS 地址，例如：

```text
https://console-api.example.com
```

首次启动轻服务会在主 SQLite 初始化固定本地操作者。可用以下命令核对当前账号：

```powershell
python backend\src\main.py console-list-admins
```

## 巨鲸控制台

- 控制台新增一级标签 `巨鲸`，页面内包含 `链上` 与 `Hyperliquid`。
- `链上` 负责维护 EVM 地址和自定义标签，支持启用、停用、删除，并展示 worker 写回的链状态与最近播报。
- `Hyperliquid` 负责维护 Hyperliquid 地址和自定义标签，支持启用、停用、删除，并展示最近轮询状态与播报历史。
- `Hyperliquid` 还提供三个人工可修改参数：`单次门槛`、`聚合门槛`、`聚合时长`。
- 新增控制台数据表：`whale_watch_addresses`、`whale_watch_chain_states`、`whale_watch_activities`、`whale_watch_hyperliquid_settings`、`whale_watch_hyperliquid_addresses`、`whale_watch_hyperliquid_states`、`whale_watch_hyperliquid_activities`。
- 前端只写地址配置和 Hyperliquid 阈值配置；链选择、轮询、活动识别、滚动聚合窗口计算和 Telegram 发送分别由 `whale-watch-worker` 与 `whale-watch-hyperliquid-worker` 负责。
- 巨鲸地址配置会记录 `created_by`、`updated_by` 作为审计字段；链上地址表在数据库侧额外限制总量上限 `500`，超过后会拒绝新地址插入，避免异常批量写入继续扩大。
- 模块细节见 `docs/OdAIly代码与整体设计/巨鲸.md`。
# 控制台权限检查补充

- 控制台登录后会通过 `/console/data` 读取 `console_admins` 验证当前本地账号是否具有控制台权限。
- `console_admins` 只用于权限展示与白名单确认；管理员账号仍由本地 SQLite 认证与部署初始化维护，不提供前端自助注册。
