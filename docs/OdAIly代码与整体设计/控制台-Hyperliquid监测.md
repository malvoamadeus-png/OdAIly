# 控制台-Hyperliquid监测

## 页面与读取

新增一级标签 `Hyperliquid监测`，独立于旧 `巨鲸` 手工地址监控。页面含 `事件与快讯 / 地址监测 / 规则与运行`，通过认证 `POST /console/hyperliquid-news/get` 读取主 SQLite，不从浏览器触发采集、生成或发布。

事件按时间倒序分页，每页 30 条。读取结构化事件与 `hl_news_dispatch` 对应 `tasks / x_task_pipeline`，展示触发类型、地址、完整合约标识、前后仓位、市值来源及占比、OI、浮盈峰值及时间、当前浮盈与回吐、单资产历史范围/完整交易轮/胜率、官方周期 PnL、动作金额、清算证据。缺失数据写“未取得”，不能变成零。原始证据放折叠区。

每条事件展示任务 ID、流程状态、草稿和最终文本、编写模型、Prompt 版本、写作/定稿/挂后台时间、提交返回与错误。地址页展示最近 100 个地址的发现来源、属性查询依据、仓位与历史。规则页展示工程默认值及最近采集统计，实际触发门槛以该事件保存证据为准。使用刷新按钮更新数据，不进行高频轮询。

## 流程

硬规则命中 → 行为重复控制 → 编写者1（独立 `hyperliquid_writer`）→ 编写者2 → 固定数据组装 → 挂后台。

不运行判断者或新闻价值筛选，不使用搜索者文本相似度。规则改变通过底层规则配置/代码维护；本页不引入人工审稿门槛。事件已经硬规则命中，不再用 AI 决定选题可不可以写。

事件与行为重复控制落在 `hl_news_dispatch`；相同事件不会创建第二个 task，相同地址/合约/触发档位/成交键/仓位轮次事实不会重复投递。真正新增行为或新触发档位可再次发。首次已有大仓作为当前状态稿，不写刚开仓。

## 发稿限制

唯一来源 `hyperliquid_news`，直接以 `deduped` 入 tasks，共享写作队列只运行 `write / format_publish / publish`。编写者2复用字符规范化，在来源分支固定正文开头 `据Odaily监测，`，程序拼接有来源与口径的数据尾部。官方 PnL 与单资产已实现盈亏分别展示，不混用；胜率只提供单资产。

原文 `sourceUrl` 固定为 `https://hyperbot.network/trader/{目标地址}`。多地址事件正文尾部列全部地址，主链接使用候选 addresses 的首个地址。

发布阶段在加载任何自动发布配置或调用发布者 AI 前强制挂后台，`isPublish=false / isPush=false`。没有正式自动采集调度；CLI 一次采集和限量投递仅用于用户已授权的官方服务器测试。测试通过、用户确认前不启用常驻自动投递。
