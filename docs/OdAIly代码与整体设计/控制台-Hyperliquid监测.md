# 控制台-Hyperliquid监测

## 页面与读取

新增一级标签 `Hyperliquid监测`，独立于旧 `巨鲸` 手工地址监控。页面含 `方向与场景 / 地址监测 / 规则与运行`，通过认证 `POST /console/hyperliquid-news/get` 读取主 SQLite，不从浏览器触发采集、生成或发布。

“正常监测”只列出十个正式方向：巨额单资产浮盈/浮亏、单资产高胜率地址操作、账户高盈利地址操作、账户总亏损高地址操作、大仓反手、巨亏后加仓、大额主动平仓盈亏兑现、单资产高盈利地址操作、浮盈回吐/双向盈亏转换、接近清算/实际清算。“上线前测试案例”列出尚未完成研究验收的方向。实验案例标明实际门槛，不进入正常监测、正式投递或基线。两组方向分别计数和筛选，空方向仍保留空状态。

左侧方向及全量记录数，右侧先展示场景说明、当前默认门槛，再显示该方向的记录列表。选中记录先展示变化摘要、前后持仓与关键证据，后展示处理流程及快讯。静态旧试稿明确标为“监测基线”。同一事件可出现在多个命中方向，但仍关联同一任务；记录数包含基线，不能当成已发快讯数。样式复用后台热点/自动快讯的分段导航、绿色选中态、指标卡片与主从布局，窄屏改为上下布局，完整 JSON 放入折叠区。

接口请求可传 `view=scenarios|addresses|rules`（默认 scenarios），仅地址页返回最近 100 个地址的完整来源/仓位/历史，场景页返回场景事件，规则页不加载事件或地址详情；未知 view 拒绝。接口请求可传 `scenario`（固定方向 key）；省略时按数据集读取对应方向。返回 `scenarios`（固定 key/name/description/rule_keys/count/prompt_key/prompt_name）及 `scenario`。未知 key 拒绝。数量从全量候选计算，事件先按方向筛选再按时间倒序分页，每页 30 条。未初始化也返回所选数据集的完整方向列表，读取不创建数据库。

读取结构化事件与 `hl_news_dispatch` 对应 `tasks / x_task_pipeline`，展示触发类型、地址、完整合约标识、前后仓位、市值来源及占比、OI、浮盈峰值及时间、当前浮盈与回吐、单资产历史范围/完整交易轮/胜率、官方周期 PnL、动作金额、清算证据。缺失数据写“未取得”，不能变成零。原始证据放折叠区。

每条事件展示任务 ID、流程状态、搜索完成时间、搜索者重复结论/命中对象/完整查重结果、草稿和最终文本、编写模型、Prompt 版本（关联版本的 version_number，非全库记录 ID）、写作/定稿/挂后台时间、提交返回与错误。地址页展示最近 100 个地址的发现来源、属性查询依据、仓位与历史。规则页展示工程默认值及最近采集统计，实际触发门槛以该事件保存证据为准。使用刷新按钮更新数据，不进行高频轮询。

## 流程

变化证据与硬规则命中 → 内部行为防重 → 搜索者跨来源查重 → 编写者1（按命中场景选择 Hyperliquid Prompt）→ 编写者2 → 固定数据组装 → 挂后台。单资产高盈利与高胜率共用单资产表现 Prompt；账户盈利与总亏损共用账户结果 Prompt；其余持仓变化、浮盈亏变化、反手、回吐、亏损加仓、平仓兑现、清算、多空分歧和新观察地址分别使用对应 Prompt。一个事件命中多个场景时按确定的场景优先级选择一个 Prompt。

不运行判断者或新闻价值筛选，保留搜索者的向量召回与事实重复复核，Lookonchain 等已收集内容可参与查重。规则改变通过底层规则配置/代码维护；本页不引入人工审稿门槛。事件已经硬规则命中，不再用 AI 决定选题可不可以写。

事件与行为重复控制落在 `hl_news_dispatch`；相同事件不会创建第二个 task，相同地址/合约/触发档位/成交键/仓位轮次事实不会重复投递。真正新增行为或新触发档位可再次发。首次已有大仓/盈亏只建监测基线，不形成状态新闻。大仓需要重要数量或成交变化，盈亏需要可核对的前后变化；多空对决可作为静态例外。去重不能代替变化性准入。页面明确标记旧静态试稿不符合当前新闻准入，保留原稿与历史文本预览。

## 发稿限制

唯一来源 `hyperliquid_news`，以 `judged` 入 tasks，共享链路运行 `search / write / format_publish / publish`。编写者2复用字符规范化，在来源分支固定正文开头 `据Odaily监测，`；所有方向均尝试补充每个相关地址在观察/操作时点前可取得的官方 `perpAllTime` 合约账户总盈亏及样本时间。多地址事件按地址分别补充。不得用成交窗口的自算账户盈亏代替总盈亏；样本缺失时显示“总盈亏：未取得”。单资产高胜率的重要操作再补交易轮数、胜率和统计日期。胜率只提供单资产。

原文 `sourceUrl` 固定为 `https://hyperbot.network/trader/{目标地址}`。多地址事件正文尾部列全部地址，主链接使用候选 addresses 的首个地址。

发布阶段在加载任何自动发布配置或调用发布者 AI 前强制挂后台，`isPublish=false / isPush=false`。正式常驻采集和自动后台投递启用上述十个方向；普通方向使用独立采集状态，新增三类要求各自上线后的成功前序快照，避免重放部署前行为。投递限制同时覆盖手工 CLI。

页面支持 `?view=hyperliquid_news` 直达；首轮试稿任务为 827705、827706、827707，均成功挂后台，原稿保留供用户审阅。支持同一事件的修订预览：显示新标题正文、实际 Prompt 版本、模型与生成时间，并标明沿用原观察时点事实且未重新挂后台；原稿与提交结果放独立折叠区，不把预览当已提交文本。

## 上线前测试案例

场景页增加“正常监测 / 上线前测试案例”切换，接口 `dataset=live|test` 默认 live。测试案例独立写入 `hl_news_test_cases`，不进入候选、tasks、投递或正式地址基线。执行 `hyperliquid-news prune-tested-cases` 删除只属于十个已验收方向的案例和预览；同时命中尚未研究方向的案例保留，并仅显示未研究方向标签。历史事实标注发生时间、重建来源与金额折算口径；缺少历史浮盈亏、清算价时不补造。

`hyperliquid-news mine-test-cases --address-limit 40 --per-side 12` 顺序获取官方多周期盈亏榜地址的近期保留成交样本，按成交前仓位连续性与一小时动作窗口识别真实开平仓、加减仓、反手、兑现、实际清算，并使用动作发生前的成交计算历史属性。可用 `--coins ZEC BTC` 追加指定合约的 `recentTrades` 地址种子；这只是有限近期成交采样，不是该资产当前持仓前 N，也不保证覆盖全市场。Hyperliquid 官方公开接口没有全网按单一资产当前持仓额排序的账户榜单；只能对已发现地址逐一查询 `clearinghouseState`，或用近期成交地址扩展样本。请求及进度缓存在独立 `test_fills:*` / `test_mining_progress` metadata，可限量重复运行。数量断裂、同时间顺序歧义不拼接成完整交易轮。窗口金额按末笔成交价折算，不能当作历史标记价快照。新观察时间不能凭历史建仓时间补造。

历史阈值实验参数：`--threshold-profile low-10|low-20` 将 BTC/ETH 单资产近30天净盈利门槛设为 300 万美元、其他资产设为 100 万美元；浮盈亏变化门槛设为 BTC/ETH 30 万美元、其他资产 10 万美元；回吐比例设为 15%，清算距离分别设为 10% / 20%。原重要操作金额门槛不变（单资产盈利操作 200 万美元，普通重要操作 300 万美元）。已验收三类采用 low-20 对应门槛正式运行；其余七类不降低门槛。

`hyperliquid-news preview-test-cases --limit 30` 为测试案例生成文本预览，每个测试方向最多 5 篇；同一地址资产在一个方向只保留一篇，按证据强度选择。回放只建立和筛选案例，不会自动生成正文，因此需单独执行预览命令。无合格案例时保持空方向，不以其它方向替代。每条预览按事件命中场景读取对应活动 Prompt；添加 `--repository-template` 时读取当前仓库的对应 Prompt 文件，不切换数据库活动 Prompt；页面标记“仓库模板（未激活）”。结果存入 `editorial_preview:{test事件key}`，页面展示标题正文、模型和 Prompt 来源，并提供直达该 Prompt 编辑页的入口。不会创建 task、不运行正式查重或编写者2、不挂外部后台；它是文稿预览，不代表完整发稿链路已经验收。

`hyperliquid-news replay-cached-test-cases --reset` 仅重建测试数据集：删除旧 `hl_news_test_cases` 及其关联的 `editorial_preview:*`，并清理已知测试事件键的孤立预览；保留正式事件预览与 `test_fills:*` 成交缓存。重放后按产品测试场景保留案例；`prune-tested-cases` 会从测试数据集中剔除十个正式方向。报告返回未研究方向的案例数和缺失方向。回放不会生成正文，随后执行 `preview-test-cases` 才会写入文本预览。

测试扫描同时从已收集 Hyperliquid 报道中提取完整地址作为发现种子（最多读取最近 1,500 条相关任务），再通过公共成交验证操作。报道只用于找地址，不能代替触发证据、也不能赋予报道声称的胜率或盈利属性。

价格重建测试证据标识 `execution_price_cost_reconstruction`，保留实际成交参考价、成本和重建阶段。浮盈峰值仅是回放取得的价格时点峰值，不是全部盘中最高值；页面完整证据可核查。`hyperliquid-news replay-cached-test-cases` 可重放缓存，仍只写测试数据集。

可传 `mine-test-cases --addresses 0x… 0x… --address-limit 40` 针对剩余场景验证已知真实地址，不查询榜单。测试工具排除 `#` 结果代币及零价格/无效数量的结算记录，只分析合约成交，避免非合约记录中断整地址回放。

“新观察地址快速建仓”测试可在真实历史首次空仓成交时点虚拟启动监测，后续真实成交仍须在规定窗口达到原金额门槛。此类样本明确标注 `historical_monitor_start_simulation`、虚拟启动时间、非钱包创建时间、非实际发现时间，页面专门说明；这是启动状态测试，不能算成我们已在生产实时发现过该新地址。测试回放只读取独立 `test_fills:*` 缓存，不从正式候选或任务复制内容。

“巨亏后加仓”测试可在已核对成本的连续路径中合并一小时内的真实加仓成交，仍用原重要操作金额门槛；旧仓浮亏取该动作窗口起点的实际成交价格参考。不得把多个不连续路径拼成一次加仓。

`hyperliquid-news enrich-account-test-cases --limit 20` 查询真实操作地址的官方 portfolio 历史曲线，只选操作开始前已存在、达到 2,000 万美元门槛的 perp 周期 PnL 样本补充账户高盈利属性。它是官方周期收益（含浮盈亏变化），不能冒充已实现盈利；保留实际历史样本时间和属性截止时间，无样本则不补，不使用操作后的榜单属性反套历史行为。

测试数据集顶部显示测试案例总数及已有案例方向数，不混用正式投递数。测试流程明确显示规则核验、编辑预览和“测试不投递”，不把未运行的正式搜索/编写者2/发布阶段展示为完成。官方收益统一标作“官方周期 PnL”，无榜单排名的 portfolio 数据不显示排名，显示收益样本时间。


测试案例的单资产高胜率门槛为至少 5 个完整交易轮、胜率至少 70%。历史补查通过时间分页取得可用成交；同一事件证据更新时旧编辑预览失效。高胜率尾部保留资产轮数、胜率和样本日期；账户总盈亏统一取操作时点前最近的官方 `perpAllTime` 样本，不使用成交窗口重算值。

单资产高胜率方向卡片展示“高胜率地址操作金额”门槛 100 万美元（`win_rate_action`）。单资产高盈利方向展示 BTC / ETH 盈利线 300 万美元、其他资产 100 万美元，以及操作金额 200 万美元；其余方向的“重要操作金额”仍为 300 万美元。

## 加载性能与旧试稿清理（2026-10-14）

场景页不再随每次读取传输未打开的地址历史；地址监测按标签延迟读取。前端合并相同登录会话、场景、分页、数据集和标签的在途请求，响应完成后立即移除，不缓存业务数据；手动刷新仍读取最新状态。Hyperliquid 读取接口支持 gzip，客户端允许时压缩超过 4KB 的 JSON，Vary: Accept-Encoding；跨域预检允许浏览器缓存 600 秒，不缓存鉴权结果或正式业务响应。

经用户要求，正常监测中原巨大持仓 2 个条目、巨额浮盈亏 2 个条目对应的 3 条唯一旧测试事件已删除（1 条同时命中两个方向）。一并删除其投递映射和编辑预览，主任务与流水线审计记录保留，独立测试案例不删除。恢复备份位于服务器 repo 之外 `/var/backups/odaily/`。此操作不删除其他方向记录，也不影响正式 account_profit 监测池、基线或成交去重。

## 地址备注与插件提醒（2026-10-14）

地址页采用紧凑行，展示地址、最近检查时间、备注输入与保存按钮；证据默认折叠。认证 POST `/console/hyperliquid-news/address-note/save` 接受 address/note，只允许已发现地址，备注不超过 80 字、无换行或括号，空值清除；保存 `address_note:{address}` metadata，包含编辑者与时间。地址页按需返回 note。备注为人工维护信息，不作为自动确认机构身份的证据。

账户高盈利正文首次地址描述后确定性插入中文括号备注，例如“某地址合约账户（Wintermute做市地址）累计收益……”，标题不添加备注；写稿及定稿分别读取当前备注，备注不作为模型指令。保存备注用于后续稿件，不自动重新向外部挂稿接口提交历史稿件。

Hyperliquid 成稿复用插件 `newsflash` 提醒项与“挂后台新快讯”声音设置，唯一键仍为 newsflash:task_id，不重复创建第二个提醒；来源徽标显示 Hyperliquid监测，“进入后台”链接直达 Hyperliquid监测及对应 event_key。原始地址链接仍保存在 source_url。声音是否播放沿用用户插件声音开关、新鲜度与防重设置。

## 地址搜索与拉黑（2026-10-14）

地址页支持地址/备注不区分大小写的子串搜索，以及全部、未拉黑、已拉黑筛选。服务端先搜索整个地址池再返回最多 100 条，前端输入防抖 300ms；请求合并键包括搜索词与状态。查询参数为 address_query/address_status。

认证 POST `/console/hyperliquid-news/address-block/save` 接收 address/blocked（布尔），仅针对已发现地址；保存 address_block:{address} 元数据及操作者、时间。拉黑移出账户轮询池，所有发现入口拒绝重新收录，普通监测及多地址事件也排除该地址，候选持久化、派发、任务各阶段和挂后台/插件提醒前复核。未完成任务置 discarded，历史已完成稿件保留。已开始的外部请求不能撤回。

解除拉黑后允许重新发现和建新基线，不补播拉黑期间操作，也不恢复已停止任务或此前候选。元数据保留 last_blocked_ms，阻止旧事件被重新派发；已拉黑列表仍可搜索和编辑备注。
