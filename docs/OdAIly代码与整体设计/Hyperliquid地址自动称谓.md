# Hyperliquid 地址自动称谓

## 产品规则

地址称谓服务于读者记忆，同一地址优先延续仍成立的名字。命名突出一个最有辨识度、证据充足的特长，不要求全面总结交易能力，也不要求附带其他资产的亏损。例如 BTC 盈利突出时可以用“BTC爆赚交易员”，不使用“偏科”等评价。

稳定特长优先，允许“大多头／大空头”等持仓状态称谓。状态称谓不代表交易员永久看多或看空，也不证明其没有其他亮点。反手或清仓使相应状态名失效，监测发现后立即停用并重新排队命名；普通增减仓不必改名。重命名期间新闻使用普通地址主体，不能继续沿用已失效方向。

每个名字包含真实地址前缀，如“ETH大空头0xa7”“原油大多头0x0c”。底层按完整地址识别，合约证据保留完整市场命名空间；称谓可以简写“原油”，统计不能混合不同原油合约。没有覆盖全市场的排名证据时不能使用“最大”“第一”等称谓。

## 覆盖与人工保护

覆盖全部已发现、未拉黑且未人工锁定的地址，不以是否发过新闻、是否进入账户高盈利池作为命名资格。首次上线逐批处理存量地址，后续新地址自动进入待检查范围。每个地址成功检查后七天再次检查，失败按退避计划重试。

现有人工备注在升级时保留并锁定。用户在地址库保存备注后，无论改成文字还是清空，都永久转为人工维护；AI不能覆盖。模型请求期间如果发生人工修改，返回的结果也不能写回。人工备注不作为机构身份认证，也不作为模型指令。

## 证据与维度

程序整理证据和统计，Luna选择最突出的维度并拟名。程序不根据一个固定阈值直接套名称，也不允许模型补造数据。候选维度包括：

- 单资产净交易盈亏、完整交易轮与胜率，逐资产保留实际统计时段和覆盖缺口。
- 当前持仓方向、规模、集中度与浮盈亏，保留观察时间和完整合约标识。
- 多空交易偏好、交易轮持续时间等已有历史能够支持的风格证据。
- 官方账户周期收益，独立于单资产交易统计，不混算贡献率或用成交收益替代官方收益。
- 近期事件、旧称谓及其依据，优先保留仍成立的亮点。

可取得、暂未取得、样本不足的维度均需在检查记录中说明。胜率以完整交易轮统计，不以成交笔数代替。观察窗口内的高盈利不能直接推成终身稳定能力；近期证据使用必要的时间限定。“顶级”“超高胜率”“爆赚”等表达须有相应强度的事实支持。

## 调度与展示边界

命名由独立worker执行，不阻塞行情监测、事件准入、查重或新闻写作，也不因命名新增新闻。优先复用独立Hyperliquid SQLite中的状态、历史与事件，不建立额外的无约束官方API扫描。

地址库备注显示当前称谓和维护状态。每个地址的命名详情默认收起，展开时才读取完整分析，展示检查维度、数据覆盖、最终选用维度、选择理由、模型、检查时间及下次检查时间。地址列表不携带完整历史，保持紧凑。

写稿与定稿读取最新有效备注。自动称谓用于新闻地址主体，失效称谓不得使用；人工备注按人工维护语义处理，不当作模型提示词。历史已完成稿件不因改名自动重发。

## 实现与运行

实现位于 `backend/packages/hyperliquid_news/naming.py`，独立表 `hl_news_address_names` 位于Hyperliquid SQLite。记录当前名、类型、依赖合约和方向、人工锁、证据与维度快照、模型、检查和到期时间、在途领取及错误。自动名与原有 `address_note:{address}` 元数据在同一事务更新，注明自动来源，兼容地址备注搜索。人工编辑同一事务设置永久锁并取消在途领取；升级时将旧人工备注保留为锁定记录。

独立命令：

```bash
.venv/bin/python backend/src/main.py hyperliquid-news run-naming --batch-size 4 --interval-seconds 30
.venv/bin/python backend/src/main.py hyperliquid-news run-naming --batch-size 4 --once
```

每批有界领取，最多四个模型请求并发；有待处理地址时连续处理各批，空队列每30秒检查。模型请求在SQLite事务外执行，提交前复核领取令牌、人工锁、拉黑和持仓事实。失败保留错误并延迟一小时重试；中途退出的领取可在租约超时后恢复。成功记录下次检查为七天后。模型固定为 `gpt-6-luna`，使用现有 `load_x_processing_settings()` 的LLM凭证、接口样式、超时和重试配置，不另读历史数据库配置。

常驻服务模板 `deploy/odaily-hyperliquid-naming.service`，由官方服务器systemd运行，使用生产 `.env` 与独立Hyperliquid库；不在本地启动产品worker。GitHub提交推送后由官方服务器fast-forward同步代码，再安装服务模板并启动。前端由Vercel随GitHub提交部署。

认证 `POST /console/hyperliquid-news/address-naming-details` 接受 `address`，返回保存的检查维度快照、选用维度和证据、理由、模型、检查与下次检查时间、失败信息。详情读取不发起模型请求，也不执行命名。地址库主接口只携带当前名字、人工锁、状态和时间，不附带完整分析。

命名输入最多保留最近八条事件的紧凑操作摘要，并分别列出单资产净交易盈亏、完整轮胜率、一天内最新持仓、官方账户周期PnL和缺失维度。保存证据快照与Prompt版本，复核时提供旧名及理由。没有可靠历史时长或全市场排名时明确标为缺失，不冒充已完成计算。

监测事务提交新持仓时校验状态名的完整合约和方向，失效时清除自动备注并使该地址立即到期。写稿和定稿再核对事件的仓位事实，防止旧事件套用当前相反方向。所有保护只约束自动称谓，人工维护内容不由程序重命名。
