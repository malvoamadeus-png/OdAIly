# 美国宏观数据快讯

## 范围

`macro-newsflash` 是独立常驻 worker，不创建 `tasks`，不进入判断者、搜索者、编写者1或发布者状态机。全部受追踪的美国宏观指标统一在日历排程窗口内以金十中文快讯为准，不再轮询 BLS API、FRED 镜像或美联储声明 RSS。

常规指标标题包含期别、指标名、实际值、前值和预期值（有预期时附加）；FOMC 利率决议在匹配目标区间声明时输出维持/上调/下调及目标区间，或在仅匹配到金十利率决定（上限）快讯时输出实际、前值和预期。正文使用“据Odaily监测，美国……”句式，再由编写者2的 `format_brief` 做最终格式整理（格式器在正文前补 `Odaily星球日报讯 `）。Push Data API 必须显式收到 `isPublish=false`、`isPush=false`。

## 指标与口径

| 指标 | 金十匹配范围与说明 |
| --- | --- |
| 当周初请失业金人数 | 匹配“初请失业金人数”，排除“四周均值”“续请”；前值支持“修正为”解析。 |
| PCE 物价指数年率 | 匹配“PCE/个人消费支出……年率/同比”，排除“核心 PCE”。 |
| 季调后非农就业人口 | 匹配“非农就业人口/人数”，排除“ADP”“小非农”“私营”“制造业”“政府”。 |
| 失业率 | 匹配美国失业率，排除“U6”“平均”“初请”“续请”“就业人数”。 |
| CPI 系列 | 同一 CPI 排程内分别匹配并各自成稿：`未季调CPI年率`、`未季调CPI月率`、`季调后CPI月率`、`未季调核心CPI年率`、`季调后核心CPI月率`。 |
| 零售销售月率 | 匹配“零售销售月率/环比”，排除“核心”“除……”“对照组”“年率”。 |
| 利率决议 | 优先匹配美联储联邦基金利率目标区间与维持/上调/下调动作，回退匹配“美联储利率决定(上限)”。 |

## 发现发布时间与休眠调度

worker 只在平时以轻量日历确认排程时间，并在临近发布时才进入高频金十追踪：

- **日历排程同步**：默认每 `15` 分钟（`MACRO_NEWSFLASH_QUIET_POLL_INTERVAL_SECONDS=900`）查询一次 **TradingView 结构化经济日历**（覆盖非农、失业率、CPI、零售销售、初请、PCE、FOMC）、**BEA 官方发布日历**（PCE）及**美联储 FOMC 官方日历**（解析 `div.panel` / `div.fomc-meeting` 结构，兼容旧表格），并用 DOL 周四 08:30 美东时间规律作为初请兜底估算（周四遇主要美国假日提前至周三，标明 `is_estimate=true`）。已公布排程优先于规律估算，官方页面优先于 TradingView。
- **静默休眠**：处于追踪窗口之外时，worker **不请求金十接口、不请求任何官方数据序列、不执行工作日固定时段盲轮询**，直接睡眠至 `min(下次日历确认时间, 下一个排程前10秒)`。
- **10 秒～60 秒追踪窗口**：任意排程进入 `[排程前10秒, 排程后60秒]` 且仍有未生成的目标指标时，worker 进入窗口模式，以约 `1` 秒一轮（`MACRO_NEWSFLASH_RELEASE_POLL_INTERVAL_SECONDS=1`、HTTP 超时默认 `3` 秒）请求金十 `flash_newest.js`；期间暂停非紧急日历刷新，避免阻塞窗口轮询。
- **发完即停**：只匹配含中文且发布时间落在 `[排程前10秒, 排程后60秒]` 内的金十快讯；一旦某排程的全部目标指标都匹配入队，或超过排程后 `60` 秒，该排程立刻退出活跃列表，worker 立即回到静默休眠（仅每 15 分钟做一次轻量日历确认）。

## 去重与投递

- 生产数据存储在 PostgreSQL `macro_newsflash` schema，不属于主任务库；显式 SQLite 兼容模式使用 `data/runtime/macro_newsflash.sqlite`。
- `macro_metric_state` 保存每项指标最后观察的统计期、来源和原始快照。
- `macro_release_schedule` 保存 BEA、美联储、TradingView 补充排程及初请规律估算。
- `macro_newsflash_events` 保存标题、正文、实际值、前值、预期值原始快照和投递状态；单指标排程按 `jin10:<release_id>` 幂等，多指标排程（如非农+失业率、CPI 系列）按 `jin10:<release_id>:<metric_id>` 幂等。
- 状态 `pending` 表示等待投递，`publishing` 表示 API 调用已开始，`published` 表示成功，`uncertain` 表示调用失败或进程中断、结果无法确认。`uncertain` 不会自动重试，需先检查后台和信息流，避免产生重复稿。
- 每个事件只调用 Push Data API 一次，并传 `Idempotency-Key`；本地去重是主要保障，服务端是否执行幂等仍取决于接收接口实现。

## 控制台只读页

控制台“金十 / 美国数据追踪”通过认证的 `GET /console/macro-newsflash/get` 只读本库，展示未来排程及北京时间/美东时间、统一的金十追踪窗口状态、已公布排程或规律估算标记、日历解析错误、最近金十请求异常、最近观测统计期及实际/前值/预期和快讯投递状态。页面不初始化数据库，不触发来源请求，也不推进投递状态；数据库缺失或尚未初始化时明确显示 worker 尚未初始化。前端仅在进入页面或手动刷新时读取快照。

## 操作

```bash
python backend/src/main.py macro-newsflash init-db
python backend/src/main.py macro-newsflash run --once
python backend/src/main.py macro-newsflash run
python backend/src/main.py macro-newsflash status
```

`MACRO_NEWSFLASH_RELEASE_POLL_INTERVAL_SECONDS` 控制追踪窗口内金十轮询间隔，默认 `1` 秒、最小 `1` 秒；`MACRO_NEWSFLASH_RELEASE_REQUEST_TIMEOUT_SECONDS` 控制窗口内请求超时，默认 `3` 秒、最小 `1` 秒；`MACRO_NEWSFLASH_QUIET_POLL_INTERVAL_SECONDS` 控制静默期日历确认周期，默认 `900` 秒（15 分钟）、最小 `60` 秒；`MACRO_NEWSFLASH_REQUEST_TIMEOUT_SECONDS`、`MACRO_NEWSFLASH_PUSH_TIMEOUT_SECONDS` 调整日历请求与推送超时；推送地址复用 `ODAILY_PUSH_ENDPOINT`；`MACRO_NEWSFLASH_TRADINGVIEW_CALENDAR_URL`、`MACRO_NEWSFLASH_BEA_SCHEDULE_URL`、`MACRO_NEWSFLASH_FED_CALENDAR_URL` 可覆盖对应日历地址；`MACRO_NEWSFLASH_DB_PATH` 可覆盖独立 SQLite 路径。生产 unit 为 `deploy/odaily-macro-newsflash.service`；部署仍按仓库规定先在本地提交并推送，再由官方服务器同步。

官方与补充日历入口：[BEA 发布日历](https://www.bea.gov/news/schedule)、[美联储 FOMC 日历](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm)、[TradingView Economic Calendar](https://www.tradingview.com/economic-calendar/)（仅用于发布日期与时间）。
