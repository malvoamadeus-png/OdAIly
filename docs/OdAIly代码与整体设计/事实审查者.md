# 事实审查者

## 职责与位置

事实审查者是独立的发布后异步模块，以主 SQLite 的 `odaily_reference_items` 全量已发布快讯镜像为入口，覆盖自动稿与人工稿。它与文本审查者平级，不进入发布主链路，不改写、撤回或重新发布快讯。

比对价值筛选标准：稿件是否在报道某个可辨认主体的具体事件，而且把该事件写错，会改变交易判断或造成名誉损害。一般观点、市场展望、纯行情和无实质影响的细节不展开核查；分析中夹带的重大具体事实仍可触发。

交易或名誉影响用于衡量错误严重程度，不作为存在错误的证据。职责是检查编辑是否把消息写坏，外部搜索解决具体编辑疑点，不重新调查消息源整篇报道的真假。

模块实现为 `backend/packages/fact_auditor/`。原中文质量审核者对外改称“文本审查者”，保留既有 `auditor` 包、CLI、表、feed kind 和 systemd 名称，兼容历史结果。其文档仍为 `审核者.md`。

## 处理流程

1. 从扫描窗口内的镜像领取当前稿件版本，使用独立租约，不领取或修改 `tasks` 发布任务。
2. 确定性编辑来源先豁免：关联 `hyperliquid_news` 等确定性来源，以及固定 Gate / MSX 报价署名。MSX 公告不因名称相同自动成为报价豁免。
3. 复用 `source_exclusion_rule_groups` 中 `competitor` 路径的启用规则与 `match_target`，命中即豁免，记录规则名、词表与匹配范围。沿用 Unicode NFKC、大小写不敏感、任一词子串匹配；URL 不参与。临时商务豁免共用这套配置，品牌负面新闻同样可能命中，不将命中解释为“已经验证是商务稿”。
4. 用 GPT 轻量判断是否值得与原文比对；此阶段只返回 `needs_review / reason`，不生成搜索问题。无需比对则保存理由，不获取原文、不搜索。
5. 获取原始材料，做一次轻量原文对照：“看看稿件有没有超出原文乱写、写错，或者漏掉会明显改变读者交易判断、损害个人或机构名誉的重要信息。只指出实质问题，不做润色。”
6. 搜索问题只能来自原文比对，筛选阶段的疑问不继承。仅解决未经证实的名称转换、关键新增事实或被稿件确定化的重大范围歧义。每个问题包含稿件逐字 `claim`、具体 `question`、`kind`、实质影响 `reason` 和原文逐字 `source_evidence`（仅 `added_fact` 可为空）；缺少依据则执行失败，不发起搜索。单次最多核查配置数量的问题。忠实转述原文的机构归因、报告预测、数字和约合金额到此结束，不重新审计来源。
7. 保存每个阶段的结果、原文与已发布稿件快照、耗时、模型、原始输出、搜索工具记录及引用，供快讯总览读取。第一版不发送插件或 Telegram 内容提醒。

已证实的实质编辑问题放 `issues`；未证实的问题只放 `questions`，允许 `passed + questions`，表示原文比对未证实错误但有具体待查疑点。不同但成立的统计口径、可补充背景、价格时点不构成错误；“存入”不推断成“仅一笔”。

正常新闻压缩可省略通用风险尾缀、无执行安排的宣传愿景和口语修饰；具体风险事实、行动承诺与状态变化仍审查。确定性变化按实际信息状态判断，不机械比较“应该、可能”是否保留；监测口语整理为陈述句不单独判错，可建议保留来源归属。讨论写成决定、拟购买写成持有、申请写成获批等仍属于实质问题。

审查按稿件实际表达判断，不补出“多数”“流通量减少”“已经加入”等更强断言再判错。值得保留、但省略未改变核心事实含义的具体信息放 `comparison.result.suggestions`，每条包含原文逐字 `evidence` 和直接说明补充内容的 `reason`；缺省为空。建议不影响状态、不触发搜索，与 `issues` 分开展示，不收集通用风险尾缀和宣传愿景等无实质价值的建议。引用须为连续原文且通过锚点校验；不合格的可选建议被丢弃，不影响已完成的事实比对，模型原始输出仍留痕。

结论先直接说明哪里写错或应补什么，再简短解释具体影响；数量、范围和关系不超出原文，不用抽象交易风险套话代替事实说明。这是所有审查结论的通用表达要求，不为单一币种添加例外。

原文与稿件完全不对应时，不发起外部搜索，记录 `comparison.result.status = source_mismatch`，表示材料对应关系有问题，不据此断言稿件在现实中为假。

## 原文获取与来源链路

- 自动生成稿优先关联 `tasks / x_task_pipeline` 的归档原始材料。先按发布响应的远端快讯 ID 识别；没有精确对应时，仅接受标题一致、发布时间相差不超过 5 分钟且唯一的匹配。
- 其余稿件使用镜像 `raw_payload.sourceUrl`，为空时回退外部 `source_url`；Odaily 站内详情页不是原文。
- X 普通帖通过 FXTwitter 获取正文；X Article 没有归档完整正文时按原文不可用处理，避免把截断内容当完整材料。
- 其他来源读取公开 HTML 或文本页，限制重定向、页面大小和请求时长，拒绝私网地址。付费墙、验证码、获取失败等均保留原因，不使用搜索摘要冒充原文。
- 原文不可用时不做推测性搜索，记录 `unverifiable` 及获取失败原因，不视为通过。

## 外部证据与判定

审查、筛选与搜索均使用 `gpt-5.6-luna`，`reasoning.effort = medium`。文字调用复用共享 OpenAI 客户端；外部搜索使用 Responses `web_search` 工具，要求真实完成的 `web_search_call`。证据 URL 必须能对应工具返回的 sources 或原生引用，证据片段不得为空。模型自编网址或没有工具调用的回答不能支撑“有证据支持 / 有证据冲突”。

例如：

- Minghong 被改为另一家机构的中文名，是关键名称对应核查，不因原文已有英文主体而豁免。
- 凭空补中文人名需要依据，不能仅凭模型记忆修成另一个中文名。
- Robinhood 创始人“卖出 90% 股票”：原文明确股票类别而稿件漏掉时由原文审查指出；原文本身口径不清而稿件将重大减持写成全部持股时，搜索确认具体分母、类别及剩余持股，不能将某类股票比例等同全部经济权益或投票权。

外部问题结论为 `supported / contradicted / unverified`。没有搜到、证据不足、未返回某个问题、超过搜索预算等均保留 `unverified`，不作为正确或错误的证明。

## 状态与版本

持久化表为 `fact_checks`，唯一键为 `source_item_id + content_hash + policy_version`。hash 覆盖标题、正文与原文定位链接。当前策略为 `fact-review-2026-10-21-v3`；收窄规则后，在现有扫描时间窗内生成新策略记录，旧策略记录保留为历史，不回填窗口外稿件。标题、正文或原文链接变化后产生新版本；总览只关联与当前稿件匹配的审查结果，旧结果在详情历史记录中保留。

| 状态 | 展示与含义 |
| --- | --- |
| `unreviewed` | 未审查，仅展示状态，当前版本没有记录；不代表进入了队列 |
| `pending` | 已建立记录，等待领取 |
| `processing` | 审查中，有 10 分钟租约 |
| `skipped` | 无需审查，显示 `—` 并可查看理由 |
| `exempt` | 豁免，命中确定性来源或排除规则 |
| `passed` | 本次审查范围内未发现问题，不代表新闻被全面独立证实 |
| `flagged` | 发现原文实质问题、材料不对应或外部证据冲突 |
| `unverifiable` | 原文不可用或外部证据不足，无法完成确认 |
| `failed` | 原文审查模型、搜索或执行发生技术错误 |

已确认原文问题、但外部搜索失败时保留 `flagged`，同时标记 `incomplete` 并展示失败阶段。其他搜索失败按 `failed`，不能自动通过。失败任务按退避重试，默认最多 3 次；达到上限不无限重试，过期租约达到上限后转失败。每次执行的完整结果另存 `fact_check_runs`，手动重试不删除历史执行证据。单轮遇到执行失败即结束本轮，避免依赖故障时密集调用。后台没有隐式历史全量回填，窗口外无记录的稿件保持“未审查”。

## 控制台

`快讯及数据总览 / 快讯总览` 增加事实审查列、状态筛选与当前筛选范围的状态数量。点击进入 `?view=newsflash&fact_review={快讯ID}` 独立详情页，可用 `check_id` 查看历史版本。

沿用认证的 `POST /console/newsflash-operations`：

- `list` 返回每条 `fact_review` 摘要及 `fact_review_counts`，支持 `fact_status`。
- `fact_review` 接收 `source_item_id` 与可选 `check_id`，返回已发布与审查快照、原文、各阶段问题与依据、结果及版本历史。

网页读取不触发模型、不领取任务。详情页展示人工可核对的结论与证据，不展示模型思考过程。第一版不接入事实审查插件提醒；文本审查者已有提醒继续保留。

## 配置与运行

环境变量在 `.env.example` 维护：

- `FACT_AUDITOR_MODEL`：只允许 `gpt-5.6-luna`。
- `FACT_AUDITOR_OPENAI_BASE_URL / FACT_AUDITOR_OPENAI_API_KEY`：为空时复用 `ODAILY_LLM_*`，再回退 `OPENAI_*`。
- `FACT_AUDITOR_OPENAI_API_STYLE`：默认 `responses`；文字调用可配置 `chat_completions`。
- `FACT_AUDITOR_SEARCH_BASE_URL / FACT_AUDITOR_SEARCH_API_KEY`：默认复用文字入口；搜索入口必须支持 Responses 和 `web_search`，不支持时记录失败，不静默换模型。
- `FACT_AUDITOR_REQUEST_TIMEOUT_SECONDS`：默认 90 秒。
- `FACT_AUDITOR_LOOKBACK_MINUTES`：默认 1440 分钟，最多 7 天。
- `FACT_AUDITOR_START_AFTER`：可选的带时区起始时间，限制首次处理范围。
- `FACT_AUDITOR_MAX_ITEMS_PER_RUN / FACT_AUDITOR_INTERVAL_SECONDS`：默认每轮 20 条、间隔 30 秒。
- `FACT_AUDITOR_MAX_ATTEMPTS / FACT_AUDITOR_MAX_SEARCH_QUESTIONS`：默认 3 次、3 个问题。

```bash
python backend/src/main.py fact-auditor-worker --once
python backend/src/main.py fact-auditor-worker
python backend/src/main.py fact-auditor-retry --check-id 123
python backend/src/main.py fact-auditor-case --input backend/fixtures/fact_auditor/jupiter_multicoin.json --output /tmp/fact-review.json
```

`fact-auditor-case` 只审查提供的 JSON 材料，不读取或写入产品 SQLite、不发布稿件，供本地离线回放与服务器模型验收使用。fixture 中 `title / content` 是待审稿，`original_text / original_url` 是原文材料；未提供原文时明确记为不可用。

`backend/fixtures/fact_auditor/narrow_review_cases.json` 保存收窄规则的回放样例：Papertrade 来源口径、Aztec 约合金额、忠实转述预测、重大股类遗漏和负面主体名称转换。预测与股类样例明确标注为合成对照材料，不是已验证的现实报告或交易。

`backend/fixtures/fact_auditor/editorial_compression_cases.json` 包含 Kimchi、Bitmine、LAPTOP 的公开材料快照及金额单位、计划状态、具体风险的合成对照样例，用于验证合理压缩与实质错误的边界。

systemd 单元为 `deploy/odaily-fact-auditor.service`。worker 使用主 SQLite 存结果并写 `pipeline_worker_heartbeats.component = fact_auditor`。模型或搜索不可用时总览保留失败原因；恢复依赖后可恢复尚未耗尽重试的已建档任务，耗尽任务在恢复依赖后用 `fact-auditor-retry --check-id` 显式重试；只允许当前稿件版本，等待或执行中任务不重复重置。
