# 事实审查者

## 职责与位置

事实审查者是独立的发布后异步模块，以主 PostgreSQL `main.odaily_reference_items` 中的全量已发布快讯镜像为入口，覆盖自动稿与人工稿。它与文本审查者平级，不进入发布主链路，不改写、撤回或重新发布快讯。生产领取使用 PostgreSQL 行锁和 `SKIP LOCKED`。代码保留 SQLite 仓储实现，供显式选择 SQLite 后端的本地隔离测试或兼容运行使用；这不代表生产主库使用 SQLite。

领取已建档任务时，先按审查状态索引筛选待处理、到期重试或租约过期的记录，再核对它仍与已发布稿件的当前标题、正文、来源链接及审查策略匹配，避免在主库写事务中扫描全部稿件；重试优先级与版本匹配规则不变。

比对价值筛选标准：已发布标题和正文是否在报道某个可辨认主体的具体事件，而且其中的主张写错会改变交易判断或造成名誉损害。标题和正文都属于待审稿件；标题中的主体、数字、状态和范围可以单独构成实质问题。一般观点、市场展望、纯行情和无实质影响的细节不展开核查；分析中夹带的重大具体事实仍可触发。

交易或名誉影响用于衡量错误严重程度，不作为存在错误的证据。职责是检查编辑是否把消息写坏，外部搜索解决具体编辑疑点，不重新调查消息源整篇报道的真假。

模块实现为 `backend/packages/fact_auditor/`。原中文质量审核者对外改称“文本审查者”，保留既有 `auditor` 包、CLI、表、feed kind 和 systemd 名称，兼容历史结果。其文档仍为 `审核者.md`。

## 处理流程

1. 从扫描窗口内的镜像领取当前稿件版本，使用独立租约，不领取或修改 `tasks` 发布任务。
2. 确定性编辑来源先豁免：关联 `hyperliquid_news` 等确定性来源，以及固定 Gate / MSX 报价署名。MSX 公告不因名称相同自动成为报价豁免。
3. 使用 `source_exclusion_rule_groups` 中独立的 `fact_auditor` 路径规则与 `match_target`，命中即豁免，记录规则名、词表与匹配范围。首次初始化时将当时的竞品规则复制为事实审核者规则；此后两边独立增删改。沿用 Unicode NFKC、大小写不敏感、任一词子串匹配；URL 不参与。临时商务豁免可配置在事实审核者路径，品牌负面新闻同样可能命中，不将命中解释为“已经验证是商务稿”。
4. 用 GPT 轻量判断标题和正文是否值得与原文比对；此阶段只返回 `needs_review / reason`，不生成搜索问题。无需比对则保存理由，不获取原文、不搜索。
5. 获取原始材料，对标题和正文做一次轻量原文对照，重点检查本条消息是否多写、错写，或漏掉会明显改变读者交易判断、损害个人或机构名誉的重要信息。标题压缩但没有实质改变原意时通过；标题本身造成实质性错误时，即使正文更准确也要指出。审查输入只有标题、正文和当前原文，没有逐句来源或作者标记；不得假设正文每项内容都来自当前原文。“此前消息”等文字只能作为区分背景的语篇线索。明确区隔的独立背景不要求由当前原文支持，不得仅因它未出现在当前原文中而判为新增事实或发起搜索。只检查它是否被错误归因给当前来源，或与本条消息混写后实质改变当前消息含义。只指出实质问题，不做润色。结论指出问题来自标题还是正文。
6. 搜索问题只能来自原文比对，筛选阶段的疑问不继承。仅解决本条消息转述中的未经证实名称转换、关键新增事实或被标题或正文确定化的重大范围歧义；明确区隔且未混入本条消息的独立背景不属于本条原文新增事实。每个问题包含标题或正文中的逐字 `claim`、具体 `question`、`kind`、实质影响 `reason` 和原文逐字 `source_evidence`（仅 `added_fact` 可为空）；缺少依据则执行失败，不发起搜索。单次最多核查配置数量的问题。忠实转述原文的机构归因、报告预测、数字和约合金额到此结束，不重新审计来源。
7. 保存每个阶段的结果、原文与已发布稿件快照、耗时、模型、原始输出、搜索工具记录及引用，供快讯总览读取。第一版不发送插件或 Telegram 内容提醒。

已证实的实质编辑问题放 `issues`；未证实的问题只放 `questions`，允许 `passed + questions`，表示原文比对未证实错误但有具体待查疑点。独立背景补充（如明确引出的“此前消息”）不参与当前原文的增删核对，不因当前原文未提及其内容而报错或搜索；该文字线索不是背景事实的来源证明。若背景被归到当前来源，或与当前消息混写并改变其含义，仍按实际主张核查。没有来源标记时不能可靠判断作者来源，因此不得仅凭当前原文未提及某项内容就认定它是错误新增。不同但成立的统计口径、可补充背景、价格时点不构成错误；“存入”不推断成“仅一笔”。

正常新闻压缩可省略通用风险尾缀、无执行安排的宣传愿景和口语修饰；具体风险事实、行动承诺与状态变化仍审查。确定性变化按实际信息状态判断，不机械比较“应该、可能”是否保留；监测口语整理为陈述句不单独判错，可建议保留来源归属。讨论写成决定、拟购买写成持有、申请写成获批等仍属于实质问题。

审查按标题和正文的实际表达判断，不补出“多数”“流通量减少”“已经加入”等更强断言再判错。标题压缩可以省略细节，但若因此实质改变主体、数字、状态或范围，应按标题中的实际表达判断。值得保留、但省略未改变核心事实含义的具体信息放 `comparison.result.suggestions`，每条包含原文逐字 `evidence` 和直接说明补充内容的 `reason`；缺省为空。建议不影响状态、不触发搜索，与 `issues` 分开展示，不收集通用风险尾缀和宣传愿景等无实质价值的建议。引用须为连续原文且通过锚点校验；不合格的可选建议被丢弃，不影响已完成的事实比对，模型原始输出仍留痕。

结论先直接说明哪里写错或应补什么，再简短解释具体影响；数量、范围和关系不超出原文，不用抽象交易风险套话代替事实说明。这是所有审查结论的通用表达要求，不为单一币种添加例外。

报告数字或金额冲突前，先对齐原文和稿件中的数值、数量单位、币种与所指对象，并统一单位比较；估值和实际交易所得不能混为一谈。
指出状态、范围或确定性错误时核对稿件已有的限定词，不得声称遗漏实际保留的“可能、预计、将、尚未”等词。待批准或待生效事项被写成已生效，以及可能采取的关键行动被写成已有计划，可能构成实质错误；日常监测用语的整理仍按既有边界判断。

本条消息的转述部分与原文完全不对应时，不发起外部搜索，记录 `comparison.result.status = source_mismatch`；独立背景段落不能单独导致该状态。该状态表示材料对应关系有问题，不据此断言稿件在现实中为假。

## 原文获取与来源链路

- 自动生成稿优先关联 `tasks / x_task_pipeline` 的归档原始材料。先按发布响应的远端快讯 ID 识别；没有精确对应时，仅接受标题一致、发布时间相差不超过 5 分钟且唯一的匹配。
- X 稿件同时提供写作任务 `metadata.context_chain` 中按由近到远排列的引用和回复，保留各帖作者、时间、链接和正文；最新帖决定当前事实，前序帖可确认同一事件的省略主体与背景，不把旧状态当作最新结果。链路不完整且没有已证实错误时记录 `unverifiable`。原文引用须能在实际材料中核对。
- 审查意见先说明原文内容，再说明稿件如何表述以及具体偏差，尤其保留安全建议的适用条件。仅因最新帖未出现主体不能断言稿件凭空添加。
- 其余稿件使用镜像 `raw_payload.sourceUrl`，为空时回退外部 `source_url`；Odaily 站内详情页不是原文。
- X 普通帖通过 FXTwitter 获取正文；X Article 没有归档完整正文时按原文不可用处理，避免把截断内容当完整材料。
- 其他来源读取公开 HTML 或文本页，限制重定向、页面大小和请求时长，拒绝私网地址。付费墙、验证码、获取失败等均保留原因，不使用搜索摘要冒充原文。
- 原文不可用时不做推测性搜索，记录 `unverifiable` 及获取失败原因，不视为通过。

## 外部证据与判定

审查、筛选与搜索均使用 `gpt-6-luna`，`reasoning.effort = medium`。文字调用复用共享 OpenAI 客户端；外部搜索使用 Responses `web_search` 工具，要求真实完成的 `web_search_call`。证据 URL 必须能对应工具返回的 sources 或原生引用，证据片段不得为空。模型自编网址或没有工具调用的回答不能支撑“有证据支持 / 有证据冲突”。

例如：

- Minghong 被改为另一家机构的中文名，是关键名称对应核查，不因原文已有英文主体而豁免。
- 凭空补中文人名需要依据，不能仅凭模型记忆修成另一个中文名。
- Robinhood 创始人“卖出 90% 股票”：原文明确股票类别而稿件漏掉时由原文审查指出；原文本身口径不清而稿件将重大减持写成全部持股时，搜索确认具体分母、类别及剩余持股，不能将某类股票比例等同全部经济权益或投票权。

外部问题结论为 `supported / contradicted / unverified`。没有搜到、证据不足、未返回某个问题、超过搜索预算等均保留 `unverified`，不作为正确或错误的证明。

## 状态与版本

持久化表为 `fact_checks`，唯一键为 `source_item_id + content_hash + policy_version`。hash 覆盖标题、正文与原文定位链接。当前策略为 `fact-review-2026-11-21-v6`。常规部署或策略版本升级不自动重审已有稿件；扫描器按标题、正文和原文定位链接匹配已有记录，避免只因 `policy_version` 改变就在回看窗口内批量建档。稿件标题、正文或原文链接变化后产生新版本。总览关联与当前稿件快照匹配的最新审查结果，不因策略键不同而显示为未审查。

需要让某篇未变更稿件按当前策略重审时，使用详情页的人工重审操作；若当前结果属于旧策略，会新建当前策略记录并保留旧记录。自动策略切换不触发历史回填。

引用链与意见表达的改进可沿用现有策略键，避免自动重审历史记录；事实审核范围或判定职责变化时升级策略键。新的审核和人工重试使用新取材规则。

| 状态 | 展示与含义 |
| --- | --- |
| `unreviewed` | 未审查，仅展示状态，当前版本没有记录；不代表进入了队列 |
| `pending` | 已建立记录，等待领取 |
| `processing` | 审查中，有 10 分钟租约 |
| `skipped` | 无需审查，显示 `—` 并可查看理由 |
| `exempt` | 豁免，命中确定性来源或排除规则 |
| `passed` | 本次审查范围内未发现问题，不代表新闻被全面独立证实 |
| `flagged` | 发现原文实质问题、材料不对应或外部证据冲突 |
| `unverifiable` | 原文不可用或外部证据不足，无法完成确认 |
| `failed` | 原文审查模型、搜索或执行发生技术错误 |

已确认原文问题、但外部搜索失败时保留 `flagged`，同时标记 `incomplete` 并展示失败阶段。其他搜索失败按 `failed`，不能自动通过。失败任务按退避重试，默认最多 3 次；达到上限不无限重试，过期租约达到上限后转失败。每次执行的完整结果另存 `fact_check_runs`，手动重试不删除历史执行证据。单轮遇到执行失败即结束本轮，避免依赖故障时密集调用。后台没有隐式历史全量回填，窗口外无记录的稿件保持“未审查”。

## 控制台

`快讯及数据总览 / 快讯总览` 增加事实审查列、状态筛选与当前筛选范围的状态数量。点击进入 `?view=newsflash&fact_review={快讯ID}` 独立详情页，可用 `check_id` 查看历史版本。

沿用认证的 `POST /console/newsflash-operations`：

- `list` 返回每条 `fact_review` 摘要及 `fact_review_counts`，支持 `fact_status`。
- `fact_review` 接收 `source_item_id` 与可选 `check_id`，返回已发布与审查快照、原文、各阶段问题与依据、结果及版本历史。

网页读取不触发模型、不领取任务。详情页展示人工可核对的结论与证据，不展示模型思考过程。最终状态为 `flagged` 时，写入插件高频区事实审查提醒，复用文本审查者卡片样式、反馈操作与声音配置；`passed`、`unverifiable`、`failed` 等状态不提醒。插件摘要优先提取 `comparison.result.issues[].reason` 与 `external.result.findings[]` 中 `verdict = contradicted` 的 `reason`，最多展示两条并限制到 180 字符，不附带原文证据、搜索过程或完整审查报告。

## 配置与运行

事实审核者排除词在控制台 `排除词` 中通过专属 `事实审核者` 路径维护。初始复制包含当时已存在的竞品规则及其启用状态、匹配范围和词表；复制完成后不再同步竞品规则。

环境变量在 `.env.example` 维护：

- `FACT_AUDITOR_MODEL`：只允许 `gpt-6-luna`。
- `FACT_AUDITOR_OPENAI_BASE_URL / FACT_AUDITOR_OPENAI_API_KEY`：为空时复用 `ODAILY_LLM_*`，再回退 `OPENAI_*`。
- `FACT_AUDITOR_OPENAI_API_STYLE`：默认 `responses`；文字调用可配置 `chat_completions`。
- `FACT_AUDITOR_SEARCH_BASE_URL / FACT_AUDITOR_SEARCH_API_KEY`：默认复用文字入口；搜索入口必须支持 Responses 和 `web_search`，不支持时记录失败，不静默换模型。
- `FACT_AUDITOR_REQUEST_TIMEOUT_SECONDS`：默认 90 秒。
- `FACT_AUDITOR_LOOKBACK_MINUTES`：默认 1440 分钟，最多 7 天。
- `FACT_AUDITOR_START_AFTER`：可选的带时区起始时间，限制首次处理范围。
- `FACT_AUDITOR_MAX_ITEMS_PER_RUN / FACT_AUDITOR_INTERVAL_SECONDS`：默认每轮 20 条、间隔 30 秒。
- `FACT_AUDITOR_MAX_ATTEMPTS / FACT_AUDITOR_MAX_SEARCH_QUESTIONS`：默认 3 次、3 个问题。

```bash
python backend/src/main.py fact-auditor-worker --once
python backend/src/main.py fact-auditor-worker
python backend/src/main.py fact-auditor-retry --check-id 123
python backend/src/main.py fact-auditor-case --input backend/fixtures/fact_auditor/jupiter_multicoin.json --output /tmp/fact-review.json
```

`fact-auditor-case` 只审查提供的 JSON 材料，不读取或写入产品数据库、不发布稿件，供本地离线回放与服务器模型验收使用。fixture 中 `title / content` 是待审稿，`original_text / original_url` 是原文材料；未提供原文时明确记为不可用。

`backend/fixtures/fact_auditor/narrow_review_cases.json` 保存收窄规则的回放样例：Papertrade 来源口径、Aztec 约合金额、忠实转述预测、重大股类遗漏和负面主体名称转换。预测与股类样例明确标注为合成对照材料，不是已验证的现实报告或交易。

`backend/fixtures/fact_auditor/editorial_compression_cases.json` 包含 Kimchi、Bitmine、LAPTOP 的公开材料快照及金额单位、计划状态、具体风险的合成对照样例，用于验证合理压缩与实质错误的边界。

systemd 单元为 `deploy/odaily-fact-auditor.service`。生产 worker 使用主 PostgreSQL 保存结果和 `pipeline_worker_heartbeats.component = fact_auditor` 心跳。模型或搜索不可用时总览保留失败原因；恢复依赖后可恢复尚未耗尽重试的已建档任务，耗尽任务在恢复依赖后用 `fact-auditor-retry --check-id` 显式重试；只允许当前稿件版本，等待或执行中任务不重复重置。显式 SQLite 后端运行时使用对应的 SQLite 仓储。
