# ADR 0003：本机 PostgreSQL 主存储

- 状态：用户已批准，实施中；基础设施已就绪，产品尚未切换。
- 日期：2026-11-18。
- 取代：ADR 0001 中“SQLite 为唯一活动主存储”的长期目标；ADR 0001 仍说明当前生产行为及历史迁移，直到正式切换完成。

## 决策

OdAIly 将把业务状态迁移到 OdAIly 官方服务器上的本机 PostgreSQL。目标数据库名为 `odaily`，共享主业务实体按既有业务边界组织；当前主业务迁移实现使用 `main` schema，仓储迁移账本按 `(schema_name, component, version)` 区分同一 schema 内独立仓储。实际表归属由完整迁移清单维护。PostgreSQL 运行时使用原生 psycopg 3 和专用 `ODAILY_POSTGRES_DSN`，所有访问经进程共享的短连接池；业务原子操作显式使用 `with conn.transaction()`。

这是本机 PostgreSQL，不是旧 Supabase，也不复用 `SUPABASE_DB_URL` / `DATABASE_URL`。未迁移域不得静默退回 SQLite；启动须对后端选择显式失败。

## 数据与发布约束

- 用户明确不创建备份或扩容文件系统。低峰停写后核对 SQLite checkpoint，并从服务器源库直接分块迁移到同一 `/data` 文件系统上的 PostgreSQL；全过程不在根盘创建迁移临时文件。只有在每个物理 SQLite 数据库的所有数据都已导入并通过全表行数、主键和规范化哈希校验后，才可删除对应完整源文件组（SQLite、WAL、SHM）以释放空间。SQLite 的 `DELETE` 不会回收 `auto_vacuum=NONE` 数据库文件空间，不得用逐行删除冒充释放空间。
- 全量保留已有业务记录、来源身份及去重账本、稿件与版本、审核和尝试记录、人工配置、外部投递结果、队列状态与租约，也保留历史、缓存、投影和审计数据。不得以空库上线、清空历史、只迁近期数据、重建而不导入，或使用无期限双写。用户接受执行中偶发异常可能带来的数据损失风险，但未授权有意丢弃数据。
- 导入须保留主键 ID，验证每表行数、主键集合、关键字段规范化哈希、序列下一个值、外键/唯一约束、队列状态、来源去重、稿件/审核关联和外部副作用幂等字段。
- 仅在通过完整验收后启用 PostgreSQL 单写。迁移验证前保留原 SQLite 文件组；源文件删除后若需回退，先停 PostgreSQL 写入并执行经验证的数据导出或恢复流程，再恢复切换前代码/配置，不得假设存在 SQLite 备份或把 PostgreSQL 新增数据假称已回灌 SQLite。

## 运行要求

- 仅连接本机 PostgreSQL；应用连接池为有界共享池，连接 checkout 有限等待，设置连接、语句、锁和 idle-in-transaction 超时。
- 领取任务用行锁与 `SKIP LOCKED` 或等价条件更新；必须保持原排序、租约、重试上限、来源/版本复核和幂等语义。
- 新增域必须提供显式、有序、checksum 固定的 schema migration 与数据兼容审查。不要创建忽略未知 SQL 的 SQLite 兼容层。
- 磁盘空间、WAL、连接池等待、锁等待、长事务与 vacuum 进入服务运维验收。本次迁移不要求创建或验证任何备份。

## 分阶段交付

1. 公共 PG 运行时与连接池、迁移账本、测试入口。
2. 主流程与业务仓储原生 SQL 移植，并逐项对齐 SQLite 当前行为。
3. HotTopic / 投资线索、队列、观测及其他独立库完成 PostgreSQL 实现；缓存和证据文件分别确认保留或重建边界。
4. 流式快照导入及逐表/业务校验工具、峰值并发和恢复演练。
5. 生产低峰停写、最终导入校验、单写切换及服务逐项启动。

本 ADR 不代表任一生产数据导入或后端切换已经发生。正式迁移在完成清单中的验收后按现有授权执行，不再增加二次批准步骤。
